v{{VERSION}}
Codex + Claude Code
macOS + Linux

从对话开始协作

你选择目标，Agent 完成接入。

不用手工维护仓库 YAML，也不用把 token 发给模型。安装、连接与诊断交给 Agent；身份在浏览器确认，配置和任务在 Hub 后台查看。

准备好这些

  • macOS 或 glibc Linux，arm64 / x64；Node.js 20+ 与 npm。
  • 已安装并登录的 Codex 或 Claude Code，只需你实际使用的工具。
  • 一个明确 Hub 地址，或允许 Agent 在本机启动 Hub。
  • 独立 worktree 需要 Git 2.31+ 和已提交基线。

npm 自动安装对应平台依赖，内含配套 HAPI，无需另装 Bun 或 HAPI。原生模型登录沿工具自身安全流程完成，不由 Runweft 接管。

01 / INSTALL

通过 npm 安装，把接入交给 Agent。

所有支持的平台使用同一条命令，npm 会选择对应依赖：

安装 Runweft
{{NPM_INSTALL}}

也可以把下面这段话交给 Agent，让它检查环境并完成安装：

可直接复制到对话
通过 npm 安装 runweft@{{VERSION}}，从已安装包中读取并接入 Runweft Skill。整个接入过程中，程序安装、升级和卸载都使用 npm。先检查已有安装和配置，保留其他 MCP、Skill 和模型设置。连接我指定的 Hub；没有地址时先问是否在本机启动。身份只通过浏览器确认，不向我索要 token。完成配置后执行一次只读委派。

Skill 已在 npm 包中

查看 Skill 源目录：

定位产品 Skill
printf '%s\n' "$(npm root -g)/runweft/skills/runweft"

Agent 先读取其中的 SKILL.md，再将完整目录复制到 Codex 的 ~/.agents/skills/runweft 或 Claude 的 ~/.claude/skills/runweft。已有不同内容先备份和确认，不覆盖其他 Skill。Skill 和 MCP 分别接入。

新终端也能找到程序

用 npm prefix -g 查看全局安装目录，确认其 bin 子目录在 PATH。通常 Node 安装已配置好路径；需要调整时按实际 shell 配置一次，不重复追加，也不覆盖未知来源的已有程序。

工程参考：启动本机 Hub
runweft init
runweft start
runweft open --print

首次只启动 Hub，不自动创建身份或 Runner。已有 Hub 用 init --url <Hub地址>；init 不覆盖既有配置。

02 / CONFIRM

在浏览器确认：是你，是这台机器。

Agent 发起连接，给你设备名、核对码和短时确认链接。在浏览器主动创建身份并保存副本，或导入已有 token，选择空间后核对并确认。不要把 token 发进对话。

刷新或报错，不会给你换一个身份。

丢失所有 token 副本无法找回原身份。重新领取不会继承原来的空间和配置；已有身份应导入保存的副本。

工程参考：加密连接交接
runweft hub --url <Hub地址> connect begin --name <本机名称>
runweft hub --url <Hub地址> connect complete
runweft hub connect status
runweft hub identity

Web 确认后 complete 才保存凭据；pending 继续等待，响应未知重跑同一 complete。status 是本机摘要，identity 才核对远端授权。凭据不进入 URL、模型或日志。

03 / CONFIGURE

机器、工具和职责，分别配置。

机器在哪里执行

独立凭据接入 Hub，再关联空间、启动 Runner。

runtime使用什么工具

这台机器上的 Codex 或 Claude Code，单独登记与分享。

Agent承担什么职责

Hub 中的指令与版本，可空间全局或关联中心仓库。

Agent 帮你配置首次只读评审职责。在 /hub 后台可维护资源、成员、仓库和自己的选择；同一仓库的不同用户各有个人配置。共享仅限空间成员，分享不公开历史任务或授予编辑权。管理员可治理，不取得他人的私有指令。

工程参考：分别接入机器与工具
runweft machine enroll --name <本机名称>
runweft machine associate <machineId> <spaceId>
runweft runner start
runweft machine discover <machineId>
runweft runtime register codex --machine <machineId>
runweft runtime list

使用实际返回的 UUID。工具可发现不等于模型登录有效，关联空间不自动分享 runtime。中心 Agent JSON、仓库匹配和个人选择见完整参考，不要建立仓库 YAML。

04 / CONNECT

让熟悉的客户端具备委派能力。

Agent 安装所选宿主的 Runweft MCP。每次实际修改先备份，保留其他 MCP、hooks、模型设置和原生会话。然后在实际项目目录重新打开 Codex 或 Claude Code。

工程参考：MCP 安装和检查
runweft mcp install
runweft mcp check

check 只验证配置、握手与连接，不代替原生实际调用。非默认数据根把同一 --home 放在子命令前。

05 / DELEGATE

发出第一条只读委派。

用 Runweft 已配置的代码评审 Agent 检查当前改动，等待结果并总结需要处理的问题。先不要修改代码。

主 Agent 先核对身份、Hub 和中心定义，再派生任务、等待并读取报告。接受不等于完成，超时也不意味着任务失败；结果未知时查原任务，不重复派生。

打开 Hub 的本人任务页，查看轮次、配置快照、报告与成果。原生会话、审批和文件沿 HAPI 复用；新标签使用同身份同空间短凭据，到期回 Hub 重开，不把 token 放到链接。

选择协作方式

共享现场，或隔离改动。

方式前置与边界
本地共享目录可无 Git；使用主目录，不自动提交/清理。
本地独立 worktree主目录是 Git；默认 HEAD，独立保留现场。
远端独立 worktree同一 Hub、源/目标 Runner 在线，显式 Git 基线。

所有方式都连接明确 Hub。独立模式先准备 Git、输入与上下文，再启动模型；未提交内容和 ignored 依赖不自动复制，依赖由 Agent 安装。默认原生权限，不新增 OS 沙箱。

拿回成果，再决定下一步

代码、附件、报告，分别确认。

每轮关闭进程，保留 session/worktree。继续任务时优先复用现场；只有原生确切历史缺失才重建上下文，未知执行绝不盲目重发。主宿主退出后不后台注入旧会话。

输入文件在模型启动前送达，声明的输出按清单下载。远端代码通过 bundle 取回，不自动 push、切分支或合入；主 Agent 审查后按你的授权处理。交付失败重试文件/代码，不用重跑模型掩盖错误。

工程参考：续接与成果取回
runweft task send <taskId> --message "继续处理"
runweft task wait <taskId>
runweft task result fetch <taskId>
runweft task result show <taskId>

Hub 可以在本机，也可以共享

一套身份与空间，多台执行机。

mode local 只表示本机可托管 Hub，不是离线 Agent 模式。hub.url 独立选择业务连接。连接已有 Hub 时，无需在客户端再托管一套服务。

公开中心通过 HTTPS 反向代理托管，代理需支持 WebSocket、SSE、Authorization header 和流式文件。各机器分别通过 Web 加密确认连接，再登记独立机器凭据；不要共享 HAPI root token。源端全局 skills/MCP/模型凭据不会自动复制到远端。

公开部署、现有服务重启和数据清理需明确授权。物理跨机验证与同机多 Runner 验证分别记录，不把拓扑示意当成实测。

维护同样交给 Agent

先查事实，不重建一切。

让 Agent 检查版本、Hub identity、Runner、runtime 和 MCP，逐层定位。401 用原身份重新交接；403 查实际权限；等待超时查原任务；原生标签到期从 Hub 重开。

升级前结束任务并停止服务，用 npm 安装目标版本、更新 MCP 入口与包内 Skill，再按角色重启验证；没有自动修改在线实例的自升级。卸载先移除 Runweft MCP/hook 并停止服务，再用 npm 卸载程序，移除未改写的产品 Skill；数据与原生设置保留。默认数据根 ~/.runweft，准确位置用 paths。

工程参考：诊断入口
runweft --version
runweft hub identity
runweft runner status
runweft doctor
runweft config show
runweft paths

不打印身份文件或完整原生配置。显式清理、备份、附件配额与完整命令见使用说明。
