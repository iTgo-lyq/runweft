五步完成接入

从安装到读回第一份评审报告。

大部分操作由 Agent 来做：安装程序、读取 Skill、连接 Hub、登记机器和工具、装好 MCP。你只需在浏览器注册或登录并授权，Agent 接着用 CLI 完成评审。主 Agent 读回报告时，接入才算完成。

开始前准备

  • macOS（Apple Silicon 或 Intel）或 glibc Linux（x64 或 arm64），装好 Node.js 20+ 和 npm。
  • 已登录的 Codex 或 Claude Code，只需要你实际在用的那一个。
  • 一个 Hub：团队给你的地址，或者让 Agent 在本机启动一个。没有现成的，就从本机开始。
  • 以后要用独立 worktree 或远端机器时，再准备 Git 2.31+ 和已提交的代码；第一次评审不依赖这些。

npm 包里已带好配套的 HAPI（Runweft 用它驱动 Codex 和 Claude Code 执行任务），不用另装 Bun 或 HAPI。Runweft Kit 从公开仓库安装。模型登录照常走 Codex / Claude Code 自己的流程，Runweft 不经手。

01 · 由 Agent 完成

安装 Runweft，接入 Runweft Kit。

把下面这段话发给 Codex 或 Claude Code。它会用 npm 安装 Runweft，再从公开仓库安装 Runweft Kit——一份写给 Agent 的接入说明，第 2 到第 4 步都按它进行。

复制这段话，发给 Codex 或 Claude Code
帮我接入 Runweft。用 npm 全局安装 runweft@{{VERSION}}，从 https://github.com/iTgo-lyq/runweft-kit 安装名为 runweft-kit 的 Skill 并按其说明执行。先检查并复用已有安装、连接和资源，保留其他 MCP、Skill 和模型设置；替换有修改的 Kit 先备份并确认。我给了 Hub 地址就连接它，否则复用既有连接；都没有时直接在本机启动。给我浏览器链接注册或登录并授权，密码由我自己输入，不向我索要 token。随后通过 CLI 复用或登记本机与已登录工具，匹配或创建并关联当前仓库，复用或创建私有代码评审 Agent，立即在当前目录执行一次只读评审，等待并读完整报告，带回当前对话和任务链接。不要等我再发第二段提示；MCP 加载和真实调用单独报告。以后升级用 npm，完整卸载先预览再执行 runweft uninstall --yes。

想自己先装程序也可以。所有支持的平台都用这一条，npm 会自动选对应的平台依赖：

安装 Runweft
{{NPM_INSTALL}}

完成标志：runweft --version 显示 {{VERSION}}，Skill 已复制到 Codex 或 Claude Code 的 Skill 目录。

安装 Runweft Kit

从公开仓库安装当前 Skill。下面的命令用于 Codex；Claude Code 将 --agent codex 改为 --agent claude-code：

安装 Runweft Kit
npx skills add iTgo-lyq/runweft-kit --skill runweft-kit --agent codex -g --copy -y

Skill 名称为 runweft-kit。先检查已有副本；内容不同或名称不同但用途相同的旧副本，先备份到 Skill 扫描目录之外，再确认替换范围，避免重复加载。项目内已有 Runweft Kit 时直接复用。Skill 和 MCP 分开安装，MCP 在第 4 步。

新终端里找不到 runweft

运行 npm prefix -g 查看 npm 的全局目录，确认它下面的 bin 在 PATH 里。装 Node 时通常已经配好；确实要改，就在你实际使用的 shell 配置里加一次，不要重复添加，也不要覆盖来历不明的同名程序。

02 · 由你确认

选定 Hub，在浏览器确认身份。

Hub 是管理身份、机器、Agent 和任务的服务，每次委派都经过它。团队已经有 Hub，就把地址告诉 Agent；没有的话，让它在本机启动一个，后台地址默认是 http://127.0.0.1:3210/hub。

Agent 给出链接、设备名和核对码。你在浏览器注册或登录账号，核对后提交即可授权；单一默认空间自动使用，只有需要选择时才多一步。密码由你自己输入，普通用户无需保管 token。

退出后，用原账号密码回来。

浏览器按标签保存登录，关闭或退出后重新登录同一账号即可找回空间和历史。忘记密码联系 Hub 部署者协助重置；在账号设置可撤销某个登录环境。

完成标志：runweft hub identity 显示你的身份和空间。

手动命令：启动本机 Hub
runweft init
runweft start
runweft open --print

第一次只会启动 Hub，不会自动创建身份或启动 Runner。连接已有 Hub 用 runweft init --url <Hub地址>；init 不会覆盖已有配置。

手动命令：浏览器登录并授权
runweft hub --url <Hub地址> connect begin --name <本机名称>
runweft hub --url <Hub地址> connect complete --wait 60
runweft hub connect status
runweft hub identity

在浏览器确认后，complete 才会保存凭据。返回 pending 就继续等；没收到响应时重跑同一条 complete，不要重新注册账号。status 只看本机记录，identity 才向 Hub 核对授权。凭据不会出现在链接、模型对话或日志里。

03 · 由 Agent 完成

登记机器和工具，创建评审 Agent。

执行一项任务需要三样东西，它们分开登记。第一次接入时，Agent 会一并配好：

机器在哪里执行

接入 Hub 的电脑。上面运行着 Runner，负责接收和执行任务的后台服务。

runtime用什么执行

这台机器上登记过的 Codex 或 Claude Code，两种工具分别登记。

Agent做什么、怎么做

在 Hub 里定义的职责和执行工具，比如“代码评审”按什么要求、用哪个 runtime。

第一次接入会创建一个代码评审 Agent，要求它只写报告、不改代码。之后在 Hub 后台 /hub 可以管理机器、Agent、仓库和成员。

完成标志：runweft runner status 显示在线，runweft runtime list 里有这台机器上登记的 Codex 或 Claude Code，Hub 后台能看到“代码评审”Agent。工具被发现不等于模型能正常运行，这要靠第 5 步的任务来确认。

团队与权限

同一个仓库，每位成员可以有各自的 Agent 选择。分享只对空间成员生效，不会公开你的历史任务，也不给对方编辑权。空间管理员可以治理和停用空间里的资源，但看不到别人的私有指令。机器关联到空间不会自动分享 runtime，需要单独分享。

手动命令：登记机器与工具
runweft machine enroll --name <本机名称>
runweft machine associate <machineId> <spaceId>
runweft runner start
runweft machine discover <machineId>
runweft runtime register codex --machine <machineId>
runweft runtime list

命令里的 ID 填实际返回的 UUID，不要填名称。Agent 定义的 JSON、仓库匹配和个人选择见命令参考。配置都存在 Hub 上，仓库里不需要放 Runweft 配置文件。

04 · 按需加载

第一份报告之后，核对 MCP。

MCP 是 Codex 和 Claude Code 调用外部工具的接口。装上 Runweft MCP，你的客户端就多了派发任务的工具。修改配置前会先备份；其他 MCP、hooks、模型设置和原生会话都保持原样。

第一份评审先通过 CLI 完成。当前宿主尚未加载 MCP 时，Agent 再检查是否支持重载，必要时提醒你重开；保留原任务 ID，不要求第二段体验提示，也不重复派发业务任务。

完成标志：在新会话里让主 Agent 调用 runweft_status，能看到你的身份、Hub 和空间。runweft mcp check 通过只说明连接正常，不代表任务能跑通。

手动命令：安装和检查 MCP
runweft mcp install
runweft mcp check

check 检查配置、握手和服务连接，不运行模型。使用非默认数据目录时，把同一个 --home 放在子命令前面。

05 · Agent 自动完成

在当前对话读回第一份报告。

账号授权后，Agent 自动完成当前仓库关联、私有评审配置和 CLI 委派。本机共享目录可读取未提交的改动；报告回到当前对话后，再按需加载 MCP。

以后再次评审时可用
用 Runweft 里的代码评审 Agent 审查这个项目，在本机共享目录执行，这样它能看到我还没提交的改动。如果没有未提交的改动，就审查最近一次提交；如果这里不是 Git 项目，先问我要审查哪些代码。只读审查，不要修改任何文件。等任务完成后读回报告，按严重程度列出需要我处理的问题。

首次接入时，Agent 已按上面的接入提示用 CLI 处理当前仓库关联、复用或创建私有评审 Agent，然后 spawn、wait、show 读完整报告，不需要你再复制这段提示。下面的提示用于以后再次评审。任务被接受不等于完成，等待超时也不代表失败。结果不明时，让主 Agent 去查原来的任务，不要再派一次。

完成标志：任务显示已完成，主 Agent 读回报告并列出问题，Hub 任务页里能看到同一轮。到这一步，第一次协作才算完成。

在 Hub 里查看任务

Hub 的任务页列出你自己的任务：每一轮的状态、当时使用的配置、报告，以及代码和附件是否已取回。想看执行过程、处理审批或浏览文件，从任务详情打开原生会话，见原生会话与审批。

进阶 · 工作目录

共享目录，还是独立 worktree？

方式适合前提与边界
本机共享目录评审、排查，需要看到未提交的改动不需要 Git；直接在当前目录工作，不会自动提交或清理。
本机独立 worktree实现功能，不想动当前目录项目是 Git 仓库；默认从 HEAD 开始，现场单独保留。
远端独立 worktree耗时任务，或需要另一台机器的环境两台机器接在同一个 Hub，Runner 都在线；必须明确指定 Git 版本。

独立 worktree 会先准备好代码、输入文件和上下文，再启动模型。未提交的改动和被 Git 忽略的依赖不会复制过去，执行的 Agent 需要时会自己安装依赖；发起机器上的全局 Skill、MCP 和模型凭据也不会同步到远端。执行沿用那台机器上 Codex / Claude Code 的原生权限，Runweft 不额外加沙箱。

进阶 · 原生会话

打开原生会话，看过程、处理审批。

Runweft 的执行层基于 HAPI，任务由执行机器上原生的 Codex 或 Claude Code 完成，会话、工具调用和审批都是它们自己的；登录、项目指令、Skill 和其他 MCP，也来自那台机器上已有的配置。HAPI 自带的会话网页，从任务详情就能打开。

从任务详情进入

打开 Hub 后台 /hub，默认就在“任务”页。点“查看任务详情”，再选“打开原生详情 / 审批”或“打开原生文件”。新标签使用同一身份和空间的短期凭据，最长十五分钟，到期后回 Hub 重新打开；链接里不会带 token。

会话消息和工具调用

它说了什么、调用了哪些工具，过程和历史都在这里。

审批同意或拒绝

Codex / Claude Code 按自己的权限设置请求审批时，那一步会等待，任务标为“需要处理”。你在会话页同意后，它才执行这一步并接着做；拒绝的话，这一轮可能就此结束。

文件文件和改动

执行期间可以浏览工作目录，查看 Git 暂存和未暂存的改动。

查看文件和改动需要原生会话在线，不要把它当作保存成果的地方。一轮结束后，做完的代码照常用 Runweft 取回本机审查，见成果与续接。

补充要求，回到主 Agent

原生页面上可能也有输入框或恢复按钮，但由 Runweft 管理的任务不接受在网页里直接发消息或恢复。补充要求、开始下一轮，都回到主 Agent 通过 Runweft 发送，这样每一轮都记进任务，照常有状态和报告。

在手机上查看

手机用浏览器就行，前提是能访问 Hub 的地址。127.0.0.1 只在 Hub 所在的电脑上可用；其他设备要访问，先按 Hub 部署 让 Hub 能从网络访问，公开到互联网时放在 HTTPS 反向代理后面。打开后用原账号密码登录，选同一个空间，就能查看任务、处理审批。

进阶 · 成果与续接

取回成果，接着下一轮。

每轮结束都会关闭执行进程，但保留会话和 worktree。继续同一个任务时，下一轮通常在原来的现场接着做；如果启动配置改了，或原生会话已经丢失，会重新启动会话，用已有的任务和报告恢复上下文。结果不明的任务不会被自动重发。

附件分输入和输出：输入文件在模型启动前送到执行机器，声明过的输出文件按清单取回。远端的代码成果经 Hub 以 Git bundle 传回你的仓库；取回不会切分支、合并或推送，由主 Agent 审查后按你的意思处理。文件或代码交付失败时，只重试交付，不必重跑模型。

手动命令：续接与取回
runweft task send <taskId> --message "继续处理"
runweft task wait <taskId>
runweft task result fetch <taskId>
runweft task result show <taskId>

原来的主 Agent 会话退出后，Runweft 不会在后台唤醒它；用这些命令仍可以查看和继续你自己的任务。

进阶 · Hub 部署

一个 Hub，连接多台机器。

本机 Hub 和团队 Hub 是同一套服务，身份、空间和授权规则相同。配置里的 mode local 只表示这台电脑可以托管 Hub，不是离线模式；实际连接哪个 Hub 由 hub.url 决定。已经连上团队 Hub 的电脑，不需要再托管一个。

对外公开的 Hub 放在 HTTPS 反向代理后面，代理要支持 WebSocket、SSE、Authorization 请求头和流式文件传输。每台机器各自在浏览器确认连接、登记自己的机器凭据；不要共享 HAPI 的 root token。

按照 Runweft Kit 的约定，Agent 在公开部署、重启正在运行的服务或清理数据前会先征得你的同意。这是写给 Agent 的操作规范，不是程序层面的强制限制。

进阶 · 诊断与维护

出了问题，先查清在哪一层。

让 Agent 依次检查版本、Hub 身份、Runner、runtime 和 MCP。常见情况：401 时登录原账号并重新授权当前环境；403 查空间成员和分享权限；等待超时先查原任务；从 Hub 打开的原生会话过期了，回 Hub 重新打开。

升级：先结束正在运行的任务、停掉服务，用 npm 安装新版本，更新 MCP 入口，按原安装来源更新 Runweft Kit，先备份已有修改，再按原来的角色重启并检查。Runweft 不会自己升级。

Runweft 1.1.4 起支持完整卸载：运行 runweft uninstall 会先列出要停止的服务和要删除的内容，这一步不做任何改动；确认后运行 runweft uninstall --yes，就会停止本机 Hub 和连接，删除本机的 Runweft 程序、MCP 接入、预览中列出的 Skill、数据和备份，Codex、Claude Code 的原生模型凭据和你的源项目都原样保留。如果只想删掉程序、保留数据方便以后装回来，用 npm uninstall -g runweft 就行。 单独安装的 Kit 若未列入预览，按它的维护说明清理。默认数据根为 ~/.runweft；其他数据根使用 runweft --home <目录> uninstall --yes。

手动命令：诊断
runweft --version
runweft hub identity
runweft runner status
runweft doctor
runweft config show
runweft paths

这些命令不会打印身份文件或完整的原生配置。清理、备份、附件配额和全部命令见命令参考。
