公共阶段的 5:57 改善包含计时器、分片以及本次更快的下载，不能全部归因于代码。macOS Intel 本轮安装 114 秒、卸载 126 秒，分别运行；1.1.5 为串行的 131 秒和 146 秒。并行消除了两项串行相加的关键路径，但不同 runner 上的单项速度变化仍应单列，不能认作并行本身的收益。此前同一公开候选的重复测量、预检和复核见[优化执行记录](../project/archive/2026-10-13-release-validation-efficiency/execution.md)与[iclaude 复核记录](../project/archive/2026-10-13-release-validation-efficiency/review.md)。

本次 11 个公共验收 job 排队仅 **2–5 秒**，没有证据表明 GitHub 并发配额构成关键瓶颈。拆分会增加 runner 启动和依赖准备次数，以更多并行资源换取墙钟缩短；job 时长不等于计费额度。当前主要时间仍在 npm 公开确认。扣除这次官网失败与诊断的 3:43，算术对照值为 **26:44**；这不是另一次无故障实测，也不能作为 P50/P95 或耗时保证。
