# 身份 token 与空间实施计划

> 来源：[需求](requirement.md)、[技术方案](technical.md)
> 执行模式：逐任务提交；用户已授权主 agent 决策及本地验收，iclaude 评审后执行。

## 交付目标

一个可独立验收的身份/空间入口：无需注册领取 token，保存与导入，创建空间及邀请成员。新身份不会取得旧 HAPI 信任域权限。

## 任务

### T1 身份和空间持久 API

- 交付：schema v7、独立 token 认证、个人空间、成员角色、单次邀请、轮换和 API 接入。
- 验收：真实 HTTP 验证两个空间三角色、并发更新、重启与秘密不入库；新旧凭据互不转换。
- 验证：新增领域集成测试及相关旧 API/schema 测试、typecheck；旧 resources 的未来版本拒绝测试改为 v8，task-results 的 v5 fixture 排除新增 v7 表后再迁移。

### T2 Web 身份与空间管理

- 交付：`/hub` 的创建/导入、复制下载、轮换、退出、空间选择及成员/邀请管理，嵌入 CLI 构建。
- 验收：用户无需 CLI，刷新保留当前身份，两个浏览器身份通过邀请协作；过期/无效凭据可操作地提示。
- 验证：Playwright 桌面和窄屏、键盘、控制台错误与敏感信息检查。

### T3 整体自动验收与规格同步

- 交付：专用服务下完整流程、兼容检查、使用说明及验收记录；通过后在关闭步骤同步 Specs 并独立归档提交。
- 验收：需求全部通过，不将未接通的 HAPI 多用户执行写成完成。
- 验证：typecheck、`bun run test`、build；真实 HAPI 新旧凭据双向拒绝、Socket 认证和 DB/WAL/日志明文扫描，复用已通过且未变化的聚焦证据。

## 风险与后续

Web/CLI 凭据程序化交付由后续接入 Change 实现；本 Change 的 Web 独立可用。全产品入口切换前必须完成 HAPI 通道授权，不能因身份 API 已完成就公开现有 root token。评审意见及处置记录到 execution.md。
