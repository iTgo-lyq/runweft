# 准备 1.1.5 正式发行候选

## 背景与目标

用户授权：“现在测试一下正式发布的耗时吧。发布完毕后告诉我目前的耗时分布。”在最新 main 的发布提速与冗余清理交付上准备下一稳定版本 1.1.5，供现有正式发布流程执行。

main 的 [开发检查](https://github.com/iTgo-lyq/runweft/actions/runs/38344006472)在原生页面到期验收中出现 `2 !== 1`。HAPI 在 JWT 到期前一分钟调用认证检查；Runweft 对限时 JWT 返回同一 token，不延长有效期。请求次数不是“没有创建新身份”的正确判据。

## 范围与行为变化

产品行为变化：无。修正验收对现有 HAPI 认证检查的错误假设，更新根版本和随包说明到 1.1.5。HAPI pin、模型、数据格式和执行语义沿用 main。

本 Change 验证并冻结发行输入后归档、合入 main；随后按用户已有授权推送不可变版本 tag，完成正式发行和官网接续。真实远端发布结果及耗时作为新的发行事实记录，不回写只读历史归档。

## 方案要点

到期场景允许 HAPI 检查同一个 JWT，检查认证请求只携带原限时 JWT、成功响应仍是原 JWT，并断言身份创建请求数为零。继续验证到期导航和凭据删除。使用现有正式工作流保留核心、四平台构建、service-package、公共 access/storage/web、四平台安装与完整卸载、latest 晋级和官网门禁。

## 验收标准

- 定向 Chromium 后台验收通过，包括同浏览器身份隔离、JWT 不续期、到期清除、无身份创建及现场清理。
- 根版本与当前安装说明一致为 1.1.5；五个 npm 包尚未占用此版本，版本 tag 尚不存在。
- 类型、文档、流程及 diff 检查通过；沿用本轮 main 已通过的根测试、Node 测试与构建证据，正式发布工作流再次对冻结候选执行完整门禁。
- 源码提交可审阅并推送，归档后合入 main；没有伪称本地准备已经完成正式发行。
