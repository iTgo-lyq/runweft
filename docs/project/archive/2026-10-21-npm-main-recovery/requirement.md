# npm 主包发布恢复

## 目标与范围

1.2.2 的四个平台包已被 npm 接受并公开，发布状态读取因网络 `fetch failed` 中断，主包尚未上传。用户要求处理错误并完成同一版本发布、确认 latest 更新。

采用 small：只修正发行控制脚本的网络读取和主包恢复，不改包输入、产品行为或不可变标签。现有候选描述及成功上传前证据仍为来源，公共集成、四平台安装及晋级门禁保持完整。

## 方案与验收

- npm 状态读取对明确网络中断及可恢复 HTTP 错误在有界预算内重试；鉴权、内容和摘要错误立即失败，发布等待阶段不重置总预算。
- 仅在原日志、来源、回执和四个平台公开摘要一致时恢复缺失主包。由冻结源码恢复主包 tarball，必须与原 CI 记录逐字节摘要相同，才能上传；已存在平台包绝不重传。
- 保存续发回执并纳入后续恢复，结果未知不得重复上传。来源、摘要、latest 基线或包输入不一致时拒绝操作。
- 针对上述边界做自动测试，复用原 1.2.2 原生报告；恢复工作流完成公开验收后核对五包 latest 都为 1.2.2。
