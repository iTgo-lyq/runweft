## 用户入口

命令树示意如下，命名仍可调整。这里只拥有命令承载、配置与运行基础；每个业务 Change 实现自己的命令，不等待全量命令才验收基础包。

| 命令域 | 用途 |
| --- | --- |
| `runweft hapi …` | HAPI Hub、Runner、执行目标与相关诊断；透传经兼容性确认的 HAPI 命令能力 |
| `runweft workspace …` | 绑定当前主工作区与仓库，查看远端执行配置 |
| `runweft machine …` / `runweft runtime …` | 分别注册和诊断全局执行资源，由资源注册 Change 实现 |
| `runweft agent …` | 维护全局/项目职责定义和 runtime 引用 |
| `runweft task …` | 发起、查看、等待、追加任务及中断委派 |
| `runweft result …` | 登记结果说明、查看结果、取回 Git 成果 |
| `runweft artifact …` | 上传、查询和下载输入/输出附件 |
| `runweft mcp` / `runweft mcp install --global` | MCP 服务与显式全局安装，由宿主适配 Change 实现 |
| `runweft init` / `runweft config …` | 初始化、模式选择、配置校验和有效值/路径查询 |
| `runweft serve` / `runweft doctor` | 封装所需服务启动与 HAPI 诊断；是否另需 serve 在能力映射后决定 |

CLI 与 MCP 调用相同协作能力，不各写一套调度。MCP stdout 只输出协议；日志走 stderr。面向机器的 CLI 输出提供结构化模式，参数传递使用 argv，不把路径、prompt 或 ref 拼成 shell 命令。

统一入口不要求 HAPI 与 Runweft 成为同一源码仓库或同一进程。Runweft 分发或定位兼容的 HAPI 构建，用户无需另装、另记 `hapi` 命令。私有发行版替换兼容 HAPI 构建，不增加厂商专属任务分支。具体 npm 打包与平台资产方案尚未定稿。

HAPI 域保留底层退出码、信号与交互终端行为；诊断可以明确说出 HAPI 故障，但修复操作仍给出 `runweft …` 命令。自动更新不能在活跃执行中替换不兼容版本。

## 进程与职责

复用 HAPI 现有 Hub、Runner 和运行布局。文档中的“协作层/服务”表示 Runweft 的逻辑职责，不意味着再启动旧工程 daemon、独立 runtime 服务或一套新的中心平台。先核对 HAPI 的服务、数据、文件与 Web 入口，再确定最小的封装位置。

| 组件 | 复用与最小新增 |
| --- | --- |
| 主机 Runweft CLI/MCP | 绑定宿主、解析业务调用、固定 Git 输入和取回成果 |
| Runweft 协作层 | 只补 HAPI 尚无的父子关联、角色分流、流程组合和交付摘要 |
| HAPI Hub/Runner | 沿用机器、会话、消息、审批、执行、状态与恢复；准备/导出有缺口才增补 |
| HAPI 文件与数据能力 | 优先保存/读取既有会话和附件；任务生命周期所需字段按缺口补齐 |
| HAPI Web | 沿用详情、审批与控制页面；Runweft 看板只补全局父子概览 |

新增执行侧行为仍在 HAPI 原有源码组织内实现，不另设 Multica daemon、通用 runtime 协议或 Runweft 进程执行器。

## 默认配置与身份

- 日常安装与操作统一使用 Runweft，内部连接沿 HAPI 现有认证；不增加第二套账号、RBAC 或任务隔离凭据。
- 子进程使用执行机器上原生客户端的全局配置和准备好的 cwd；不创建空白 home、集中管理 skill/MCP 或跨机器复制用户凭据。
- 权限使用 HAPI/原生已配置默认，不增加 OS 隔离，也不自动设置 yolo/跳过审批。
- 主/子角色由启动关联和宿主信息识别；仅限制 Runweft 的派生工具，不能当作通用安全沙箱。实际工具分流见[宿主适配](../../changes/host-mcp-adapter/design.md)。
- 日志不记录完整 prompt、源码或凭据；已有 HAPI 数据按其接口读写，不由 Runweft 直接篡改会话表。

## 分发与维护

包装兼容 HAPI 构建并保留现有版本诊断，不为每个上层操作再造一套底层契约。新增协作字段和产物纳入现有备份/保留流程；仅当 HAPI 没有相应能力时补充存储。

远端离线、原生认证无效或必需能力缺失时明确反馈，不静默换机器/runtime。真实安装前核对现有配置；本轮只更新文档，不修改用户 Codex/Claude Code 设置、HAPI 数据或模型凭据。

## 本地模式与 Hub 模式

本地模式无需用户单独部署共享 Hub，由 Runweft 管理本机 HAPI 服务，使用 loopback 连接和本机执行资源；Hub 模式连接明确配置的 HAPI Hub，沿其已有认证和机器路由。具体内嵌/后台进程组织在本 Change 技术方案中固定，不新增独立执行器。

模式选择只改变服务位置和资源范围；CLI/MCP 的协作语义一致。切换不自动搬迁本地任务、凭据和注册。本机 Hub 测试可自动验证 Hub 配置与协议，但不能当作真实跨机器验收。

## 数据与配置布局

推荐默认根为 `~/.runweft`，允许显式覆盖；最终路径在本 Change 技术方案中固定。全局配置文件与 agent 定义可读、可校验；机器/runtime 注册独立表达，项目只可声明项目 agent 和引用，不存机器注册副本。

按已选模式/连接区分持久数据归属，在受控根下组织 HAPI 数据、Runweft 必需关联、附件、托管工作区、日志、缓存与临时文件；CLI 可列出实际路径、配置来源、备份范围及保留规则。HAPI 已有 HAPI_HOME/DB_PATH 可复用，不把 HAPI 会话复制成另一套数据库。临时文件只保存可重建内容，不能承载唯一成果或续接现场。

原生工具的配置与 session 沿原生目录使用，共享主工作区保持原处；这些外部归属在路径诊断中标明，不为追求一个目录复制凭据或用户源码。既有 HAPI 数据不自动迁移。每个领域的数据迁移和保留约束由领域拥有，完整发行 Change 验证组合。

本地安装、配置、启停与数据持久性由 agent 自动验收；不要求用户手工配置或测试。
