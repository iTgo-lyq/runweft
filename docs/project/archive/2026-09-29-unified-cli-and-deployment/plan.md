# 统一 CLI 与部署实施计划

> 来源：./requirement.md
> 技术方案：./technical.md
> 执行模式：逐任务提交
> 确认方式：按用户授权，由 iclaude 对本 Change 评审一次，主 agent 复核后推进。

## 交付目标

获得可以安装、初始化、启动本机服务、连接 Hub 并诊断配置的一套 Runweft 基础 CLI。后续功能通过稳定的配置、目录和 HTTP 入口扩展。

## 关键决策与风险

- 原生执行复用固定 HAPI 程序；Runweft 服务只承载自己的上层业务。
- 单地址代理必须真实验证 Socket.IO/WebSocket 和 SSE，不只检查 health。
- macOS 正式安装必须有实际平台证据，不以 Linux 构建替代。
- 不实现下游业务占位；远端执行本 Change 不验证。

## 任务

### T1 配置、工作区绑定与可运行 CLI

- 交付：工程构建入口、CLI 帮助、初始化、配置编辑/校验/来源、目录诊断和稳定工作区绑定。
- 验收：首次使用有清楚的下一步，重复初始化保留配置；错误有字段位置和非零退出；不写入用户原有客户端 home。
- 验证：类型检查、配置/绑定聚焦测试、专用 home 的 CLI 调用。

### T2 复用 HAPI 的双模式服务与认证

- 交付：HAPI 命令透传、服务组合启停、统一 HTTP/SSE/WebSocket 入口、现有 HAPI 认证、Web 登录入口、状态与 doctor。
- 验收：真实 HAPI 与 Runner 能启动并通过入口通信；本地与独立 Hub 客户端不混用状态；退出与信号可核对。
- 验证：真实服务集成测试、编译程序的代理协议测试、专用目录启停与重启持久性、污染环境变量与 Runner 版本交接关闭。

### T3 平台包与安装路径

- 交付：固定源码 HAPI 构建、Runweft 二进制、npm 启动器和平台包，许可与依赖版本清楚。
- 验收：安装后只用 runweft 即可完成基础链路；没有源码 checkout 或全局 Bun 依赖；缺包和不支持平台提示明确。
- 验证：本机临时 registry 的真实 npm 可选依赖安装与服务验收、已安装启动器信号转发，Darwin 目标构建。

### T4 平台验收配置与操作文档

- 交付：同批候选包的跨平台自动验收配置，以及安装/配置/部署/数据维护说明。
- 验收：自动化配置使用真实 npm 安装，不发布公共包、不上传凭据；操作文档与已验证命令一致。
- 验证：工作流结构、平台标签与 Actions 固定版本、文档链接、现有安装脚本；实际平台结果由 T5 验收。

### T6 公开依赖源修正

- 交付：消除锁文件对本机内部 npm 镜像的依赖，固定公开源并保留版本与完整性 hash。
- 验证：专用目录、空缓存、公开 npm 源的 frozen-lockfile 安装。

### T5 实际平台与整体验收

- 交付：macOS 实际安装与服务验证证据、需求逐项验收；通过后单独同步 Specs 与归档。
- 验收：Requirement 每项有对应证据，文档命令可以按顺序完成配置和启动；无待补核心功能。
- 验证：macOS CI 安装测试、文档链接与 Change 校验、逐项验收。

T4/T5 将原 T4 的自动化配置和实际运行验收分开：CI 必须先取得已提交配置，不能在运行前把平台验收标为通过。

## 整体验证

- 真实 npm 安装路径下运行本地/Hub 协议、HAPI 与 Runner、认证、诊断和启停。
- 核对不改用户全局设置、不输出令牌、没有业务占位与假成功。
- 通过后按用户授权自动验收，同步实际 Specs，再归档本 Change；远端实测缺口不写成成功。
