## 结论：没有阻塞问题，可以推进

CLI 缺口的取舍能支撑 Agent 完成实际业务，我没发现遗漏的主体能力，也没有明显多余的内容。人工 CLI 密码登录复用待连接流程，以及只读路径和链接交接的方向都正确。下面两项意见都不阻塞推进。

## 意见

**1. 不带 Parent 的只读路径会让受管子任务也能读任务（不阻塞，建议在技术方案补一句）**

- **现状**：CLI 发出的所有任务 POST，包括 list、read、wait，都会带上 `HAPI_SESSION_ID`。服务端对它们统一执行 `assertCanDelegate`，所以受管子 agent 现在连 `task list/show/wait` 都会被拒绝。
  - 依据：`src/hub/delegation/client.ts:27`、`src/hub/delegation/api.ts:45-46`、`src/tasks/store.ts:146-155`。
  - MCP 那边也因此对子任务不暴露任何工具：`src/mcp/server.ts:62-65`。
  - 产品层也写着“受管子 agent 禁用 Runweft MCP，CLI/MCP 递归委派均拒绝”：`docs/usage.md:198`。
- **问题**：方案说只读 client“只需用户身份/空间，不伪造父会话”。这样调用方的会话上下文也一起丢了。子任务进程和用户共用同一个 CLI 连接，就能对同一用户同一空间做 `list --all`、`wait` 兄弟任务、读 `messages`。方案只写了 MCP 和写操作保留原规则，没有提到子任务这个主体。
- **最小修改**：只读 client 不构造 Parent，但仍带上调用方的 `HAPI_SESSION_ID` 作为上下文。服务端在只读入口复用现有的子任务拒绝判断。如果有意放开子任务读取，就在需求里明确写出来，不要让它成为隐式的行为变化。

**2. 人工 CLI 密码登录时，多空间选择的先后顺序要写清楚（不阻塞，小）**

- **问题**：方案让密码分支“校验密码、期限、成员资格后调用同一确认事务”，确认时需要目标空间。但用户有多个空间、又没有有效默认时，终端在认证前拿不到空间列表。实现时容易变成两种不好的做法：再加一个凭密码列空间的接口，或者让用户重复提交密码。
- **最小修改**：CLI 分支确认时不要求事先选定空间，单空间的情况直接用。激活后由 `complete` 用新凭据列出空间，在终端选一次再保存，语义和 `space use` 相同。这和方案自己的说法一致：CLI 凭据不只授权一个空间，空间只是本地默认值。确认事务本身不用改。

## 各重点核对

**CLI 缺口取舍**
- 账户、空间/成员/邀请、无本机登记的只读任务查询、消息诊断、Web 链接交接，这几项正好补上了 Agent 不得不去网页抄 UUID 或必须登记本机的缺口。
- 执行和资源命令直接复用。按业务结果比较、不逐个按钮镜像，这个原则合适。

**人工 CLI 登录与账户管理的主体边界**
- 复用待连接记录、同一个确认事务和 `complete` 保存流程是合理的。丢响应恢复、取消、撤销的语义都能和浏览器路径统一，也不会多建 browser 凭据。
- “账户管理只接受原始凭据，不接受派生短 JWT”与现有的分工一致：现在 `/api/runweft/hub/*` 用原始 token（`src/hub/api.ts:52`、`src/hub/client.ts:117`），业务 API 用 JWT。所以 CLI 和 Web 的主体边界是统一的。

**默认范围、`--all` 与 MCP 规则**
- 除第 1 条外没有矛盾。
- 对 CLI 类型的 Parent，现有实现本来就不按 Parent 限制按 ID 读取（`src/tasks/store.ts:42` 只校验 mcp）。所以去掉机器登记前置，不会扩大 CLI 已有的读取范围。
- 默认 list 现在就是精确的 machineId + cwd 过滤（`src/tasks/store.ts:60-64`）。改成在服务端分页前用同样条件筛选，语义不变。

**消息诊断与 Web 链接**
- 复用方式正确。网关已允许用户主体经过 session 读权限检查后 GET messages（`src/hub/access/http.ts:171-187`）。任务会话的 GET 也不受 `sessionPolicy` 限制（`src/hub/delegation/service.ts:72`）。HAPI 已支持成对的 before 游标。
- 链接落在 Hub 任务详情，由用户点现有按钮再走 `openNative` 打开原生页（`src/hub/app.ts:136-149`）。这一步需要用户点击，且依赖已登录的 Hub 标签换取短 JWT。方案的“继续使用现有原生页面入口”与此一致，实现时不要改成登录后自动弹出原生标签。
