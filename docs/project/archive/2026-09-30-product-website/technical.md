# 官网技术方案

> 来源：[Requirement](requirement.md)
> 状态：已确认
> 技术就绪性：已就绪；内容依据、平台包、Node/Bun 和 Playwright 均在当前仓库可用。

## 实现边界

HAPI 现有页面承载执行和审批，不提供 Runweft 产品介绍或首次安装指南；新增独立静态官网，不修改 HAPI UI、服务路由或 CLI。源文件放在 website/，使用语义化 HTML、CSS 和原生 JavaScript，不引入框架或修改根 package.json/lockfile，保持已冻结 CLI 构建输入不变。

website/build.mjs 读取 dist/packages/index.json 和已构建 tarball，验证版本/架构集合、index SHA-512 和发行 SHA256SUMS，并生成每个平台独立 SHA-256 文件与安装数据。把静态源文件、四个平台包和现有 docs/usage.md 复制至 dist/website 的独立暂存，成功后替换网站目录；缺包/校验失败明确报错，保留旧站点。静态链接全部使用相对路径，不写开发机器路径、虚构下载地址或外部脚本。

website/serve.mjs 仅绑定 loopback，提供本地 HTTP 预览与浏览器验收，不承担公开生产服务；生产部署复制 dist/website 到静态服务器。文件路径限定输出根，下载支持 GET/HEAD，不意外暴露源码和 .dev-smoke。

## 内容与交互

首页：产品主张与协作图 → 已有工作方式的延伸 → 委派/准备/执行/取回流程 → 四平台下载与安装 → 两种部署 → 常见问题。独立 guide.html 用侧栏定位实际操作步骤，既提供可复制命令，也解释返回 ID、PATH、权限和原生登录等必要操作。

静态 HTML 保留默认安装与全部指南正文；增强脚本只处理平台/模式切换、剪贴板与移动导航。下载数据由构建产物注入，平台不得仅凭浏览器猜测架构，默认 Apple Silicon 且允许明确选择。安装命令内嵌对应 SHA-256，macOS 用 shasum、Linux 用 sha256sum，单个包即可验证；独立校验文件仍可下载。复制失败选中对应命令并提示手动复制，不显示虚假成功。无 JS 可直接使用四平台下载表及默认命令。完整 usage.md 额外生成为 UTF-8 HTML 原文参考，说明其完整交付目录安装与官网单包安装的区别。

## 视觉决策

面向使用 Codex/Claude Code 的开发者，以清晰安装和理解协作为首要任务。配色：墨蓝 #122B42、主蓝 #2860E1、冷白 #F6F9FD、灰蓝 #627489、浅线 #DFE7F0、青色 #138A8A。拉丁字标优先使用 Avenir Next / URW Gothic 几何字形，中文使用系统无衬线，命令使用等宽字体；不依赖远端字体加载。

首页左右分栏，左侧短标题与安装入口，右侧以连接主工作区、两个子任务和返回成果的线条作为 Runweft「编织协作」的识别元素。它表达真实流程，不用假在线指标或复杂装饰。后续区域保持留白、有限色彩和清楚层级；指南更紧凑。标题/正文对比、可见焦点、移动布局和 reduced motion 贯穿两页。

## 验证

使用 Playwright Chromium 自动验证桌面/手机、平台切换后的文件及命令匹配、复制成功/失败反馈、导航/FAQ/模式示意、无 JS 阅读与 reduced motion；检查链接、下载/校验、控制台和页面溢出，并目视检查截图。实际浏览器下载后检查 hash，并在非根子路径复验链接；直接从页面 DOM 提取 Linux x64 安装命令，在专用 HOME/PATH 自动执行到版本输出，服务/MCP 配置不触及用户全局环境。核心 CLI 未变，不重跑原生模型矩阵。
