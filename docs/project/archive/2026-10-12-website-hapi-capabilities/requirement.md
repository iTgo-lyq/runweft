# 官网补充原生执行与 HAPI 能力

> 更新：2026-10-12

## 需求

用户要求在官网突出以更原生的方式接入第三方 runtime subagent，同时补充 Runweft 基于 HAPI 已具备的产品体验。沿用上一轮文案全部由 iclaude 编写、主 Agent 核对事实与集成的分工；沿用工程决策、自动验收和官网发布授权。

## 行为变化

### MODIFIED

- `website/product`：当前重点为委派场景；补充原生 Codex/Claude Code 执行及现有登录/配置、会话过程、浏览器审批、文件与 diff、会话续接等用户收益，说明 HAPI 提供的基础能力。
- `website/guide`：补充从 Hub 任务详情进入原生会话/审批/文件的具体路径，说明手机浏览器需要能访问 Hub，续接仍由主 Agent 通过 Runweft 发起。

## 约束

保留现有样式、上手主路径、npm 命令和版本。仅介绍当前 Runweft 已开放能力，不把 HAPI 支持的全部 runtime、App、Telegram、语音、推送、relay 或任意终端写成已接通功能。不新增产品代码、接口或配置。

## 验收

- 原生执行方式及其用户收益可读，明确基于 HAPI。
- 会话查看、待审批处理、文件/diff、续接均有当前 Runweft 源码或 Specs 依据。
- 手机浏览器的网络前提、受管任务的续接入口准确，不承诺任意接管或完整 HAPI 功能。
- 所有新增或调整的官网文案由 iclaude 完成，内容增补不破坏原有视觉和接入路径。
- 网站构建、三页 Playwright、链接与线上文件核对通过，保留 npm 1.1.3。
