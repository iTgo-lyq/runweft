# 完整版本集成与发布计划

> 来源：[Requirement](requirement.md)
> 技术方案：[Technical](technical.md)
> 执行模式：主 agent 逐任务实现和本地提交；唯一一次 iclaude 评审已完成并由主 agent 复核，见 [Execution](execution.md)。沿用户持续授权执行，不新增确认门禁。

## 交付目标

交付同版本的 macOS/Linux arm64/x64 可发布安装包，完整本地/Hub 协作、集中数据和易用配置，以及可追溯的自动验收证据。Mac 实机验证由用户承担；真实跨物理机器验证按既有授权保留缺口。两者均不省略对应平台或远端功能。

## 关键决策

- 依赖 C11 验收归档。此阶段只整合发行与验证；发现领域缺陷明确定位并修复，不以文档或假数据替代。
- 正式版本为 1.0.0，固定现有 HAPI revision。打包不执行公开发布、push 或 PR。
- 原生测试只使用专用配置/认证副本；未知执行先观察原记录，禁止用重复派生掩盖问题。
- 用程序 SHA-256 和包 SHA-512 绑定矩阵结果。旧 0.1.0 程序在更新产物前保留，用于升级/回退；最终产品代码变化后重跑受影响验证。

## 任务

### T1 四平台发行包与可复现安装

- 交付：1.0.0 主包与四平台包、来源与校验清单、明确的未发布安装入口；生成包可发布，源码工程保持 private。修复干净构建/CI 的 HAPI 依赖安装顺序，并同步首次安装、数据路径、local/Hub、MCP 和 Mac 操作说明。
- 验收：先保存 0.1.0 产物及索引，新交付目录不含旧 tarball。四平台二进制格式与架构、许可和匹配源码完整；Linux x64 从真实 npm 安装及平台包解包独立运行，不依赖开发 checkout 或全局 Bun；arm64 探查本地仿真并记录实际范围。安装候选在专用原生配置完成两次 MCP install、uninstall、其他配置保留及 backups/restore。Mac 双架构产物和验证步骤一并可交付。
- 验证：干净源码 frozen install、types/根测试、四平台构建、包 hash/内容、实际安装/诊断/服务与卸载保留数据；不把交叉编译当实机执行。

### T2 正式候选的完整协作组合

- 交付：沿现有 smoke 入口，验证两宿主 × 两 runtime 在本地共享、本地独立 worktree、远端独立 worktree 的完整流程；shared/worktree 同时覆盖 local/Hub，远端采用同机独立 Runner。
- 验收：全局 MCP 安装/幂等/其他设置保留；真实派生、等待、结果、关闭、同 session 续接及工具禁用；独立模式先准备环境并保留后续现场；输入/输出附件、代码取回与合入语义正确。全部记录指向同一候选程序 hash。
- 验证：T1 提交后固定候选；collaboration 共享 8、本地 worktree 8、远端 4 组，本地附件沿 artifact-mcp，controls 每种 runtime 各一组，另加成果安装验证和 Playwright 看板。复用已结束任务验证成果，区分真实模型执行和故障 fixture，不重复完成任务。

### T3 原生异常恢复与版本升级回退

- 交付：把已研究的真实历史缺失重建转为可重复验收入口；验证真实审批/拒绝/中断、失败可见及旧版升级/兼容回退。
- 验收：两 runtime 精确 missing 才重建，原历史保留、新输入仅一次、来源与新 ID 可追溯并关闭；未知不重放，交付失败仅重试交付。专用数据根从 0.1.0 到 1.0.0 再兼容回退，身份、任务、报告、附件和 Git refs 保留；旧服务与新程序版本差异可诊断。
- 验证：原生 controls/reconstruction、领域失败用例、专用备份恢复与版本状态检查；不修改用户正式数据或降低权限。

### T4 完整交付核对

- 交付：逐项需求证据、四平台产物路径与校验信息、用户 Mac 验证说明；包内用户说明在 T1 定稿，T4 只修改 Change/Specs，确需修改包内内容则重新打包并验收安装。同步 Specs 并归档另作关闭提交。
- 验收：包内说明与最终实现一致，没有未实现占位；机器/runtime/agent 的作用域清晰；所有持久数据归属明确。如实列出 Mac 实机由用户验证、物理跨机延期、arm64 实际测试方式、CI 未触发及既有 HAPI 环境性测试失败；Nginx 等配置示例未经运行时明确标注。外部发布和 Runweft 开源许可证选择不在本次自动动作中。
- 验证：文档/链接、包内容与 hash、需求映射和 Git 状态；仅因新变更或未解决失败补充检查，复用同一代码已通过的证据。

## 整体验证

先完成各任务独立提交，再按 Requirement 逐项核对。沿用户授权自动本地验收，保留明确由用户承担的 Mac 运行验证与已允许延期的物理远端验证，不将整个产品降为 MVP。所有领域实现完成后同步当前事实并归档，外部发布仍需单独授权。
