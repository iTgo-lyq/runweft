# 官网与 npm 并行发布及部署定向复验

## 背景与目标

1.1.6 发布的 npm 公开确认耗时 16:52，官网在 npm 晋级后才启动，并因短暂读到旧版 guide.html 立即失败。用户明确接受官网与实际 npm 状态短暂不一致，允许官网先展示目标版本。本 Change 承接此前独立 worktree、验证与 iclaude 复核后合入 main 的发布优化任务。

## 范围与行为变化

- MODIFIED：稳定版正式发行的官网与 npm 流程并行启动，官网不以包公开或 latest 晋级为部署前置；整体发布成功仍必须包括 npm 全部验收/晋级和官网内容/浏览器验证成功。
- MODIFIED：官网 HTTP 200 内容摘要暂时不匹配时，在原三分钟预算内重新读取；最终仍要求每个文件精确匹配，鉴权、项目外重定向、错误 MIME 立即失败。
- ADDED：显式指定原官网 run，只读取其已上传回执并复验同一部署，不再次上传。核对原来源、环境、版本和本次静态文件摘要，拒绝不一致或缺失回执。
- 保留普通官网 push/手动发布的既有 npm 就绪检查；仅绑定正式发行的显式并行模式允许短暂领先。预发行、空参数预检和只读公共矩阵不触发正式官网。
- npm 最终失败时保留真实失败与已上传官网回执，不自动回滚官网或重发 npm；按原候选定向处理。暂时不一致可能持续到故障被处理，不承诺固定收敛时间。

## 验收标准

1. 工作流依赖证明官网不等待 beta 或 promote；稳定版本和来源校验仍有效，失败/取消/缺失必需结果不得成为整体成功。
2. 夹具验证 npm 未公开时仅正式并行模式可部署；普通路径、Beta、预检、只读验证的边界保留。
3. 旧内容最终变正确可通过，持续错误在预算内失败；网络、状态、MIME、跨域和完整摘要检查仍有效。
4. 仅复验模式无 Cloudflare 上传调用；真实既有部署完成十文件与三页双尺寸浏览器复验，错误回执/文件/环境被拒绝。
5. Node 检查、workflow/actionlint、文档检查及实际 iclaude 独立复核通过，记录未执行的正式新版本实测边界。
