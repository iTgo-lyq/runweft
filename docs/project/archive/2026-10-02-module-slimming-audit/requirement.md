保留全部现行产品能力、对外接口和权限边界（用户本轮明确移除历史数据迁移/兼容与 data reset），寻找可以收敛的实现逻辑。覆盖产品源码、测试、fixture、验收流程、构建与发行脚本、官网及随包 Skill。HAPI 按当前固定版本核对实际接口和实现，不在本仓库重建其执行、原生协议、会话、审批、恢复和文件框架。

## 交付与验收标准

1. 覆盖表能够追溯全部范围文件，明确静态调查、实际执行与未验证范围。
2. 已证实清单按收益和风险排序，每项包含文件位置、调用或实验依据、具体改法、能力与边界保持理由、验证方法及实施前置条件。
3. 测试删除/合并建议逐项说明保留的行为保障；尚无等价保障时要求先迁移，不能以测试数下降作为成果。
4. 怀疑单列，说明需要什么证据才能接受或排除；给出可据此制定 Plan 的实施顺序。
5. 不设删除比例，不把真实信任边界、异步后的并发重查、故障恢复、现行持久状态恢复或产品状态区分当作冗余。不引入更复杂的去重框架。
6. 本轮允许在独立工作区修改源码、测试、fixture、smoke 和构建发行实现；不改 HAPI source/pin、版本、lock，不上传 npm 或部署官网，不修改用户宿主配置、数据或凭据。
7. 每项删除前完成有效保障迁移与实际验证；全部任务由主 agent 验收后才同步 Specs、归档。真实原生/浏览器与安装组合使用同一候选，无法执行的远端范围如实保留。
