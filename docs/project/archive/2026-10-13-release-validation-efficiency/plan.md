# 实施计划

## T1 取消残留计时器并去除重复服务验收

使用同一候选建立顺序基线，修复关闭/MCP 等截止计时器，删除原始平台目录的重复服务验收。验证成功退出不再保活、失败/强杀仍失败，以及 standalone/npm 两条完整覆盖。记录修改后各用例耗时，提交可独立验证的改动。

## T2 按实测拆分验收并优化磁盘准备

根据 T1 测量决定 service-package 有限并行、storage/access 固定分片及 Mac Intel 拆分是否值得。验证并发现场隔离、完整覆盖、失败传播及晋级门禁；在 GitHub runner 测量执行/准备/磁盘开销。保留确定性串行完整组入口和失败后定向续验。

## T3 完成独立复核与发行准备

运行相称的整体检查，交由 iclaude 独立复核全部差异、要求和证据，修复问题并定向验证。同步发行操作文档，准备下一正式版本。经用户已有合入授权验收归档，合入 main；随后执行正式发布并在发行记录中整理实际耗时。

## 执行顺序

按 T1 → T2 → T3 串行实施；正式发布属于归档合入后的已授权操作，其实际证据写独立发行记录，不回写归档。
