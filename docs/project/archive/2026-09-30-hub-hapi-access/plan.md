# HAPI 通道授权实施计划

> 来源：[需求](requirement.md)
> 技术方案：[Technical](technical.md)
> 执行模式：逐任务提交。主 agent 按已有授权确认，已完成 iclaude 评审并落实修正，见 execution.md。

## 交付目标

提供可独立组合真实 HAPI 的授权网关，所有 HTTP、Socket、SSE 与流式文件经统一主体/对象检查。正式 serve 迁移与默认入口切换由阶段 5 完成。

## 任务

### T1 主体凭据与可信对象映射

- 交付：增量持久化、用户 JWT/机器/任务凭据校验、对象归属与执行意图接口。
- 验收：不同身份/空间/机器权限独立；任务凭据只服务 Runweft 自身传输/协同，不代替原生机器凭据；伪造字段无效；token 轮换/撤销、成员移除即失权；重启保持归属，映射不能被抢占。
- 验证：真实 SQLite、认证单测、迁移/并发/重放测试；typecheck。

### T2 HTTP 与文件授权网关

- 交付：受控认证交换、原生路由授权与响应过滤、会话/附件绑定、流式传输取消、旧入口拒绝。
- 验收：可用的机器/会话/文件只展示本人权限内内容，可信启动意图可核对 receipt 后 adopt；root/HAPI JWT/未匹配入口不能绕过。
- 验证：真实 HAPI 专用实例，允许与拒绝成对检查，传输中撤销、响应丢失与重启。

### T3 Socket、终端与 SSE

- 交付：现有 Socket.IO 库转接、按对象限制 RPC 注册/心跳/消息、终端和 SSE 当前权限检查及空闲撤销。
- 验收：原生 Runner 连接和 RPC、原生终端双向可用；跨对象握手/事件/ack/重放拒绝；撤销后现有连接不能继续收发。
- 验证：真实 HAPI、Runner 与协议测试，WebSocket/polling、SSE 重连和背压；不靠新增 runtime 实现。

### T4 整体验证与下阶段接口交付

- 交付：可重复集成 smoke、安装产物编译检查，记录真实覆盖、明确默认服务尚待阶段 5 迁移。
- 验收：两用户两空间的认证、对象、直接 API 与长连接矩阵通过；无根凭据外泄；新模块无旧入口旁路。
- 验证：bun run typecheck、bun run test、bun run build，真实 HAPI smoke，逐项核对 [验收矩阵](validation-matrix.md)；通过后同步 Specs 和归档。

## 风险与限制

原生新建/续接会话的归属必须在暴露前绑定，客户端元数据不可信；不支持的路径明确失败。HAPI 更新需审计路由和事件表。中间阶段保持旧部署可运行，不自动启用尚未完成 CLI/资源迁移的新网关；最终交付必须移除旧凭据旁路。
