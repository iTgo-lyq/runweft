# 恢复 1.1.5 官网接续

## 背景与目标

用户授权正式发布并测量完整耗时。1.1.5 五包已经完成全部发布门禁并晋级 latest；[发布 run](https://github.com/iTgo-lyq/runweft/actions/runs/38345712525)的官网接续和[对应官网 run](https://github.com/iTgo-lyq/runweft/actions/runs/38348023714)失败，需要定向修复后恢复官网，不重发包或重跑成功的产品验收。

## 范围与行为变化

修正测试夹具继承 `RELEASE_VERSION` 导致模拟 push 被错误识别为发布接续的问题。等待器在 dispatch 返回的精确 run ID 上，允许未完成运行短暂显示默认工作流标题；标题就绪后仍核对版本/run/attempt，完成状态必须严格匹配并成功。

没有产品接口、数据、模型或不可变 npm 候选变化。修正文件不属于 packageInputs，已发布 1.1.5 的包和 tag 保持原样。

## 方案要点与验收

- 只对 Beta 子进程夹具清空继承的发布版本，真实生产接续的严格检查继续有效。
- 覆盖默认标题到正确标题的真实 API 时序、错误完成标题及一直默认标题超时；始终只 dispatch 一次，不扩大运行身份或成功判据。
- 运行 Node 发布/官网检查和流程、文档、diff 验证；使用 `RELEASE_VERSION=1.1.5` 复现环境确认修正。
- small 自验收归档并按用户发布授权合入 main；只恢复官网并记录实际结果及耗时。原失败与人工修复时间如实保留，不回写既有归档。
