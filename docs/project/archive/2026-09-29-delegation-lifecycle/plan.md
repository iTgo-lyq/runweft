# 本地共享委派实施计划

> 来源：[Requirement](requirement.md)
> 技术方案：[Technical](technical.md)、[协作契约](contract.md)、[中心协调](coordinator.md)
> 执行模式：逐任务提交
> 评审：当前工作区 iclaude 一次，明确额度不足时才用替代 subagent。

## 交付目标

主 agent 通过已安装 MCP 完成本地共享目录的派生、等待、消息、续接、中断和结果读取；任务原生终态及进程停止由中心封装 HAPI 确认，宿主断线不取消任务。CLI 提供一致的操作者入口，配置和数据沿前置模块。

## 关键风险

- 不将持久接受、输入消费、原生终态、进程关闭、成果可取回混成同一状态；未知副作用只查询，不自动重放。
- 当前只开放发起机 shared；未实现的模式明确拒绝，不能把另台机器的同名路径当作主工作区。
- 角色从已验证 MCP 身份、HAPI_SESSION_ID 和中心 child 关联判断；CLI 不伪装原生父身份。
- Codex 同业务轮次追加沿原生队列/steer 返回实际归属；Claude 仅支持下一轮排队，不能假装支持 steer。

## 任务

### T1 中心接受与单轮执行闭环

- 交付：schema v2 保留资源登记；业务记录与 request 去重、父/目标/共享目录约束、服务进程内协调器，从持久接受到真实原生查询和自动关闭的内部端到端流程。
- 验收：并发同请求只有一次接受/执行；输入前保存关联；纯报告/非 Git 无额外副作用；宿主请求断开后仍可收尾；启动/输入/关闭未知不冒充成功或重复执行。同时交付 task spawn/list/show/wait 作为正式使用和验收入口，MCP 由 T3 接入。
- 验证：SQLite 升级、HAPI HTTP fixture、丢回复/重启/并发窗口、专用实际 HAPI + CLI 单轮执行与退出证据、JWT 续期、轮次历史游标、类型检查。

### T2 串行续接与定向控制

- 交付：下一轮排队、复用 session、精确缺失时历史重建、本轮 Codex 追加、定向中断、原生权限响应和报告解析/分页，同时交付 task send/interrupt/permission。
- 验收：下一轮等待前轮停止和模式收尾；环境/目标不随配置变更重定向；新旧 HAPI/native 身份保留，只有明确缺失重建；迟到操作不命中后轮，缺少结构化报告仍可读取原文。
- 验证：聚焦状态组合与实际两种 runtime 的 resume/中断/默认权限、Codex 追加与 Claude 不支持分支；明确模型/推理参数真实启动。

### T3 CLI 与原生 MCP 协作入口

- 交付：完善 task CLI 与完整 MCP 工具，共用客户端、受控子拒绝、请求查询、revision 游标、可取消等待和清晰错误；既有 serve 自动承载协调器。
- 验收：任务接受立即返回；工具断线不取消或重复运行；MCP 原生身份和 CLI 操作者来源明确；Codex 自有 MCP 超时与 wait 余量匹配；安装无需新增独立进程/配置；其他 MCP 与原生子代理不被限制。
- 验证：CLI 子进程、MCP 协议/取消/工具列表、父权限/namespace/子角色、HTTP 服务组合及类型检查；每个真实宿主先完成 spawn→wait→read、子 CLI 拒绝，Codex/Claude 真正超过 60 秒的 wait 超时响应。

### T4 两宿主两 runtime 配套验收

- 交付：可重复运行的原生协作 smoke，使用编译 Runweft/HAPI 验证完整用户流程和本轮结束自动关闭。
- 验收：Codex/Claude 宿主分别调度 Codex/Claude runtime；非 Git 共享编辑与纯报告、追加/中断、后续 session 历史、连接中断、CLI 子端递归拒绝有真实证据。当前模式为同机 local 与 Hub 协议组合，不冒充实际跨机执行。
- 验证：专用 home/工作区、四种组合、进程/原生事实和磁盘副作用；故障清理有证据，模型未知不得靠文本猜成功。

### T5 完整使用说明与阶段关闭

- 交付：任务协作/诊断/数据维护说明、需求证据映射与候选安装包；作为关闭流程中 Specs 同步和独立归档提交的验收输入。
- 验收：从安装配置与定义到派生/等待/续接有清晰命令；无未解释失败、临时数据残留或未提交实现，完整项目仍按后续 Changes 推进。
- 验证：常规回归、类型/构建、候选安装与适用服务回归、文档结构/链接检查；复用未变化的前置证据，不重复无关模型任务。
