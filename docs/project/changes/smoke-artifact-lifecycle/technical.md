# 验收现场与证据治理方案

依据 [Requirement](requirement.md) 和 [Research](research.md)，复用现有验收入口，收敛现场所有权和消费者边界。本文与 [Plan](plan.md) 是用户要求的审阅草案，尚未获得实施确认。

用户随后要求重新评估测试分层和脚本是否过重。[补充调查](research.md#补充调查测试分层与脚本成本)发现问题涉及测试职责与 CI 触发范围；下述目录治理草案需要结合该结论重新确定范围，当前不据此进入实施。

## 方案

### 独立创建测试现场

普通单元测试使用自己创建的唯一临时目录，并在测试结束后回收；不把仓库中预先存在 `.dev-smoke` 当作测试环境条件。卸载验收分别准备工作根和报告输出父目录，输出位置不再隐式决定工作根是否存在。现有专用 HOME、原生配置目录和 npm 隔离设置保持。

保留有意义的验收输出路径，不新增“先建空目录再运行全部测试”的补丁脚本，也不要求所有生产者立即支持一个新的全局环境变量。已有 `RUNWEFT_SMOKE_ROOT` 只有部分入口支持，按实际能力使用。

### 回收本次拥有的可重建数据

每个入口负责自己创建的唯一现场，显式列出可重建目录和需保留的产物。只抽取重复的路径边界与删除检查到小型 helper，业务成功、服务停机和消费者结束条件由各入口判断，不建立通用临时目录管理器。

| 场景 | 回收条件 | 留存边界 |
| --- | --- | --- |
| 普通安装、服务、包验收 | 断言全部成功；本次服务确认停止；报告已保存 | 回收 npm prefix/cache、专用 HOME、解包和 HAPI 源码展开目录；保留根及嵌套 evidence、约定日志 |
| 官网验收 | 浏览器检查及适用安装检查成功；浏览器和服务器均已关闭 | 回收专用安装与工具夹具；保留 DOM 命令、截图、证据和诊断日志 |
| 完整卸载验收 | 验收成功且配套进程停止 | 回收测试现场；外部输出报告不受影响。断言失败时即使停机成功也保留现场 |
| `RUNWEFT_SMOKE_KEEP_INSTALL=1` | 普通验收不得回收仍有消费者的安装 | 保留配套 Runweft/HAPI 及其依赖；继续返回可用路径和程序摘要，后续由现有消费者明确结束 |
| 失败、停机未知、回收异常 | 不执行正常成功回收 | 保留剩余现场，报告失败/留存原因；继续现有敏感临时文件擦除规则 |

删除仅面向已登记的本次路径，不扫描历史兄弟目录、系统临时目录或用户目录，不跟随符号链接。嵌套服务证据先确认可读取，再回收同级大文件；父入口不能整棵删除子证据目录。既有原生 `removeFileSmokeData` 的根层白名单不能直接套用到含嵌套证据和截图的入口。

报告保存失败时保留现场；回收中途失败不能恢复已删除的可重建文件，但必须保留剩余文件、写入错误并返回非零状态。可重建数据回收与产品卸载/用户业务数据删除是两个不同的调用边界，后者不改。

### 将 Kit 检查纳入正式入口

扩展现有官网安装验收与包内容校验，复用 `checkRunweftKit` 的元数据、引用与文件枚举能力；不另立第二套临时安装工具。

官网继续执行实际 DOM 中提供的 Codex 安装命令；Claude Code 采用同一公开来源、同一 Skill 选择和 CLI 选项，仅切换正式支持的宿主参数。两个宿主分别使用独立 HOME、CODEX_HOME、CLAUDE_CONFIG_DIR 和缓存，检查各自的实际发现位置及旧名缺失，避免共享安装掩盖某一宿主失败。浏览器限定模式继续明确跳过真实安装，不因此变成双宿主安装证明。

包校验使用冻结候选携带的 Skill 清单/归档及其来源进行完整文件集合与字节比较，覆盖 `agents/openai.yaml`，不保留分散的五份/六份硬编码清单。公开 Kit 只要求名称、引用、内容结构与宿主发现正确；需要字节一致性时必须绑定明确的分发 revision，不能比较可变公开 main 与任意应用源码 HEAD。

上述正式检查通过后，删除本地 `verify-kit-install.py`。不会改产品 Skill 正文，也不安装到开发者全局或启动模型。

### 显式选择证据输入

将 `report-evidence` 的输入改为一个或多个显式目录/报告路径；无参数时报用法错误，消除本地默认遍历整个历史根目录的隐式行为。调用方使用本轮生产者返回的路径，多个入口的结果显式列举；去重后每个报告只输出一次，JSON 损坏继续报错。

现有 CI 的每个 job 使用新工作区，默认根目录内是该 job 的产物，因此这些调用可以显式传 `.dev-smoke`，无需为本次治理重构全部生产者。复用本地工作区的命令文档必须给出具体本轮路径。网站 job 继续显式传 `.dev-smoke/website-pages`，保留其收集普通 JSON 的现有模式。

日志包裹结构 `RUNWEFT_CI_EVIDENCE={path,report}` 保持；官网 `check.json`、`deployment.json`、`prepare.json` 的序列化路径保持 `.dev-smoke/website-pages/...`，避免破坏 Actions 日志恢复。读取文件时可以解析绝对路径，但不要顺便把日志中的逻辑标识改成绝对路径。

## 影响与取舍

本方案治理正式脚本的创建、消费和回收责任，允许 `.dev-smoke` 继续作为部分验收输出根。目录字面量不是删除标准：历史归档、HAPI 哈希测试向量、官网恢复标识和原生续验入口继续保留。

HAPI 中实际向父目录写入的十个测试属于独立 fork；以后在 fork 将其改为自有临时目录，分别在独立 checkout 与 submodule 中验证，再随必要 pin 升级集成。本 Change 不为字符串清零触发四平台重建。OIDC 证据形式也不在本次治理中扩展。

已删除的历史产物无当前消费者，三个保留项的去向见 Research。索引草稿与未知元数据不会阻塞正式脚本改造，也不会在实施结束时被顺带删除。

## 验证

| 风险/需求 | 验证路径 |
| --- | --- |
| 空父目录导致测试顺序依赖 | 独立 cwd、无 `.dev-smoke` 运行受影响 Node 用例；卸载报告写到工作根之外 |
| 成功仍残留大文件、误删外部文件 | 普通安装/服务/包/官网定向运行；核对本次拥有路径消失、链接外哨兵保留、证据仍可读取 |
| 失败现场被提前删除 | 注入断言失败、停机未知、删除失败；核对非零退出、原因和剩余现场；卸载失败但停机成功单独覆盖 |
| 显式保留安装失效 | KEEP_INSTALL 定向运行后复核 CLI/HAPI 路径、候选摘要及现有无模型消费者预检；不自动重跑真实模型矩阵 |
| Kit 漏检或错误绑定发布节奏 | 两宿主独立公开安装；缺文件/多文件/旧名/错误引用反例；固定候选完整文件检查，公开来源独立更新反例 |
| 丢失证据或历史串入 | 根及嵌套报告保留；旁置历史失败报告；显式多输入去重；本轮坏 JSON 失败；无参数用法错误 |
| 官网恢复协议回归 | 现有 Actions 日志恢复和发布 Node fixtures；既有 path 标识不变，无需真实上传 |

执行阶段按改动运行 Node 测试、文档/工作流检查和适用的类型检查，再定向运行安装、包与网页验收；失败先定位，续验具体失败项。实现完成后按 medium 流程做独立审查，不以此前的方案审计代替实现审查。本轮仅有历史清理与文档改动，尚未执行上述实施验收。
