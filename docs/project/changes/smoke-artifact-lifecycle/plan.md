# 验收现场与证据治理计划

依据 [Requirement](requirement.md) 与 [Technical](technical.md)，按 T1 → T2 → T3 → T4 串行实施。现场回收、官网安装和证据输出有共享文件及消费者关系，不拆并行任务。任务状态仅以 `change.json` 为准。

## T1 消除验收对预存父目录的依赖

使普通 Node 测试拥有独立临时目录，卸载验收分别准备工作根与输出父目录。交付不依赖其他检查先创建目录的执行入口，并保持既有用户环境隔离。

验收：受影响用例在无 `.dev-smoke` 的独立 cwd 下通过；卸载报告路径位于其他目录时不会因工作根不存在失败。运行定向用例及相关 Node 回归，不通过额外预建目录掩盖缺口。

## T2 按成功与消费者边界回收验收现场

统一安装、服务、包、官网和完整卸载验收的成功回收条件，保护嵌套证据、截图和显式保留安装。修正卸载失败但停机成功仍删除现场的行为，同步本地验收留存说明。

验收：普通成功不遗留本次大型可重建数据；失败、停机不确定及清理异常留存且可辨别；链接外文件不受影响；KEEP_INSTALL 返回相同候选的可用配套程序。以边界反例测试加一次适用的定向安装/服务/包/浏览器验收验证，不扩大到完整模型矩阵。

## T3 将双宿主 Kit 安装检查迁入正式验收

在现有官网/包校验能力内覆盖 Codex、Claude Code 各自的公开安装、当前名称及发现位置；完整文件集合用于冻结候选比较，公开 Kit 维持独立发布契约。正式覆盖完成后删除临时 Python 脚本。

验收：两宿主使用不共享的隔离用户目录，通过安装与旧名缺失检查；完整文件检查能发现 `agents/openai.yaml` 等遗漏、额外文件和内容变化；公开 Kit 正常独立更新不因任意源码 HEAD 不同而失败。验证新增安装现场服从 T2 回收规则，浏览器限定模式仍准确标注跳过。

## T4 限定本轮证据输入并完成集成验证

证据收集要求显式输入并支持本轮多个路径，更新 CI 与本地命令说明。保持官网日志路径协议与原生续验边界，完成文档和入口一致性核对。

验收：本轮根和嵌套证据均可收集，相邻历史失败报告不串入；重复输入不重复输出、损坏 JSON 不被吞掉、无参数明确失败；既有官网恢复样例通过。运行适用的 Node 回归、文档/工作流/diff 检查及跨入口定向验证，独立审查最终实现，再提供 medium 人工验收材料。

## 执行条件与交付边界

用户已授权的一次性清理和 AGENTS 提示删除记录在 Research，未作为上述尚未实施任务的完成证据。完整需求、技术方案和计划获得确认后才进入执行；确认时沿用本轮审阅结果，不逐任务重复请求批准。

不依赖新的产品凭据或真实模型调用。安装/包验收需当前 Bun、固定 HAPI 构建、有效候选包和网络；官网验收需兼容 Chromium。执行前核对现有候选是否适用，缺失时按仓库现有构建入口准备，不能把准备失败记为验收成功。HAPI fork 整理、外部索引事项及未知元数据来源确认不作为本 Change 的隐藏前置。
