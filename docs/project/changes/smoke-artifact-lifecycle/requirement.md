# 验收临时现场与证据生命周期治理

## 背景与目标

`.dev-smoke` 同时承载可重建安装、测试数据、证据、临时工具和待处理草稿。清空旧产物后，正式入口仍会重新生成大量现场，个别测试还依赖目录事先存在。目标是让开发者能够独立执行验收、获得本轮可信证据，并明确哪些现场可以回收、哪些必须留给后续消费者。

用户已授权先清理明确无影响的历史产物、删除 AGENTS 中指定临时目录的提示，并要求准备技术方案、走 Change 流程。2026-10-14 已执行的清理及例外见 [Research](research.md)。本次授权不等于全部后续改造已获确认；按用户要求一并准备 [Technical](technical.md) 和 [Plan](plan.md) 供审阅。

## 范围

涵盖本仓库安装、卸载、服务、包内容和官网验收的临时现场管理，独立测试的目录准备，公开 Runweft Kit 安装检查，以及本轮证据的显式收集。暂定 medium：现场生产与回收、Skill 分发验收、证据消费三个职责需要联动修改逻辑。

保留当前正式验收入口、npm 与 Kit 独立发布边界、官网日志恢复协议，以及原生验收的配套程序和定向续验能力。历史归档继续作为证据保存。

本 Change 不改用户数据清理策略、模型配置或凭据，不升级 HAPI pin，不执行发布或部署。HAPI fork 内的测试目录整理另行处理。索引纠错草稿与来源待确认的 deploy-key 元数据继续保留，前者不自动发送，后者不读取内容或迁入源码。

## 行为变化

### MODIFIED 独立验收与现场回收

现在部分用例依赖已有父目录，成功验收留下安装、缓存和服务数据；卸载验收可能在断言失败但停机成功时删除现场。调整后，各入口自行准备所需目录；只有本次验收成功且所有本次服务确认停止，才回收本次拥有的可重建数据，保留需要收集的证据、日志和截图。失败、停机不确定或回收失败明确报告并保留剩余现场。

显式保留安装时，后续消费者仍获得同一候选的 Runweft/HAPI 程序。普通成功回收不得使该入口提前失效；恢复现场不纳入自动过期或全目录清理。

### MODIFIED 正式安装与证据检查

公开 Kit 的 Codex、Claude Code 安装与名称检查进入正式验收，在互不共享的专用用户目录执行。包内容检查覆盖完整文件集合；公开 Kit 可以独立更新，不要求其公开 main 与任意应用源码 checkout 字节一致。

证据收集由调用者指定范围，复用本地目录时只收集本轮输出；CI 的新工作区可以显式选择本 job 的根目录。损坏 JSON 继续失败，官网恢复所需的日志路径标识保持有效。

### REMOVED 临时提示与重复工具

删除 AGENTS 中要求临时文件放 `.dev-smoke/` 的提示。临时 Python 安装检查的必要能力迁入正式入口并验证后，再删除该脚本。已完成的一次性历史清理不转化为产品自动清理功能。

## 验收标准

1. 不存在 `.dev-smoke` 的独立工作目录中，相关测试和自定义输出路径的卸载验收能自行准备现场，不因父目录缺失失败。
2. 普通成功验收不再遗留本次大型安装、缓存、解包和服务数据；嵌套证据及约定日志、截图仍可读取。
3. 失败、停机未知及回收异常均可辨别且不误报成功；不跟随现场内符号链接删除外部文件。
4. 显式保留安装仍能被后续消费者使用，候选程序摘要不变；不影响原生续验的拒绝错误候选规则。
5. 两种宿主各自安装得到当前 Kit，目标发现目录无旧名副本；完整包内容检查包括 `agents/openai.yaml`，公开 Kit 的独立更新不误阻断 npm 验收。
6. 本轮目录旁预置历史失败证据时，显式收集只得到本轮结果；损坏本轮报告不能被跳过或视为成功；既有官网恢复样例仍可读取。
7. 三项暂存例外按各自条件处理，历史归档及 HAPI 固定测试向量不做路径替换。

## 可行性与限制

已确认目录前置缺口、成功后残留和现有路径消费者；调查包含正确 iclaude 配置下的独立评审及主 Agent 复核，详见 Research。后续自动回收、两宿主正式覆盖及证据接口改造尚未实现和验证。本次不改变 UI，无原型交付。
