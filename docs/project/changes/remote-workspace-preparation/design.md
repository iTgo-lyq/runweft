# 远端工作区准备

> 状态：草稿
> 来源：[本 Change 需求](requirement.md)、[跨 Change 架构](../../architecture.md)
> 按用户要求保留需求阶段的方案讨论；本文件不是已确认 Technical，也不代表已实现。
> 已确认：主仓库继承、每个 subagent 独立 worktree、启动前完成本文件的必需准备；项目依赖由 agent 启动后安装。

## 1. 主工作区准入

本机 Runweft 从 MCP/CLI 绑定的真实目录读取 Git 信息，记录仓库根目录、当前工作树身份、工作子目录、Git 对象格式，以及主 agent 明确选择的 `baseRef`。

- 非 Git 工作树、尚无 commit、ref 不存在或有歧义：拒绝远端委派。
- 将 ref 在主仓库解析为具体 `baseCommit`，先保存该对象的保留引用，再发起远端操作。之后分支移动不改变本次基线。
- 主工作区存在未提交或未跟踪文件可以发起基于指定 commit 的任务，但响应与子任务上下文必须说明这些内容未包含；不自动 stash、commit 或同步脏文件。
- 子目录项目保留相对仓库根的 `workdirRelativePath`；该路径必须在指定基线中可用，不把主机绝对路径直接交给远端。
- 子任务从同一仓库派生，不接受 agent 任意更换 repo URL。非 Git 输入用附件表示，不能伪装成另一个任务根仓库。

`repositoryId` 与允许的 Git 来源先由主工作区绑定确定。按已确认策略，无 remote URL 或基线尚未 push 的本地 Git 仓库仍可通过 bundle 提供已提交基线。

## 2. 冻结准备输入

协作服务先持久化下列逻辑清单，之后才调用 HAPI；相同 `requestId` 的重试返回同一 `delegationId`。

| 字段 | 含义 |
| --- | --- |
| 主体、namespace、`workspaceId`、`repositoryId` | 谁从哪个主工作区委派 |
| `delegationId`、`preparationId` | 子协作上下文与准备操作身份 |
| `baseRef`、`baseCommit`、对象格式 | 用户选择和本次不可漂移的实际基线 |
| `workdirRelativePath` | agent 应启动的仓库内目录 |
| `target` | HAPI 实例、机器、runtime 及所需能力 |
| `source` | 已授权 Git 来源，或已确认上传的输入 bundle |
| `inputs[]` | 输入附件 ID、hash、类型与目标逻辑名称 |
| `contextRevision` | 任务说明、agent 定义及 prompt 模板的固定版本 |

只记录凭据引用，不把 Git token 放进 URL 或清单。清单准备好不意味着远端已经执行成功。

## 3. 取得 Git 对象

bundle 是已确认的默认传输方式；已授权 Git 来源可作为取得相同对象的优化，最终都必须校验同一个 `baseCommit`：

1. **Git 来源可访问：** HAPI 侧在受控缓存中 fetch 本次所需引用；在缓存中确认实际 commit 与对象闭包可用，不能直接用远端分支的最新 HEAD 代替本地冻结值。
2. **基线未推送或没有可访问来源：** 主机将固定保留引用打成 Git bundle，通过附件中心传输；目标导入受控缓存。首版可传所需基线的完整可达历史，后续有接收方前置对象证明时再优化为增量。

Git bundle 只提供 Git 对象，不自动包含 LFS 实体、子模块仓库、ignored 文件或依赖目录。项目需要 LFS/子模块时，初始化策略必须在启动前取得它们并校验对应版本；能力或凭据不足则拒绝启动，不把不完整工作树称为已准备。

网络失败时，仅当缓存已具有精确基线及所有声明必需对象才可继续，并记录实际来源；不能以“缓存里有同名分支”降级。禁止为传输基线自动推送主分支或改写用户远端。

准备完成前在中心持久保存可恢复的基线对象闭包及保留引用；可从已上传的输入 bundle 导入，或由中心读取已授权 Git 来源后封存。多个任务可在同一权限范围复用已验证基线。仅保存 URL、SHA 或执行机缓存不满足此条件：源仓库删除分支、执行机丢失后，结果仍须能验证和取回。完整历史的首传成本与存储配额必须计入准备开销。

## 4. 复用公共 Git 工作区

HAPI Runner 在已明确的受控数据根中维护仓库对象缓存；跨机取得精确基线后，调用[公共 Git 准备](../local-workspace-execution/design.md#准备与启动)创建或复用 worktree。repository/environment/preparation 身份及 Git 收尾由公共工作区 Change 唯一定义。

本 Change 负责远端机器选择、Git 对象来源、缓存同步和输入落地。缓存中的 Git 修改沿公共并发保护，不重复实现分支、worktree 或归属检查，也不创建另一个执行器。

工作区、输入、上下文和输出均位于统一 CLI 声明的持久数据布局内；不为每轮使用随机系统临时目录保存必须续接的现场。不同 subagent 用不同 worktree，同一 subagent 跨轮次复用。

## 5. 输入与上下文

- 下载所有必需输入，校验长度和 hash；输入目录逻辑上只读，执行期不覆盖同名输入。
- 将仓库身份、基线、实际工作路径、输入附件映射、父任务说明和成果规则写入任务上下文。
- 优先使用 runtime 原生附加指令入口或仓库外的上下文文件，不覆写仓库受版本控制的 AGENTS.md/CLAUDE.md。需要临时辅助文件的适配必须能排除其进入成果并在结束后清理。
- 主工作区的实际源代码由 Git 传输，不塞进 prompt。用户明确提供的补充材料走输入附件。
- 不执行按技术栈猜测出来的安装、构建或数据库脚本；这些交给启动后的 agent。机器必需工具、原生登录与 Git 能力属于预检查。

runtime 对仓库外输入/上下文目录的访问规则必须实测；若只能读取 cwd 内资源，则在专用保留目录挂载/复制并验证排除规则，存在路径冲突时拒绝启动。

沿原生全局配置和已准备 cwd 发现工程 skill/MCP，不创建空白配置 home，也不集中同步它们。工程配置随所选 Git 基线到达，ignored 或未提交 skill 不因设置 cwd 就自动出现在远端；细节归[Agent 定义](../../archive/2026-09-29-agent-definition/requirement.md)。

## 6. 远端准备完成与启动条件

远端回执组合公共准备证据、执行机器/runtime 引用、Git 来源、输入摘要和上下文版本。基础 Git、目录归属、HEAD 与版本的实际启动检查沿[公共工作区能力](../local-workspace-execution/design.md#准备与启动)执行；远端额外核对目标机器、已到达输入和对象完整性。

任一必需准备失败不启动 agent。Hub 可提前保存关联，但不能让子 agent 通过 prompt 补做任务根仓库初始化；启动已准备路径时也不再创建默认 HEAD 的 worktree。

本 Change 可单独验收跨机准备及专用启动探测。正式远端代码协作的 CLI/MCP 模式须在远端成果回收也就绪后开放，不能把不可取回的远端改动当作功能完成。

## 7. 续接与基线变化

同一 delegation 复用 worktree、分支、依赖目录，原生 session 优先续接，但每轮结束都关闭子执行进程。第二轮通过 HAPI 重新启动/续接，从上一轮成果继续；session 缺失时按[委派设计](../delegation-lifecycle/design.md#7-一轮结束与下一轮续接)构造历史。初始 `baseCommit` 仍保留，每轮另外记录开始 HEAD。

主工作区的新提交不会自动同步到活跃 subagent。建议基线变化创建新 delegation；显式同步旧环境可作为后续能力，不能偷偷 reset 或 rebase 正在协作的分支。

新增输入按轮次创建不可变版本，在该轮消息交给 agent 前准备好。工作区丢失时可以从已发布成果重建，但这是一次明确恢复：保留恢复依据、可能丢失的依赖缓存和原生历史范围，不宣称无损续接。
