# 未上线版本的历史清理

> 2026-10-01 用户修正：项目尚未上线，无需兼容迁移历史。此契约替代原 YAML/多库迁移设计。

破坏性更新直接清理旧试验数据，再按新 Hub 流程登记机器、runtime、仓库和 Agent。不实现 namespace 归属映射、历史快照转换、跨库 staging/journal、迁移继续或回退框架，也不提供旧 YAML 导入器。

提供简单的显式清理命令，列出当前数据根内将删除的业务库、托管原生数据和本机连接/机器记录；实际清理要求对应服务已停止。只清理本产品管理且明确列出的路径，不遍历或删除项目仓库、保留的 worktree、用户 Codex/Claude 全局配置或模型凭据。命令说明历史任务、附件、身份和登记需要重新建立，`paths` 能核对实际数据根。

新服务不读取旧 YAML 为运行配置，不自动认领或执行旧无中心归属的任务。现有简单加表升级可保留；遇到不兼容的试验库直接给出清理命令，不为恢复旧库新增转换层。无需为了未上线数据维持生产级历史升级矩阵。

本任务同时检查本阶段的过度封装：删除只为旧配置兼容、迁移或假设扩展服务的重复适配和默认退路；保留有实际调用方的 HAPI 复用、身份授权、请求幂等与真实执行结果判断。清理不能把不确定执行伪装成成功。

自动验收在专用数据根验证清理后可首次启动、重新接入和委派，并确认根目录之外的仓库、worktree 和用户配置未被修改。不自动清理开发者真实数据或部署服务。


实现命令为 `runweft [--home <数据根>] data reset`，默认只列出清理与保留范围，`--apply` 执行。它不读取旧配置，因此 tokenEnv 等不兼容字段不会阻碍清理；同时删除 config.yaml，后续显式 init 重新配置。清理前检查托管服务和所有连接的 Runner 进程记录，发现存活、损坏记录或路径符号链接时在首次删除前拒绝。不会按进程名扫描或停止其他服务。

清理固定包含中心业务目录、托管 HAPI 的数据库/令牌/附件、旧全局 Agent 文件、本机 client.sqlite、各连接的身份/机器记录与原生 Runner settings/state。保留各连接的 workspaces 全树（含 Git 缓存）、artifact-transfers、日志和 MCP 安装备份；目录之外的仓库和原生模型配置不触及。保留现场失去中心历史关联，需按原路径自行审查回收；不提供自动重新认领。

消费命令不再选择旧客户端分支；删除旧 Agent/资源命令生成器及本机工作区绑定目录。MCP 仅使用已验证宿主 cwd，不为每次工具调用维护另一套工作区身份。已有领域回归使用的原生 HTTP fixture 与纯业务协调器保留，不为测试重新打开默认服务的旧授权入口。
