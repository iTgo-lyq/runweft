# 测试与工程辅助流程重构实施计划

依据 [需求](requirement.md) 和 [技术方案](technical.md)，按第五轮明确的覆盖取舍推进。删除清单与原始证据见 [Research](research.md#可直接删除的具体用例)，前四轮评审中被第五轮替代的保留要求不再作为实施约束。

## 交付边界

最终形成少量核心状态测试、主要跨模块契约集成、五项原生主链及按影响选择的专项；固定测试自行准备和收尾，灵活验收使用独立的 `dev:env start/stop`。完整操作入口交付为 `docs/testing.md`，launcher 放现有 src，不新增测试框架、领域目录或旧入口别名。

每项包含对应实现、必要验证和现行说明，一起提交推送。T1 的首轮 Actions 暴露未准备 submodule 时的文档校验依赖，追加 T11 先修复，保留已完成任务记录；其余按原编号串行。Bun 试点先验证真实清理语义；原生模型验收安排在候选和公共准备稳定后，按冻结的源码/测试版本执行，避免对每个中间版本重复付费验收。已选核心保障的替代与旧入口删除同批交付，直接放弃的低价值覆盖不补等量测试。

## T1 按改动选择 CI 检查与依赖

**交付**：让轻量 scope 先于依赖安装，统一本地与 CI 的选择规则。修复新分支零 SHA、PR merge-base、测试/helper 漏选和最终汇总假绿；选中什么才准备什么。暂用当前入口，后续任务在替换入口时同步唯一映射，不为未来文件建空注册表。

**验收**：文档-only 无产品依赖、HAPI、宿主或浏览器安装；原型、官网、Kit 只选所属检查；共享影响无法确定时保守选择。重命名取新旧路径并集，删除按旧路径选，工作区参数纳入未提交和未跟踪文件。所选 job 失败、取消或缺结果不能通过汇总；native 仅输出建议，不被开发 CI 自动执行。

**验证**：使用 Git 临时仓库和工作流行为反例核对上述选择；跑 Node 工具测试与 actionlint。本分支文档提交产生的 CI 可作为实际无关依赖未安装的证据；不能把本地 scope 输出冒充 Actions 成功。只保留跨工具门禁断言，不再断言步骤显示名、固定分片数等实现细节。

## T2 删除已确认的低价值测试和不可达分支

**交付**：删除 Research 列出的 24 个低价值测试块及随之无用的 fixture/import，整文件移除 website-build 测试；删除 collaboration 的不可达 CONTROLS/DISCONNECT 分支。删除普通默认值、展示、诊断、参数和汇总排列，不追加等量替代测试。

**验收**：清单逐项能对应实际删除；配置失败不覆盖原文件、损坏数据库保留、真实字节/超时、发布失败和不可重复写入等既定保障仍存在。另 6 个依赖旧编排/交接的块留到 T4/T9 与机制替换一起删除。

**验证**：运行受影响的现有 Bun 测试文件、Node 工具测试和类型检查；检查被删 helper 的消费者。记录实际删除正文、辅助代码及接受的覆盖损失，不将文件搬移或整份旧脚本行数计为净减。

## T3 用真实接线试点 Bun 集成与关闭语义

**交付**：将精简后的 Hub 配置链改为 Bun 集成测试，作为其唯一固定实现；需要的准备/关闭使用就近普通函数。CLI 对替身仍可共享编译，真实 Hub/Runner 使用显式匹配的程序。试点用 Bun 原生入口运行，现有整体入口同步调用该实现；不创建第二份同场景测试或长期兼容命令。

**验收**：实际 setup、HTTP、子进程和收尾在成功及失败时有效；关闭逆序进行，一个失败不阻止其他资源关闭，重复/并发 close 复用同一结果。超时/关闭未知判失败且保留必要诊断，不靠 Bun 子进程兜底猜测 detached 服务已退出。非必要抽象不随试点引入。

**验证**：在固定 Bun 上运行正常链，并用代表性的 setup 失败、断言失败、超时和关闭失败检查进程/目录残留；保留忽略 SIGTERM 后强杀仍判失败的测试，缩短可注入宽限期。试点证据支持迁移后再进入 T4；若 Bun 生命周期假设不成立，先解决此交付，不批量搬目录。

## T4 集中核心契约并切换默认与集成入口

**交付**：将保留用例按实际成本归入 core/integration；跨模块契约按身份/配置、派发/轮次、文件/工作区、生命周期集中负责。删除其他层的完整复演，保留 CLI 的真实输入输出接线；复用身份/Runner、Git 基线等重复准备，断言使用独立可变现场。用一次 Bun test 调用和原生过滤/分片替代旧集成调度与清单。

**验收**：`test` 只运行少量核心测试，不编译 CLI 或要求 HAPI 可执行文件、宿主和浏览器；integration 的 CLI 编译只初始化一次，真实服务缺少匹配程序则失败。权限/CAS/撤销、不重放、文件字节与 Git 引用、SSE/RPC、服务退出等核心保障各有主要负责层。机器过期只保留一次实际等待；三条不同大文件传输边界仍各有明确保障，普通链使用小样本。旧分片变量、integration-cases 清单及其四个镜像测试随当前消费者切换一并删除。

**验证**：类型检查、core、tools 及迁移后的无模型集成；对权限绕过、错误重发、字节损坏选少量代表性反例证明剩余保障有效，不建 mutation 平台。验证文件/名称过滤、原生分片无缺项、缺依赖或空选择失败，以及无历史现场的运行。HAPI 内部 manager 专项只按 pin/协议/检查本身影响选择；本次改变选择接线时验证它确实执行并能阻断，无相关变更不额外跑全套。

## T5 收敛候选安装、启动与卸载验收

**交付**：以 Node 安装入口直接验证两种实际安装形态，合并 package/service/install/uninstall 的重复准备。launcher 移入 src，随候选输入清单和所有消费者一起切换；候选校验与私有安装函数归工程脚本，供后续自由环境和 native 复用。删除旧安装/包/卸载转发入口及 KEEP_INSTALL 获取环境机制。

**验收**：显式候选只读消费，运行资产来自候选，程序在 checkout 外运行；无需 Bun 可完成安装、服务/信号与退出、MCP 配置和卸载。成功释放安装根、cache、解包和 service 目录，失败按确认停机结果处理；候选摘要/平台/来源不符拒绝，不重建候选自我修复。四平台验证各自包布局与进程边界，不重复产品业务矩阵。

**验证**：本机执行安装的两种布局及代表性的候选不匹配、关闭失败；在无法访问 Bun 的隔离环境验证驱动和程序。更新四平台安装 CI 并取得对应结果；本机结果只证明本机，缺平台证据如实列出。使用私有 prefix 和专用配置，禁止借测试改变开发者全局安装或原生凭据。

## T6 缩减浏览器与原型验收到核心用户路径

**交付**：Hub 保留身份连接、配置选择、任务到原生详情三条主路径；普通浏览器检查使用当前格式样本，导出必要页面断言供 T9 消费真实历史。官网从六档宽度缩为桌面/手机两档；原型只保留入口加载、隔离、主导航和代表性交互。删展示字段/角色按钮/全错误排列及演示业务 CRUD 复演。

**验收**：真实 WebCrypto/原点绑定、跨 owner 隔离、撤权失效及日志/数据库/WAL 秘密扫描仍有归属。官网保留准确版本安装入口、复制/基本键盘、图片加载和无溢出；Kit 安装由 Kit 负责。原型保持 opaque iframe 和无外部请求，不将演示数据业务当产品测试。

**验证**：执行相关 Hub web 集成、官网实际构建和本地 browser-only 验证、原型所属 build/test；统计实际页面/视口/业务操作减少量。普通样本不能宣称验证了原生历史；N1/N5 的真实历史由 T9 在同 case 最终清理前核验。无需部署官网或原型来验证这些变更。

## T7 提供独立的灵活验收环境入口

**交付**：实现薄 `dev:env start/stop`，直接复用已稳定的配对程序、候选私有安装和身份/Runner 准备函数。默认仅本机 Hub，可选 Runner，以本次环境目录为操作句柄；不新增业务 seed、profile、任务调度或进程注册平台。

**验收**：`--bin` 或 `--candidate` 明确且二选一，不隐藏编译或候选切换；ready 后返回明确 URL、专用配置位置和停止方法。默认不复制模型凭据或启动模型。stop 核验目录归属和产品会话状态，活跃/未知时保留并说明待处理项；确认停机才删除。固定测试不依赖 dev:env，ready/stop 不生成业务验收通过结论。

**验证**：按真实程序分别走仅 Hub、带 Runner 和候选启动/停止；验证 setup 中途失败、重复停止、错误归属、活跃/未知会话不误删。检查服务后台化后启动终端退出仍可用明确句柄处置；业务操作由当前需求决定，不新增固定场景脚本。

## T8 明确工程工作目录与报告消费

**交付**：逐项落实 CI 工具/配置、发行源码与候选、空间记录、官网证据、安装报告和 Kit 导出的所有者及关闭/删除。工作流使用本次 run/attempt/job 临时根，本地传明确目录；report-evidence 消费显式文件列表。同步官网 publish/recover/verify-live 的物理位置调用契约，沿用现行日志信封、发行标记和官网稳定 path 标识。

**验收**：本项迁移的工程操作不要求 `.dev-smoke` 文件系统现场，原生链剩余依赖在 T9 随入口替换删除；官网协议字符串作为明确例外保留，历史记录不改写。报告在被测现场之外，已停止的资源再删除，清理失败不掩盖原失败。缺失/冲突证据不能猜测成功，恢复保持只读，不能因迁移路径重传/重发。Kit 有效安装检查归正式入口，其一次性导出由创建者回收。

**验证**：Node 发行/官网恢复测试、actionlint、显式报告收集与路径/缺失/冲突反例；使用既有证据或本地替身验证恢复决策，禁止真实发布。搜索所有活跃调用方核对去向，实际执行成功/失败路径检查根目录释放；不扫描或删除用户草稿、未知密钥和不属于本次的现场。

## T9 将原生验收收敛为单 case 生命周期

**交付**：`test:native --candidate … --case <case|main> --report …` 直接拥有准备、执行、历史/成果检查与收尾。main 仅 N1/N4/N5、C-codex/C-claude；删除 N2/N3/N6、expanded、独立 execution 和跨命令交接、stdout 路径解析及其剩余两个镜像测试。R-codex/R-claude/L-claude 按相关变化执行，不再是每次普通发行的固定附加链。

**验收**：三条 N 各一个任务两轮；N5 承担一次真实重启取回与不重放，N1/N5 承担真实历史。两类 runtime 保留批准/拒绝/中断，Codex steer/兄弟隔离集中于 C-codex。删重复 Git/LFS 构造、治理排列、记忆准备轮和 65 秒空等。N3 的 Git hook 失败/封存重试已在 T4 归入无模型工作区契约。

报告绑定实际候选、冻结产品/测试源码和构建输入、宿主/runtime 版本及模型/effort；不包含凭据/原生状态 hash。校验器从调用方接收必需集合，缺项、错误来源、失败/未知拒绝；认证刷新不使已成功模型验证误失败。公开 CI 重建包的安装证据与源码级模型证据分开，不能声称两个包逐字节相同。单 case 为复验单位，新现场重跑，不自动整组重试或拼接旧交接。

**验证**：先以无模型反例验证选例、候选/报告绑定、前置失败、真实进程超时和清理，冻结版本后再运行模型。在已经授权且专用的环境中验证五项主集合；本次改变恢复/长路径执行入口，选择对应三个专项验证接线。正常发行仍按影响选择专项，不将本次重构验收集合固化为以后必跑集合。记录真实模型轮次、耗时和首次失败，任何未执行 case 不记通过；缺环境/授权时明确阻塞相应实际验收，不用 mock 替代真实证据。

## T10 交付完整测试验收手册与整体验证结果

**交付**：将前序任务随入口更新的说明收敛成 `docs/testing.md`：首次准备、按改动选择、固定测试、自由验收、候选/原生、CI/发行、失败判读与定向复验、官网/原型/Kit 入口。每条路径写清触发、输入、命令顺序、通过条件、清理和失败下一步。发行文档保留发布/恢复操作，引用通用手册；AGENTS 更新现有检查入口，不新增任何临时脚本提示词。

**验收**：操作者能从改动类型找到唯一 scope 和可用命令，理解固定测试与前置环境的差别，无需读脚本寻找隐藏参数。旧命令、兼容交接、重复设施及失效说明有明确去向；主集合、专项和未覆盖边界明确，不能把少跑的保障说成等价覆盖或性能收益。

**验证**：在干净工作目录按手册完成普通回归、Hub 自由验收与显式停止、候选安装、一个受控失败后的定向复验；复用 T5/T9 同版本有效的平台/模型证据，相关代码变化才重验。运行与最终差异相称的类型、构建、固定检查及文档/流程检查；独立评审覆盖完整差异、需求和真实证据，整改有新任务记录。完成后提供人工验收材料，按 Change 规则再同步 Specs、归档；本计划不预填验收或授权发布。

## T11 修复轻量文档校验的 submodule 隐含依赖

**交付与验收**：修复 T1 在未初始化 HAPI 的干净 checkout 中失败。根仓本地引用照常核验，外部 HAPI 源码引用在未准备时明确报告未验证；已准备 pin 时仍核验实际目标。产品检查准备 HAPI 后补跑文档检查，不因历史引用给文档-only 引入源码或依赖安装。

**验证**：在不初始化 submodule 的临时干净检出运行文档/流程检查；当前已准备 pin 的工作区运行完整文档检查；Actions 复验并保留最初失败证据。

## 整体证据与规模核算

实施事实按任务写入 execution.md，评审问题沿用 review.md 的独立编号。任务状态只在 change.json；既有调查和归档证据保留历史含义，旧源码引用需要时固定到基线提交，不把新实现伪装为旧调查依据。

最终按需求验收标准核对以下结果，复用对应任务证据，不再无条件重复整组检查：

| 交付结果 | 主要证据 |
| --- | --- |
| 低价值覆盖实际删除，核心契约各有归属 | T2 删除记录、T4 代表性反例、T6/T9 实际操作量与已放弃覆盖 |
| 最小检查不准备无关依赖，必需检查不漏选 | T1 scope/工作流反例及 Actions；T4 core/integration 成本边界 |
| 固定测试独立运行，灵活验收入口单独可用 | T3/T5/T7/T9 成功、失败、超时与关闭证据；T10 手册实走 |
| 候选、数据和当前发布恢复边界得到保留 | T5 四平台安装、T8 只读恢复与显式报告、T9 来源与集合校验 |
| 工程结构更简单且规模透明 | 同口径代码/入口/调用关系对比、创建者到消费者到清理的闭环，无旧机制别名 |
