# 测试与工程辅助流程重构方案

## 方案与取舍

对应 [需求](requirement.md) 与 [现状证据](research.md)。本文是用户要求的可评审技术草案，提前展开以支持多轮架构决策；不代表需求、技术或实施计划已经确认。范围是工程验证体系，不扩展 Runweft 产品编排能力。

推荐以三种验证成本组织测试，以三种工程职责组织辅助脚本。核心回归允许真实 SQLite、临时文件和本机 HTTP，不再强行拆成纯单元与组件两套框架；启动真实 HAPI、编译 CLI 或浏览器的检查进入集成层；消费发行候选或调用真实模型的检查进入验收层。各层使用 Bun/Node 现有测试能力和普通函数，删除同一保障的重复长链，不建设测试 DSL、插件体系或全局场景注册中心。

## 改造后的组织全貌

```text
 test/
 ├─ core/                 # 规则、状态、协议组件；不要求 HAPI 构建/宿主程序/模型
 ├─ integration/          # 实际 CLI + HAPI 接线、文件/Git、Hub 浏览器回归
 │  ├─ hub/
 │  ├─ files/
 │  ├─ workspace/
 │  └─ web/
 ├─ acceptance/
 │  ├─ install/           # 候选内容、安装/卸载、服务信号、宿主配置；无模型
 │  └─ native/            # Codex/Claude 真实调用、控制/恢复/历史；显式运行
 └─ support/              # 确实跨套件复用的进程、隔离环境与候选读取
 scripts/
 ├─ build/                # Runweft/HAPI 构建、打包与来源校验
 ├─ check/                # 文档、流程、Kit、CI 范围；相邻 *.test.mjs
 └─ release/              # 发布/恢复、分发与发行结果；相邻 *.test.mjs
 packaging/               # 随 npm 包发布的 launcher 等运行资产
 website/                 # 官网构建/发布及自己的验证
 packages/prototype/      # 原型及自己的验证
 .agents/skills/           # Skill 与其所属工具/测试
```

目录只表达责任；不要求每层复制一套 runner、config、fixture 和 reporter。单一套件的辅助代码就近放置，跨套件已有共同语义再放 `test/support/`。发行生产逻辑不反向导入测试 fixture；构建或候选校验的通用逻辑留在所属 `scripts/` 模块，由验收复用。`packaging/` 明确 npm launcher 是交付运行代码，其行为回归归安装验收。

长期测试验证稳定产品契约，长期工具服务可重复工程流程。现场探索按需要临时处理，不新增临时脚本生成器、存放约定或 AGENTS/Skill 提醒。旧 `.dev-smoke` 不是新的长期工具目录。

## 执行入口与成本边界

| 入口 | 输入与依赖 | 保障范围 |
| --- | --- | --- |
| `bun run test` | 根依赖与 pin 的共享源码；显式只运行 `test/core` | 规则、状态和隔离组件，无 HAPI 构建、Codex/Claude、浏览器或真实模型 |
| `bun run test:tools` | Node；明确列出三个 scripts 职责中的测试 | 发布决策、范围选择与有分支的通用工程逻辑；不执行真实发布 |
| `bun run test:integration -- <suite>` | 明确的 CLI/HAPI 构建；web 才安装浏览器 | 当前真实接线、传输、工作区、UI；按 suite/测试名定向执行 |
| `bun run test:install -- <candidate> [case]` | 明确不可变候选；宿主配置 case 才需原生宿主程序 | 包内容、两种部署形态、服务/信号、配置、卸载；全程不调模型 |
| `bun run test:native -- <candidate> <case-set>` | 候选、专用原生配置、已授权模型 | 原生工具调用、实际历史、控制、重建及跨边界成果 |

不保留 `test:execution`、`test:packages`、`test:uninstall` 等旧转发入口；相关能力由安装或 native 的明确 case 承担。发行的完整集合由工作流固定选择，缺依赖/空集合必须失败；开发者有意选择子集只报告该子集，不冒充全量通过。`bun test` 不带路径的自动发现不能成为 CI 入口，避免递归误跑重层。

## 测试职责的实质收敛

### 核心层与集成层

根 43 个测试按断言证明的契约拆分，保留有效规则和组件回归；不按当前文件名整包搬移。编译 CLI、直接导入 HAPI 实现、启动真实宿主等检查从默认入口拿走，放到实际证明其边界的层；共享一次 CLI 编译的现状继续保留于集成准备，不重复建设缓存框架。

权限隔离、状态转换、重试幂等、不可重放、格式拒绝、成果映射等异常组合在最小真实组件上验证。真实 Hub 场景只补足认证中间件、Socket、HAPI API、CLI 调用与状态持久化之间的接线。下沉需要用代表性破坏证明低层会失败；不能用“有 mock 测试”作为删除集成保障的理由。

- 资源治理不再附带 MCP 安装检查。登记/共享/禁用/轮换归 Hub；原生 MCP 配置归安装验收，协议格式归核心，真实宿主调用归 native。机器过期策略尽量用可控时间验证，保留一条真实在线/离线接线；若当前接口不支持可控时间且修改会扩大产品 API，先保留必要的实际过期用例，不为提速扩展产品接口。
- artifacts/inputs/outputs/prune 与结果 fetch/tasks 收敛为文件与成果领域套件。小数据承担业务权限/内容断言；72 MiB、持续上传超过普通期限等专项按独立传输边界保留，使用同一数据生成工具，不强行合成一个覆盖全部路径的用例。
- Git 导入/导出与 workspace preparation 收敛为工作区套件。恢复、离线与留存断言分成可定位的契约场景；默认目录准备不一律构造 103 个文件，只有数量/分页/LFS 边界需要时才生成对应数据。保留真实 Git/LFS、字节、pin、ignored-file 与释放语义。
- 三个 Hub UI 入口合为 web 套件，浏览器只验证用户路径与页面绑定，权限/状态错误排列由非浏览器层负责。真实模型历史的呈现使用明确的新格式 native 证据作为输入，普通 UI 回归使用固定当前格式样本；两者的证据性质分开报告。
- 删除仅验证旧 smoke 编排结构、旧分组数量、旧 producer/consumer 格式和历史兼容分支的测试。清理/超时设施如仍存在真实并发和错误语义，保留对应失败边界测试，不因属于辅助代码就删除。

### 候选与安装验收

将包内容校验、安装、服务、原生配置和卸载收敛到 `test/acceptance/install` 的直接 case。共用候选读取和部署适配；tarball/symlink 与 npm launcher 保留各自启动、信号、路径和卸载覆盖，不各跑一遍全部 Hub/成果领域回归。跨平台发行仍验证全部支持平台；安装验收执行器只要求 Node 和验收代码；被测程序在干净隔离环境仅从候选取得运行资产，不能从 checkout 补载依赖或依赖 Bun/编译器。开发可用 package 命令快捷调用，跨平台 CI 直接使用 Node 入口。

原生配置 case 使用专用 HOME/CODEX_HOME/CLAUDE_CONFIG_DIR，保留其他 MCP 和原生配置。不再用本机找不到 Codex 就 skip 的方式制造完整成功；套件被选择后缺少必需工具即失败。产品当前支持的显式升级/备份/恢复不是“旧测试兼容”，其保障保留。

### 原生模型验收

移除 `expanded` 全排列作为长期入口，保留按风险选择的有限覆盖表。现有六条主链已覆盖 host/runtime、local/hub 和 shared/worktree/remote 的关键组合，初始以它们作为证据基线；不为减少数字盲删，也不再增加同义执行脚本。两种宿主的控制与重建保障继续有明确归属，能由无模型测试准确证明的分支下沉。

将 collaboration 生产者、shared/worktree/remote 三个消费者以及 execution 的重叠路径收敛为同一 case 的完整生命周期。用普通函数共享明确的运行上下文，删除跨命令的 producer/consumer 交接文件、stdout 路径抓取与多套现场所有权。验证真实 MCP 调用、成果与历史之后，必须仍在同一 case 内停机，再用安装候选启动服务并读取、取回/释放成果；比较 session 标识、轮次和原生历史摘要，证明重启后的只读操作没有新模型执行。合并的是工程交接协议，不删除产品停机/重启边界。最终由创建者统一关闭资源。只有浏览器实际需要时才启动浏览器，native preflight 不一律安装浏览器。

继续支持点选 case 定向复验；新格式只接受同候选、同测试实现、同模型选择和同环境指纹（不保存明文配置）的结果，原始失败与复验分别保留。整组通过不能由缺项或旧版本结果拼出。涉及当前任务恢复、停止、审批、断线与不重放的产品能力必须验证，不与旧工程格式兼容混为一谈。HAPI session/shutdown 专项先区分 Runweft 接线和 HAPI 自有内部行为：前者进入集成/native 对应 case，后者以独立 fork 回归为归属，未落实该覆盖前不删除唯一有效保障。

## 工程工具与发行流程

构建保留 HAPI pin、源码干净、版本与程序 hash 检查；打包保留平台集合、来源归档和摘要，候选只构建一次供下游消费。`build-hapi`、`build`、`package` 可以共享内部模块，但仍是三个有意义的操作，不合成带大量旗标的万能 CLI。npm launcher 从辅助脚本移为明确的发行资产，不删除其运行行为。

发行保留候选绑定、npm 信任校验、部分发布的明确失败及当前格式恢复。发布与恢复共用决策逻辑，日志/汇总只负责呈现，不能通过解析任意旧日志推断发布成功；未知写入先查询实际远端状态，不自动重发。现有磁盘前置检查是否简化依据候选构建实测，不随文件数裁撤；平台并行不能冒充总工作量减少。

文档、SpecTrail、Kit 与 CI 范围检查各有独立用途，保留明确入口，公共读取和判定函数就近复用。Kit 的真实安装和使用验收属于 Kit 分发流程；官网只检查页面和下载契约，不再承担 Kit 全部内部结构验收。原型保留自己的构建/浏览器验收，HAPI 内部测试留在 fork，不迁入本仓。

现存 `.dev-smoke/verify-kit-install.py` 的有效校验并入 Kit 正式验证后删除；唯一 issue 草稿保留为用户材料，未知密钥文件继续不读取、不纳入工程工具清理。两者不是新架构的执行依赖。

## CI 范围先于环境准备

增加轻量 scope job，只 checkout 必要历史并用 Node 读取变更路径，不递归拉取 HAPI、不安装产品依赖。PR 以目标分支 merge-base 比较；正常 push 使用已验证存在的 before/head；新分支首次 push 使用远端默认分支的 merge-base，避免零 SHA 导致无条件全组。不能建立可信比较基线时进入完整开发检查，绝不静默空选。

类型检查也随依赖边界拆分：默认项目检查产品、核心和普通工具，直接依赖 HAPI 实现的集成测试由集成项目配置检查；共用编译选项，不复制整套配置或通过 any 绕过类型。后继 job 根据结果分别准备 core、tools、integration、install、website、prototype、Kit；job 的切分服务依赖成本，不要求一套件一个独立 job。scope 和最终汇总始终运行；被选择的 job 失败/取消/缺结果都不能判绿，未选择明确显示为未执行。

| 变化 | 必要选择 |
| --- | --- |
| 普通文档、AGENTS、Change | 文档/流程链接检查；不安装 HAPI、宿主或浏览器 |
| prototype | 原型自身构建/验证及必要文档检查 |
| website | 官网自身逻辑/构建/浏览器验证；不跑 Runweft 模型链 |
| Kit | 结构检查、独立场景验收与分发验证；模型场景按授权执行 |
| 产品规则或组件 | 类型/核心回归及相关真实边界套件 |
| 测试用例或就近辅助、共享 support | 选择其所属套件；跨层 support 选择全部实际消费者；不会因为路径是 test 就跳过集成 |
| 构建、打包、launcher、安装逻辑、pin | 工具回归、构建与候选安装；pin 等共享边界扩大集成范围 |
| 工作流、依赖锁、范围选择或难以分类代码 | 按明确依赖选择；未知共享影响保守走完整开发检查 |

发行门禁与开发 diff 选择分开：发布必须对明确候选完成固定的平台/集成集合；真实模型按发行矩阵与已有授权运行，普通 CI 不触发付费模型。小型显式路径规则即可，不建设依赖图推断引擎；重命名按旧/新路径并集、删除按旧路径选择，scope 自身和工作流条件变更保守验证受影响门禁；用真实漏选/多选反例验证规则。

## 现场、证据与失败语义

套件入口为本次运行创建唯一隔离工作目录，把候选作为只读输入，把结果写到调用方明确指定的输出位置；本地默认使用系统临时目录，CI 使用 runner 临时目录。复用少量现有生命周期函数，去除各脚本自行创建嵌套 `.dev-smoke` 根的做法。

运行结果使用一个简单的当前格式：候选摘要、suite/case、测试实现与模型选择摘要（适用时）、开始/结束、结果、阶段、清理结果和明确的附件路径。核心测试继续使用原生测试输出，不强迫所有检查生成自定义报告。结果收集只接收当次生成的显式报告列表，删除递归扫描 `.dev-smoke` 和按固定旧路径恢复的解析器；website/release 的当前生产者与消费者同步更新。未知旧格式明确拒绝，不补写、不迁移。

入口拥有进程、现场和退出状态，成功须同时满足断言与停机完成。成功释放大目录；失败保留必要脱敏诊断，已确认停止的临时模型配置及时清除；停机未知则标为失败并保留现场，不能递归删除仍可能在使用的目录。诊断留存不等于凭据留存，摘要不收集原始配置、完整 prompt 或源码。CI 先收集结果再清理，定向复验保留第一次失败，禁止自动整组重试。

## 影响、验证与后续集成

先建立新入口及范围判定，并用现有候选对照低层/重层的覆盖；随后按领域下沉重复断言、合并安装与 native 生命周期，最后接通发行、网站和 Kit 消费者并删除旧入口。每次职责切换连同当前调用方一起提交，不长期保留两套接口或迁移适配。这里是技术集成约束；large Change 的任务计划在方案确认后建立。

验证至少包含：默认核心检查在无 HAPI 构建/无宿主/无浏览器环境仍可运行；所选验收缺依赖必须失败；文档-only/新分支/共享边界等范围反例；真实权限/不重放/文件字节/进程信号/原生历史；同候选跨平台安装及发布决策故障注入；成功/失败/超时/停机未知的现场处置；当前格式拒绝旧输入与报告缺项。测试工具自身只验证实质分支，不镜像目录和静态矩阵数量。

同候选、同保障集合比较首次运行的准备次数、HAPI/CLI/浏览器/模型启动次数、总执行时间和现场峰值/残留磁盘。已有 8 分 52 秒文档 CI 是浪费实例，不能作为全项目提速承诺；架构评审尚未证明任何性能收益，最终实现必须补实测。
