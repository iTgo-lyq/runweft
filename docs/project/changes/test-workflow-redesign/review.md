## 主 Agent 已完成的自审修订

以下是主 Agent 的方案修订，均未冒充 traex 建议：

- **D1 默认验证依赖**：核心层仍依赖 pin 的共享源码，因为产品直接导入 HAPI schema；不要求 HAPI 构建、原生宿主或浏览器。类型检查随依赖边界拆开，避免只搬目录却仍需全套环境。
- **D2 安装隔离**：Node 加验收代码负责驱动候选；被测程序不得从 checkout 补载依赖。不要求把验收代码也从空气中获得，不将开发快捷命令对 Bun 的依赖误写成候选运行依赖。
- **D3 原生重启保障**：合并 producer/consumer 的工程交接协议，但保留实际停机、安装候选重启、读取/释放成果，以及 session/轮次/历史摘要的不重放比较。
- **D4 CI 漏选边界**：测试和就近 helper 变化选择所属套件，共享 support 选择实际消费者；重命名按旧/新路径并集，删除按旧路径；范围规则与工作流条件变化需覆盖受影响门禁。
- **D5 结果复用边界**：新格式结果绑定候选、测试实现、模型选择及环境指纹；摘要不保存明文配置。核心测试使用原生输出，不建设统一报告平台。

后续有效评估需要形成“具体反例 → 采纳或不采纳的理由 → 修订 → 复核”闭环，至少经历职责取舍、方案挑战和收敛复核。实现审查和产品验收仍由后续阶段实际执行，不能由设计讨论代替。
