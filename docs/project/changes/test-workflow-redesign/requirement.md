# 重构测试与工程辅助流程

## 背景与目标

现有测试分层虽已区分核心回归、无模型集成和模型主链，执行入口、职责归属、CI 触发与现场生命周期仍混杂。用户要求另立任务，对测试、辅助脚本和整体流程架构重新梳理，并明确允许大胆删除、重构，不兼容旧数据与旧逻辑。2026-10-16 用户取消 traex 参与，要求主 Agent 自行多轮评估；不单建 packaging 目录，launcher 放现有 src，并进一步减少目录和抽象。

前一 Change 已完成一次性历史产物清理并合入 main，基线为 `94f36a25776c59a87fb3d83cf4448d28411c66ec`。本任务的目标是建立可理解、可独立执行、按风险选择且失败可定位的工程验证流程，减少重复准备与重复验证的总量；不以单纯搬目录、改命令名或增加并行度作为完成依据。

规模保留 large：涉及独立 CI 修复、HAPI 关键门禁与集成试点、原生生命周期、固定测试/安装、通用环境准备、工程路径消费等需要分阶段集成的职责交付；不因减少目录就降低实际改造规模。本轮交付收敛方案，不预填阶段确认或实施完成。

## 范围

覆盖根测试、验收脚本和辅助设施、构建与候选校验、发布/恢复工具、开发与发行工作流，以及官网/原型/Kit 验证和这些流程的接线。HAPI 内部测试按独立 fork 的所有权评估；如需改动 fork，明确实际缺口与集成步骤，不在根仓复制其实现或为改目录名升级 pin。

允许删除被替代的测试命令、旧脚本、转发入口、重复断言、陈旧 fixture/证据读取与编排逻辑；统一更新当前调用方，旧名称不留 alias，旧格式不加兼容解析、补写或自动迁移。现有脚本数量、命名、分组、模型 case 数量和旧计划均不是保留约束。

“旧数据”在本任务中指测试夹具、验收现场、测试证据及工程流程记录。产品用户数据、原生认证配置和已发布不可变 npm 包不作为自动删除对象；现有产品恢复、权限隔离和发布不可重复写入等保障需要在新设计中有明确覆盖。无需为既有测试记录继续可执行而保留旧实现。

本轮进行源码调查、自审和方案收敛，不触发 npm 发布、官网部署或新的产品模型矩阵；不再调用 iclaude/traex，不修改全局配置或凭据。

## 目标行为

### MODIFIED 按职责选择验证

日常规则/组件验证、真实 HAPI 接线、安装冒烟、UI 验证、模型专项和发行矩阵各有明确的依赖、输入、保障边界与触发条件。开发者能运行与改动相称的最小检查，不因验证一个规则强制启动无关模型、浏览器或完整服务。

明确区分“仓库维护固定断言的测试”和“为当前需求提供可操作环境的前置命令”。按需运行、选择 case 的原生验收仍是固定测试；灵活验收由 Agent/人工决定操作与判定，环境启动成功不能计作验收通过。方案须按编码、集成、需求验收、候选安装、真实模型、官网/原型、CI 与发行列出入口及前后关系。

需要真实 HTTP、数据库或子进程才能发现的故障继续使用相应层级；不能为追求“纯单元”而引入大量失真的 mock。重型场景只承担低层无法替代的跨边界保障，异常组合放到能够准确证明其行为的最低成本层。

### MODIFIED 简化流程与现场所有权

测试和工程辅助代码分离清晰，每个入口说明作用与结果。候选、现场、进程、缓存和证据的创建者与消费者明确；必要的失败留存/定向验收保持直观，不构建通用调度、迁移或资源池框架。

测试只按成本分 core/integration/acceptance；领域使用文件名区分，辅助就近放置。工程脚本保持平铺及现有 scripts/tests；launcher 归 src，不预建领域子目录、全局 support 层或多套 TypeScript 项目。

提供一个薄的 dev:env 前置入口，复用现有普通函数准备隔离 Hub/可选 Runner 或候选安装，以新建目录为明确句柄，提供 start/stop，按产品状态核对资源；不承诺终端退出能回收后台服务，不猜测停止外部任务；不运行固定业务用例、不自动调用模型、不形成新的场景框架。固定测试直接复用准备函数并自行清理，不以“先跑某个测试并保留现场”作为灵活验收的前提。

CI 先确定验证范围再准备所需依赖，文档、原型、官网、Skill、产品代码和发行变更分别选择当前必需的门禁；新分支有可证明的比较基线，无关变化不因首次 push 自动进入全量长链。对无法确定影响的代码变更明确使用保守路径，不静默漏验。

### MODIFIED 发行和原生验收

构建、包内容、安装、服务、发布、官网和 Kit 各自负责真实边界，避免在不同包装形式上重复全部领域回归。原生模型只承担真实宿主调用、完成/中断/审批/历史等不可由无模型检查替代的事实；具体组合与生产/消费协议允许重写。

发行继续绑定明确的不可变候选、摘要和平台，失败或未知外部写入不能通过重新构建/重发来伪装成功。删除旧测试交接格式，但保留当前发布日志协议及恢复能力；不为清理目录而引入信封格式迁移。原生证据按冻结源码与构建输入核对，公开重建包的安装/集成证据单列，不假定两次构建摘要相同。

### MODIFIED 通用代码与按需实验

仓库沉淀产品稳定契约的回归检查，以及确有复用价值的构建、验证和发行工具。一次性排查或冒烟可以按实际需要使用临时脚本，但不把现场操作固化为长期入口，不为此增加 AGENTS、Skill 或其他提示词提醒。也不以“通用”为由构建测试 DSL、插件框架、通用资源调度或自动清理平台。

### REMOVED 旧工程入口与兼容负担

被替代命令、过时脚本/格式、重复设施和无独立故障保障的断言随当前调用方一并删除。只读历史文档可留作事实，不提供恢复旧执行逻辑的兼容实现。

## 验收标准

1. 提供现有测试/脚本到新职责的去向清单；每项保留、合并、下沉或删除均有独立保障或当前消费者依据，无未归类的可执行遗留入口。
2. 默认开发检查与重型集成、浏览器、真实模型有可验证的依赖边界；缺少不需要的外部程序不妨碍低成本层运行，也不能把必须运行的检查静默跳过。
3. 对权限隔离、不重放、文件/Git 字节与成果、进程退出/信号、原生调用/历史和发布候选一致性给出明确覆盖；删除/下沉场景提供替代证据或说明其无独立保障。
4. 文档-only、新分支、原型-only、官网/Kit-only、领域代码与发行变更的 CI 选择有可重现反例测试；实际工作流按所选范围准备依赖。
5. 成功、失败、超时及停机未知的现场处置可辨别；不泄漏凭据，不误删用户数据，不丢必要诊断；验收记录只消费明确的当次或明确指定结果；发布恢复沿用现行日志协议。
6. 同候选、同范围下记录首次结果、失败归因、实际执行总量、耗时和磁盘占用；不预设无证据的提速比例，不用少跑必需覆盖或单纯并行宣称总成本降低。
7. 当前调用方全部切换，新旧入口不双轨运行；旧测试命令、别名、fixture 交接及兼容分支被移除；已淘汰格式拒绝而不迁移，未改变的现行发布协议继续使用。
8. 设计经过主 Agent 多轮自审及用户组织的 Claude 复评，分别审查职责与去向、覆盖损失反例、最终流程与复杂度；记录具体证据、取舍和修订，不冒充独立外部评审。最终方案附完整技术设计和简洁组织结构全貌。后续实现另做审查，不以设计评估代替代码验收。
9. 每个入口标明执行环节、固定断言或环境准备性质、依赖、结果及生命周期。固定集成/安装/native 无需预先启动 dev:env；dev:env 可单独提供环境，ready/stop 成功不生成业务通过结论；准备失败按明确归属回收，stop 遇到活跃或未知会话保留现场。
