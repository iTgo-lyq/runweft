# 官网 Cloudflare Pages 实施计划

> 来源：./requirement.md
> 技术方案：./technical.md
> 状态：执行中
> 执行模式：逐任务提交

## 交付目标

独立官网 CI 可检查并上传到 Cloudflare Pages；生产/预览分流、npm 安装版本和部署结果可自动核对。

## 任务

### T1 实现发布检查与 Pages 工作流

- 状态：已完成
- 交付：独立构建/检查/上传工作流，清晰的凭证缺失提示，Pages 项目与在线版本验证，聚焦失败路径测试。
- 依赖：Plan 一次只读 iclaude 评审后主 agent 独立判断。
- 验收：不触发 npm 发布，不上传未知事件/分支或不可安装版本，secret 不落入产物；本地检查通过。
- 验证：Node 聚焦测试、工作流 YAML 与权限/脚本检查、typecheck、根测试、官网构建及公共 npm 实测。

### T2 验证托管 runner 检查

- 状态：待开始
- 交付：推送当前分支触发托管 runner，核对公共 npm 检查；缺凭证时保存明确未部署的跳过证据。
- 依赖：T1。
- 验收：当前分支托管检查完成，实际上传与凭证跳过分别记录。
- 验证：托管 CI 与脱敏检查/准备产物。

### T3 接通账户并验证真实预览

- 状态：待开始
- 交付：凭证就绪后创建/核对 Pages 项目，验证唯一预览 URL。
- 依赖：T2、用户 GitHub Secrets 就绪。
- 验收：实际环境为 preview、全部静态文件/版本/MIME 一致；不自动合入 main。
- 验证：托管 CI 和 Pages HTTP 脱敏证据。

### T4 同步规格与归档

- 状态：待开始
- 交付：官网/开发/项目入口说明、实际已验证 Specs、验收记录和完整 Change 归档。
- 依赖：T3。
- 验收：明确生产合码前提和实际部署范围；未完成外部条件保留缺口。
- 验证：validate-change、文档链接与 diff；独立提交并推送。

## 风险与恢复

Cloudflare 上传失败先查实际部署，不盲目重发；已有项目不自动改生产分支。npm 尚未发布时重跑 Pages 检查，不上传占位包。main 尚无代码，工作流在当前分支先验证预览；不通过修改默认分支或伪造 branch 开启生产。

## 关键决策与风险

缺 Secrets 不阻塞 T1/T2，阻塞 T3；在其就绪前不归档。main、手动和 PR 的真实触发不在本轮证据内。保留 Node 聚焦测试与网站 job 内检查，不为网站接入重建原生 CLI。

## 整体验证

本地测试/构建/公共 npm、托管 runner 和真实 Pages HTTP 分别验收；生产部署需后续 main 合码，本轮不冒充已验证。
