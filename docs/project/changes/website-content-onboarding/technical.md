## 依据与方案

已读取三页模板、site.js、构建器、使用说明和 website/product、website/guide Specs。当前官网为三个 HTML 模板及共享 CSS/JS；GitHub API 确认产品仓库为私有，当前首页/页脚的源码链接不能作为公开访客入口，改为公开 npm 包链接；首页 Agent 接入与 npm 命令并存，指南五步包含大量前置概念及工程边界；命令参考从已发布使用说明转义生成。

1. 保留现有样式类、布局、页面路径、核心锚点和 npm 命令占位符。首页文案围绕委派任务、任务结果、接入步骤展开；远端能力作为完成本机首次任务后的扩展。
2. 首页和指南采用相同的接入对话，终点为装好 MCP 并提醒用户重开客户端，首项委派在重开后单独发送；将 Skill 解释为 Agent 的接入说明，MCP 解释为当前工具的委派入口，Hub 解释为管理任务与执行机器的服务。用一个本机共享目录只读评审作为首个任务，避免新手立即承担 Git 基线和跨机设置。
3. 指南先给出一段接入对话，随后按用户实际要确认的动作解释五步；工程命令沿用当前 CLI，收在 details 中。首个任务提供复制入口与报告完成标志。参考页保留使用说明原文，增加按需查阅指引。
4. 仅调整网站模板、示意交互文字及必要的验证脚本。示意图本机评审显示共享目录，功能实现显示独立目录，远端统一为独立目录。package.json、docs/usage.md、Skill、产品源码和 HAPI 固定输入保持 1.1.3 已发布版本，网站内容单独构建。
5. 复用现有 Playwright 验证基础，检查所有视口、链接、复制、选择、折叠、无 JS 和截图；补充用户实际从首页复制接入提示、重开指引到复制首项任务的路径检查；提供显式 browser-only 验证模式并在证据中注明跳过 npm 安装，不写逐字镜像文案测试。安装命令未改动时核对生成值，已发布二进制无需重测完整四平台发行。

## 协作与交付

iclaude 在当前仓库评审已形成的 Plan，并给出具体段落和组织建议；只提供公开产品材料和本次文档，不传递凭据。主 Agent 整合后实施、核对产品事实和浏览器结果。当前请求覆盖官网内容修改、提交和自动验收；结合此前官网发布授权完成既有 main/Pages 发布流程，核对唯一部署 URL 与正式域名。

网站构建、15 项发布检查、专用 Playwright 内容路径及现有交互检查；320/390/768/1024/1440 宽度溢出与截图；源码包输入与 v1.1.3 一致；部署静态文件摘要和正式域名的内容/链接。自动验收不修改真实模型、MCP 或用户配置。
