# 公共 Git 工作区与本地独立执行设计

> 状态：草稿
> 更新：2026-09-29
> 来源：[Requirement](requirement.md)、[拆分方案](../../delivery-structure.md)。本文件集中原远端方案中的公共 Git 规则，不表示正式 Technical 已确认。

## 所有权与调用边界

Runweft 组合 HAPI 现有 Git、目录和执行能力；执行侧缺口在 HAPI 原代码内补齐。不建立另一个 worktree daemon 或 runtime 协议。委派调度提供启动/收尾条件，本 Change 返回对应环境和成果证据。

公共操作接收已经可访问的 Git 仓库、固定 commit、仓库内相对 cwd、环境归属及已解析输入位置。它不负责从 Git remote 或附件中心下载对象；本地可直接使用主仓库，远端 Change 先提供缓存仓库再调用同一规则。

## 准备与启动

1. 从真实主仓库解析指定 ref 到确定 SHA；拒绝无 commit、歧义 ref 或不在基线中的工作子目录。主工作区未提交、未跟踪文件不自动迁入。
2. 绑定 repository/environment/preparation 身份和基线，在目标仓库创建独立分支与 worktree；已有路径只能在归属及准备版本一致时复用，不在未知 checkout 上 reset/clean。
3. Git 目录修改串行保护，不锁住不同 worktree 中的 agent 开发。完成 Git、cwd、已提供输入和上下文检查，形成准备证据；LFS/子模块等必需内容不可用时拒绝就绪，不能宣称完整环境。
4. HAPI 实际启动处重新核对归属、版本、HEAD 和必要输入；准备失效不得启动，也不再次用默认 HEAD 创建 worktree。项目依赖交由 agent 安装。

公共准备接收相同结构的本地文件事实；附件或 Git 对象如何到达由调用方负责，避免本地模式依赖跨机传输。

## 本轮固定成果

HAPI 确认执行结束并关闭本子执行后，先确认本任务受控工具已停止写入。无法确认则保留工作区并阻止封存；不能扫描或终止无关进程来制造空闲。

- 核对环境归属、当前 HEAD 和初始基线的祖先关系；无关历史、未解决冲突或仓库绑定变化时保留现场。
- 保留 agent 已有提交。按已确认的自动 checkpoint 策略，只在本 subagent 独立 worktree 内提交遗留 Git 改动，包含文本、二进制、删除和非 ignored 新文件；不在主共享目录提交，不制造空提交。
- 临时上下文、输入和初始化元数据原则上置于源码树外。无法区分辅助文件与成果时停止自动提交，不把注入内容一并交付。
- checkpoint 身份、hook 与签名策略须在正式方案中固定；不修改用户全局 Git 配置，不冒充用户，不静默跳过已有 hook/签名要求。失败保留现场，不能报告未包含改动的 SHA。
- 保存初始 base、本轮开始 HEAD、成果 HEAD 和不可变成果引用后，才向委派报告本轮代码已固定。执行失败或中断也可形成部分成果，但不改变原执行结论。

本地成果引用与主工作区共享对象库，主 agent 可查看 diff 和合入；远端结果 Change 消费同一固定引用，另负责打包、传输及可取回验证。上传可以在代码固定后继续，但不能在未固定时放行下一轮写入。

## 续接与回收

同一 delegation 保留 worktree、任务分支及已安装依赖，下一轮由 HAPI 优先 resume 原生 session；明确缺失时沿委派规则重建上下文。主仓库的新提交不自动同步，不偷偷 reset/rebase 活跃分支。

显式结束协作后，公共回收检查环境归属、活跃/未知执行、未封存改动和成果保留条件；远端提供方还须确认上传及对象保留依赖。代码取回或合入本身不触发删目录。具体保留时限与配额未因本次拆分而获得确认。

本 Change 的真实验收在本地独立 worktree 完成；纯 Git 失败场景用临时仓库验证，不能以这些实验替代两种 runtime 的实际执行与续接。
