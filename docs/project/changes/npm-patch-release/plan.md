# 1.1.1 正式补丁发布计划

> 来源：./requirement.md
> 技术方案：./technical.md
> 状态：执行中
> 执行模式：逐任务提交

## 交付目标

真实走通 v1.1.1 → 四平台候选/安装 → OIDC 五包上传 → 匿名 npm 安装 → main/正式官网更新。

## 决策与风险

沿用当前 main 和已配置工作流；仅先推送 tag，公共 npm 验收后再推送 main。冻结候选与 tag 不变，未知上传先核查回执；真实新版本上传能力由此次结果确认。

## 任务

### T1 准备一致的 1.1.1 版本输入

- 状态：已完成
- 交付：根版本、常规安装说明与 README 安装目标一致，当前 npm Skill 入包；完成一次 iclaude Plan 评审及独立判断。
- 依赖：无
- 验收：历史离线说明不冒充新整包，HAPI/工作流不变，提交后源码干净。
- 验证：类型检查、根 ./test、轻量 build；使用说明在离线附录前无 1.1.0、安装/对话为 1.1.1，静态八文件无 1.1.0；历史附录保持 1.1.0 且标明原整包；git diff。

### T2 正式可信发布并匿名验收

- 状态：待开始
- 交付：不可变 v1.1.1 tag、成功原 run、同候选五个公共 npm 包及脱敏回执。
- 依赖：T1
- 验收：四平台 CI 安装通过、五包 OIDC/真实上传/公开 SHA-512/latest 与候选一致；专用 Linux x64 npm 安装和当前 Skill 校验通过。
- 验证：确认原 run 为 push/v1.1.1 且 SHA 匹配版本提交，产物是成功 publication 而非 preflight；读取原候选/回执，匿名 registry 查询与逐包下载摘要，既有 Playwright DOM 安装验收；不修改旧发行目录。

### T3 推送 main 并部署生产官网

- 状态：待开始
- 交付：main 版本提交与正式官网安装目标为 1.1.1。
- 依赖：T2
- 验收：main 推送的 CLI/Pages CI 通过，production 回执、唯一 URL/正式域名八文件与三页浏览器检查通过。
- 验证：推送前 packageInputs 与 v1.1.1 无差异；原工作流结果、产物与回执、公开 HTTP 和专用 Playwright；后续文档推送完成前不重跑过时 main。

### T4 同步发行事实并归档

- 状态：待开始
- 交付：当前安装/Skill/发行/官网 Specs、文档、可追溯验收记录及完整归档。
- 依赖：T3
- 验收：实际公开/部署结果、来源和实测限制清楚；Change 结构/链接通过，main 工作区干净且已推送。
- 验证：需求对应表、脱敏 verification.json、Change 校验、文档链接和 git diff 检查；最终推送前 packageInputs 与 v1.1.1 无差异；如官网说明触发部署，等待其结果。

## 整体验证

每项验收映射到实际 CI、公开包或浏览器证据。发布和部署全部确认后自动验收、同步 Specs 并归档；不以预演代替上传，也不继承旧候选模型证据。
