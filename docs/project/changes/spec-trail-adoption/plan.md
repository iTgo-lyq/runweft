# SpecTrail 接入计划

依据：[需求](requirement.md)、[技术方案](technical.md)。按编号串行交付，每项包含对应验证和文档。

## T1 工作流替换与历史状态迁移

交付完整 SpecTrail、共享 hook/CI 校验、39 个归档和一个暂停 Change 的 JSON，以及历史任务编号/来源记录。验收：全部契约有效、正文无重复流程状态、历史内容和未测范围保留，临时仓库实际 hook 成败通过。检查上游目录一致性和迁移前后内容差异。

## T2 独立 Hub 交互原型

交付原型包、设计约定、页面主体和内存场景、当前清单与自包含构建。验收：身份/空间、任务筛选详情、资源管理、Agent、仓库、本人选择与成员主要交互可用，三设备不透明 iframe 验证通过，不访问真实服务或持久存储。

## T3 固定版本发布与工作台引用

交付 R2 适配器、截图、发布说明和固定引用。验收：适配器正常/冲突/失败测试通过，真实上传和匿名摘要检查通过，SpecTrail 静态与浏览器验证通过，引用可追溯到干净源码提交。

## T4 整体验收与规划分支整理

独立评审全部差异，完成基础检查和验收对应；在专属分支保留暂停 Change，将交付分支的过程关闭、同步开发规范并归档，推送分支及原型保留标签。验收：交付分支不含未归档 Change，暂停内容在专属分支可恢复，远端分支/标签核实，具体外部验证限制如实记录。
