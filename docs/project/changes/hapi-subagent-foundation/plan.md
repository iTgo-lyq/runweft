# HAPI 执行契约实施计划

> 来源：./requirement.md
> 技术方案：./technical.md
> 状态：执行中
> 执行模式：逐任务提交
> 确认方式：按用户授权，当前工作区 iclaude 一次评审，主 agent 独立复核后执行。

## 交付目标

后续委派能通过同一套 Runweft 调用，启动并重查 HAPI 执行，关联输入和真实结果，定向中断，停止后原生续接。默认权限和原生配置继承保持现有行为。

## 关键决策与风险

- HAPI 已有基础链路已实测；新增工作限制为已证实缺口，不重写 runtime。
- Claude 消费回执早于原生处理；必须保留未知并消除模糊失败自动重发，不能只补 happy path 的终态字段。
- HAPI fork 与 Runweft 分别提交，后者固定 fork revision；临时探测不成为补丁流水线。
- 共享进程关闭与中断竞态必须有可重复证据，不能把整个服务停止算作单执行停止。

## 任务

### T1 可重查的启动与调用入口

- 状态：进行中
- 交付：HAPI requestId 启动回执与查询、兼容声明，Runweft 类型化启动/查询和错误关联。
- 依赖：统一 CLI 已验收
- 验收：同一 requestId 不会创建两次；参数冲突明确拒绝；丢失回复后可查原 sessionId，未知不会换 ID 重发；显式同 ID 重查/重调保持去重，确认停止后才允许业务层决定新建。
- 验证：HAPI 回执存储及路由测试、并发/丢回执测试、真实 Runner 启动关联、Runweft 类型检查；两仓库独立提交。

### T2 两种 runtime 的原生事实与定向中断

- 状态：待开始
- 交付：现有 HAPI 消息中的输入/结果观察、执行侧目标校验、Claude 模糊异常保留未知；Runweft 投递、查询和中断封装。
- 依赖：T1
- 验收：原生结果对应指定 localId；ready 不冒充成功；侧链及 Claude 自主根轮次不污染根结果；迟到中断不会命中下一轮；模糊退出不会重复执行输入。
- 验证：协议与转换测试、可控 SDK 异常复现、原生中断竞态、真实 Codex/Claude 完成和失败事实；执行 HAPI 共享变更规定的检查。

### T3 关闭、续接与运行能力验证

- 状态：待开始
- 交付：复用 archive/resume 与审批的完整调用封装、配置继承和身份依据、能力不足/认证/离线/原生缺失诊断；先复现再补齐机器到 Hub 的明确缺失码。
- 依赖：T2
- 验收：结束本轮后关闭该执行；共享 runtime 兄弟会话仍可用；原 session 可续接并返回实际身份；仅确认缺失可支持后续历史重建。
- 验证：两种 runtime 的真实两轮任务、原生审批、共享 Codex 会话关闭；专用项目配置继承与 HAPI 身份检查，不修改用户全局配置。

### T4 配套构建与整体验收

- 状态：待开始
- 交付：固定 HAPI revision 的完整执行验证脚本、能力说明、需求逐项证据。
- 依赖：T3
- 验收：所有本 Change 标准闭环，没有未实现的核心执行语义；远端实测缺口独立记录。
- 验证：编译后的 Runweft/HAPI 组合真实执行测试、原有服务回归、文档和 Change 校验；通过后单独同步 Specs 并归档。

## 整体验证

本地专用环境覆盖两 runtime 的启动、投递、原生结果、审批、中断、关闭和续接；故障注入证明未知不会触发重复输入或启动。宿主 MCP、工作区准备、附件和真实远端组合由所属 Change 验收，不把这些业务实现放进本 Change。
