# 全局机器与 Runtime 注册实施计划

> 来源：[Requirement](requirement.md)
> 技术方案：[Technical](technical.md)
> 状态：执行中
> 执行模式：逐任务提交
> 确认方式：按用户授权，当前工作区 iclaude 一次评审，主 agent 独立复核后执行。

## 交付目标

无需 agent 定义即可通过一个 CLI 分别登记机器和 Codex/Claude runtime，查询实际可用性并取得稳定执行引用。local/hub 共用持久资源服务，离线、缺失工具和未验证认证不会混为成功。

## 关键决策与风险

- 复用 HAPI machineId、心跳和 availability；只增加现有查询的离线列表及原生版本详情，不修改 launcher。
- runtime ID 与 machineId/flavor 固定；取消后恢复复用 ID，名称变化不改写执行目标。
- 资源以中心 namespace 为作用域，服务端转交调用者 JWT，不借默认身份扩大访问。
- 取消登记保留历史关联、禁止新解析，明确受影响引用，不停止原生执行或扫描/修改项目定义。
- 版本探测异步且有时限，失败单独报告；Codex 详情查询实际 shared launcher 的命令，不将旧 preflight override 当实际执行对象。当前不验证模型认证。
- local 的本机限制位于客户端；中心解析按 namespace，不以中心 config.mode 拒绝远端机器。register 不隐式启动服务，列表默认隐藏未登记历史并展示不可用于新委派的原因。

## 任务

### T1 暴露 HAPI 现有机器库存与原生工具详情

- 状态：已完成
- 交付：可包含离线机器的已有 API、原 availability 链路的可选详情及能力声明；更新契约文档并固定 HAPI revision。
- 依赖：已归档执行基础
- 验收：namespace 正确，默认在线列表和轻量查询不变；实际 launcher 命令对应版本，并区分旧 preflight 与真实命令；失败和超时可辨认，旧 Runner 明确拒绝，不启动模型。
- 验证：聚焦 schema/RPC/路由/命令解析回归、HAPI 规定的全量检查；专用真实 Runner 的版本查询。HAPI 与 Runweft 分别提交。

### T2 双模式全局资源登记与目标解析

- 状态：已完成
- 交付：中心 SQLite 资源表、认证后的机器/runtime API、不可改绑的 ID 与下游目标解析调用层。
- 依赖：T1
- 验收：登记幂等且并发唯一，注销/恢复稳定，namespace 隔离，机器/runtime 分开；下线和失效引用明确失败，不改绑原执行位置。
- 验证：真实 SQLite 与接口组合测试、故障分支及连接隔离测试、类型检查；不把模型模拟当真实执行验收。

### T3 统一资源 CLI 与使用说明

- 状态：已完成
- 交付：机器/runtime 分别 register/list/show/rename/unregister，runtime discover/check；本机默认、显式目标、默认/--all 列表、可操作诊断及集中数据说明。
- 依赖：T2
- 验收：空环境有明确下一步；当前连接本机可登记，发现不隐式注册，JSON 与人类输出表达同一事实；任意项目 cwd 共用全局注册，不生成项目级资源文件。
- 验证：专用 CLI/API 环境覆盖重复调用、名称变化、注销后恢复、无效参数及错误提示；常规测试和类型检查。

### T4 配套注册整体验收

- 状态：待开始
- 交付：可重复的编译版资源验收脚本、local/hub 持久性与原生探测证据及用户说明。
- 依赖：T3
- 验收：无 agent 定义/任务即可完整登记和查询；服务重启、机器离线与恢复、CLI 缺失/配置无效均正确；授权边界与本机路由正确，中心自身 local 配置不误拒其他 Runner；原有安装/MCP 能力不退化。
- 验证：配套构建、专用本地中心与 Hub 客户端/Runner、真实版本和故障注入、相关服务/安装回归及 Requirement 映射。通过后自主验收、同步 Specs、独立归档。

## 整体验证

机器在线与原生工具发现分别取证；不声称认证或任务执行已验证。当前新增查询不修改执行适配；原有真实执行证据在实现未变时复用。真实跨机器链路单独留给远端阶段，不能用本机双连接替代。
