# Runweft Kit 统一命名

## 背景与目标

用户已确定公开分发仓库和仓库内的 Skill 都命名为 `runweft-kit`，要求同步调整相关链接、CI 和使用入口，清除当前交付中的旧身份并重新验收。此前直接合入 main、验收自动同步的交付选择继续适用于本次改名。

## 范围与行为变化

- MODIFIED installation：Skill 的 name、宿主显示名、调用提示、源码目录、宿主安装目录及新构建的包内目录统一为 `runweft-kit` / Runweft Kit。Runweft 程序和 MCP 身份保持原有产品名称。
- MODIFIED release：保留公开 GitHub 仓库身份及历史，重命名为 `iTgo-lyq/runweft-kit`；公开树仅保留新 Skill 目录。同步 workflow、脚本和专用写凭据使用新名称。
- MODIFIED website：安装指引从公开 Kit 仓库获取当前 Skill，避免依赖已经发布的 npm 包中的历史 Skill。既有发行包和 Git 历史属于不可变交付，本次不重写历史或另发程序版本；后续程序构建携带新名称。

## 方案要点

本次为 small：主要是已有分发链路的名称和引用替换，继续使用现有同步、打包和卸载流程。先在公开仓库的临时候选分支验收新名称安装，主分支 CI 用新凭据写入新的 Skill 目录，再移除公开旧目录、更新 README 并删除临时候选分支。更新当前文档和 Specs；归档保留历史事实。旧凭据在新链路验证成功后移除。

宿主安装先核对已有内容；发现同功能的其他名称副本时，备份用户修改到扫描范围之外，经安装/替换授权后只保留选定的新入口。验收使用隔离目录，不修改开发者全局配置。

## 验收标准

- GitHub 原仓库重命名成功，新地址公开可读，当前公开树只发现 `runweft-kit`。
- 源码、元数据、公开 README、安装命令、CI、打包与卸载识别一致；当前维护内容无旧仓库名、旧产品 Skill 名及路径。
- 结构、同步真实 Git 夹具、打包内容和安装/卸载相关测试通过；独立 Agent 场景验收覆盖名称发现与安装/维护指引。
- 隔离安装只得到新名称 Skill；主分支自动同步真实提交成功，公开 Skill 目录与主分支内容完全相同，再次触发内容一致时不创建重复提交。
- 常规 CI 及官网浏览器验收通过。外部搜索收录以实际查询为准，不把可安装等同于已收录。
