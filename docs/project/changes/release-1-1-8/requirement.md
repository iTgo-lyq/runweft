# Runweft 1.1.8 发布准备

## 背景与目标

用户已授权将发布证据留存调整直接合入 main，并触发一次正式版本发布验证。五包 latest/beta 当前均为 1.1.7，1.1.8 五包均未公开；使用新的补丁版本承载当前 main 的已完成改动。

## 范围与行为变化

MODIFIED：根版本与随包使用说明、安装命令统一为 1.1.8，使用说明的验证来源指向对应 GitHub Actions 运行。源码准备完成并归档合入后，以不可变 v1.1.8 tag 触发现有完整发布流程。

本 Change 仅记录发布前的版本准备及检查；发布后的 npm、官网结果和耗时由 Actions 日志与 Summary 留存，不再产生仓库内的版本报告。`.dev-smoke` 的依赖梳理由其他会话处理。

## 方案要点

复用现有构建、上传 beta、四平台公共安装/卸载、集成验收、latest 晋级和官网并行流程。固定 HAPI 与依赖不变；失败时按实际证据定向恢复，未知上传结果先调查。

## 验收标准

- 版本与安装提示一致，相关本地检查通过，源码干净且可冻结为 v1.1.8。
- 全部准备内容归档并合入 main 后，由正式 tag 执行发布门禁。
- 会话跟进实际发布结果，核对五包及官网版本、CI 汇总可查询，并确认发布后没有自动生成版本报告或文档提交；实际结果以 GitHub 运行记录为准。
