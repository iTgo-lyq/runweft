# Hub 空间、身份与集中 Agent 配置

> 状态：已确认
> 规模：大型
> 更新：2026-09-30
> 当前范围：总体产品契约与最终集成；用户已同意开始，领域实现按 [交付拆分](delivery.md) 顺序进行。开发使用专用数据，不修改运行中的 Hub 或用户配置。

## Review 导读

- **目标：** 用户通过 Agent 与 Skill 完成安装、连接、配置和维护，通过 Web 查看机器、runtime、Agent、仓库与任务；委派必须连接 Hub，配置及授权由 Hub 管理。
- **已明确：** 项目配置关联 Git 仓库，不再要求在仓库内保存 Runweft 配置；不同用户可维护自己的 Agent；参考 Multica 的空间与资源可见性，身份采用用户自行保存的独立 token。
- **交付方式：** 本 Change 保留整体契约并承担最终组合验收；身份、执行授权、资源、配置、委派、Web/Skill 分属独立 Change，不在本目录重复实现。用户授权主 agent 完成工程决策、每个 Plan 用 iclaude 评审、逐任务提交及本地自动验收。
- **设计入口：** [产品模型与用户流程](product-design.md)、[身份与授权](access-design.md)、[现状和 Multica 调查](research.md)。设计建议不等于已经实现或全部得到确认。
- **本轮确认：** “公开”限所在空间成员；私有 Agent 仅所有者可修改/分享，非所有者的空间管理员可禁用；不建设登录/注册服务，所有可访问 Hub 的人都可领取自己的身份 token 并自行保存。

## 已确认方向

1. CLI 面向 Agent，安装、启动、资源登记、配置和诊断由 Skill 引导 Agent 完成；用户的主要操作入口是对话和 Web。
2. subagent 必须经过已连接的 Hub；Hub 是机器/runtime 登记、Agent 定义与个人配置的权威来源。
3. 项目级设置由 Hub 关联 Git 仓库，用户无需提交 `.runweft/agents` 等配置文件。
4. 机器、runtime、Agent 是独立对象；配置归属、可见性和可使用范围必须明确。
5. 用独立身份 token 区分用户并保留空间模型，不要求邮箱、密码或外部登录；其他用户不能因能够发现或使用某资源而取得修改权。
6. 执行基础继续复用 HAPI，保留既有本地/远端工作区、原生执行、会话与成果回收能力；本次调查须明确 HAPI 在多用户授权上的实际缺口。
7. runtime/Agent 的“公开”仅向所在空间成员开放，不向所有 Hub 访客公开。
8. 私有 Agent 的编辑和分享仅由所有者决定；非所有者的空间管理员可禁用，不能改写配置或扩大共享。

## 背景与范围

当前 namespace 只有数据分区语义：没有空间成员与角色，资源没有用户所有权，基础 token 可以选择 namespace。Agent 的全局/项目定义及个人绑定仍在客户端文件和数据库中，Web 主要展示任务。因此集中配置与多用户权限需要同时设计，不能只移动 YAML 或增加列表页面。

本 Change 覆盖身份 token、空间、资源归属与共享、仓库关联、集中 Agent 配置、Web 资源视图、Agent 使用 Skill、必连 Hub 的交互和旧配置迁移。当前先完成需求与产品设计，后续实现应按独立结果拆分，不把所有模块作为一个巨大开发任务推进。

不扩大到集中托管其他工程 skill/MCP、接入新原生 runtime、业务自动编排、主宿主关闭后恢复、自动合码或跨 Hub 联邦。仍只支持 Codex 与 Claude Code；工程 skill 由真实 cwd 的原生加载机制继承。

## 行为变化

### ADDED

#### `identity/tokens`：无注册的持久身份

任何能访问 Hub 的人都可主动领取一个独立身份 token，无需注册或外部身份验证。Hub 用稳定用户 ID 记录所有权，token 是使用该身份的凭据；Web、CLI 和 MCP 使用同一身份。用户自行保存 token，之后通过保存的 token 使用原身份，不要求打开终端获取凭据，也不分发共用 HAPI 根 token。

创建身份不授予已有空间的成员资格。没有留存副本的 token 丢失后，不提供邮箱等找回路径；重新领取产生不同身份，不能自动认领旧配置。具体领取、保存与失效处理见 [身份设计](access-design.md#身份-token-的使用流程)。

#### `spaces/membership`：空间与成员

一个 Hub 可包含多个空间，一个用户可加入多个空间。空间具有所有者、管理员、成员，成员关系在服务端校验。空间切换不迁移机器、配置、仓库和任务；空间不等于 Git 仓库、磁盘工作区或 HAPI namespace。

#### `resources/access`：所有权与共享

机器登记、runtime 注册、Agent 配置保持独立。runtime 与 Agent 默认私有，“公开”只向所在空间成员开放，共享不自动转让编辑权或机器控制权。私有 Agent 仅所有者可修改/分享，非所有者的空间管理员可禁用但不能改写或扩大共享。引用他人 runtime、使用共享 Agent、续接任务和取回成果均校验当前身份；不能通过已知 ID 或另一个 API 绕过。

#### `repositories/identity`：仓库关联

Hub 用稳定仓库身份关联项目设置，实际 checkout 路径只描述某台机器上的工作现场。相同仓库的多个 clone/worktree 可关联同一仓库记录，fork 与不同托管服务不误合并。检测到 Git remote 不等于取得空间、配置或代码访问权限。

#### `interaction/agent-operation`：面向 Agent 的完整管理流程

提供产品 Skill，让主 Agent 完成安装、Hub 连接、身份凭据接入、资源登记、Agent 配置、诊断与升级，返回可直接打开的 Web 入口。用户可在 Web 领取或导入 token 并保存副本；CLI 的结构化结果供 Agent 使用，凭据不进入普通对话或诊断日志。

### MODIFIED

#### `deployment`、`delegation/interface`：必须连接 Hub

- 当前：local/hub 双模式；本地启动路径可自动管理本机服务，Agent 配置从本机读取。
- 目标：委派前必须有明确 Hub、有效身份凭据及空间成员资格，定义从 Hub 解析。未连接或无权访问时给出可由 Skill 处理的原因，不静默切换另一 Hub 或本地定义继续派生。本地执行与远端执行是目标位置差异，不再是两套配置权威。
- 当前设计建议：仍可在 localhost 自托管一个 Hub，但必须显式连接，使用相同身份、空间和授权规则；是否自托管与是否连接 Hub 是两件事。

#### `agents/definition`、`agents/scope`：集中配置与个人选择

- 当前：全局/项目 YAML 是定义来源，个人 runtime 绑定保存在本机 client.sqlite。
- 目标：定义、仓库适用范围、个人偏好及绑定都由 Hub 保存。不同用户在同一仓库可以有自己的 Agent 和选择，不修改他人的定义。配置作用域与访问范围独立：跨仓库配置也可私有，仓库配置也可向空间共享。
- 已接受任务保存当轮配置版本、发起身份与权限上下文。后续编辑不改写历史；新轮次使用可解释的配置版本并重新鉴权。

#### `dashboard/subagents`：Web 资源与任务入口

- 当前：任务总览、HAPI 会话与机器链接；无完整 runtime/Agent 配置视图。
- 目标：Web 按当前用户和空间展示机器、runtime、Agent、Git 仓库、个人/共享配置及任务成果，解释所属人、来源、共享范围和不可用原因。用户无需调用 CLI 查看配置；可见性必须与 API/MCP 一致。
- 复用 HAPI 会话、审批和文件能力时，同样受对象授权约束；跳转原生页面不能放宽权限。

### REMOVED

#### `agents/scope`、`installation/cli`：取消客户端权威配置与人工命令主路径

取消 `.runweft/agents/*.yaml`、客户端全局 Agent 文件和本机个人绑定作为新委派的权威配置来源；保留显式迁移读取，不自动删除旧文件。官网从逐条指导用户敲命令改为引导用户交给 Agent/Skill 完成。

取消“知道共用 Hub token 即取得同一 namespace 全部管理权”作为面向用户的权限契约。HAPI 内部执行认证是否继续复用，由后续技术方案明确，不能把内部 root 凭据发给普通用户或 Runner 来替代对象授权。

## 验收标准

- [ ] 不配置邮件、OAuth 或注册服务也可领取身份 token；两次主动创建得到不同身份，同一 token 在 Web/CLI/MCP 使用同一身份与配置。
- [ ] 刷新、凭据失效或连接失败不会自动创建替代身份；清除本机凭据后可导入保存的 token 恢复使用，重新领取不能认领旧资源。
- [ ] 两个用户处于同一空间时，B 无法修改 A 的私有 Agent/个人设置；Web 隐藏按钮之外，直接 HTTP、CLI 和 MCP 请求同样拒绝。
- [ ] 非所有者的空间管理员能禁用私有 Agent，但不能修改其配置或扩大共享；“公开”的 Agent/runtime 对空间外身份仍不可使用。
- [ ] 不属于空间的用户不能凭空间、runtime、Agent、任务或附件 ID 读取、修改、执行或下载；列表、计数及流式更新不泄露私有数据。
- [ ] 资源共享后，被授权用户能够执行允许的动作；编辑、扩大共享范围和机器文件/终端访问权不会随之增加。
- [ ] 未连接 Hub、身份凭据无效、成员已移除、资源已撤销共享时，新的委派/续接不会绕过校验；已运行任务的后续处理明确记录。
- [ ] 同仓库不同 clone/worktree 命中同一仓库配置；同名仓库、fork 和不同空间保持独立；同仓库两位用户的个人配置互不覆盖。
- [ ] 新委派不依赖仓库内 Runweft 配置；未识别仓库或存在多个匹配项时不猜测，也不自动获得访问权。
- [ ] 全局和仓库级 Agent 的所有权、适用范围、绑定与实际生效版本可在 Web 查看，离线机器不导致配置消失。
- [ ] Agent 在专用环境完成安装、身份凭据接入、连接、登记、配置和首次委派；用户通过对话及 Web 领取/导入 token 完成接入，无需操作 CLI。
- [ ] HAPI 原生会话、审批、文件、终端、SSE/WebSocket 与 Runner 接入全部纳入权限验证；普通用户无法直连底层通道扩大权限。
- [ ] 旧数据导入有预览、去重、归属指定及失败恢复；历史任务与成果保留，不能猜测历史记录的真实用户。

## 可行性与限制

- **已确认：** Runweft 已有机器/runtime 中心库、任务协调与持久成果，可继续复用；独立用户身份、空间成员和私有资源授权缺失。
- **有条件可行：** 新的身份/配置层放在 Runweft 上层，但 HAPI 目前所有 HTTP/Socket 路径依赖 namespace。仅增加网页登录不足以满足授权；必须验证完整代理授权或最小通用 HAPI 认证扩展，不能宣称零改动接上即可安全多用户。
- **尚未验证：** 多用户端到端授权、共享 runtime 的跨空间接入、身份撤销对长连接的影响。调查只读源码和文档，没有运行 Multica 或修改现有服务。

## 后续技术设计

本轮共享范围、私有 Agent 管理权及身份入口已确认，不再作为待回答问题。后续需验证身份 token 与 Web/CLI/MCP、HAPI 各入口的衔接，细化空间邀请、凭据撤销与迁移，再拆分实现 Plan；不把邮件、OAuth 或登录/注册服务作为前置。
