# 产品模型与用户流程草案

> 更新：2026-09-30
> 本文是需求讨论材料，不是已确认 Technical 或实现 Plan。明确指示见 [Requirement](requirement.md)，身份边界见 [授权设计](access-design.md)。

## 入口分工

用户表达目标，由当前 Codex / Claude Code 主 Agent 通过产品 Skill 执行管理操作。CLI 提供结构化、可检查的管理动作；MCP 提供协作工具。Web 是用户了解连接、资源、配置和任务的完整入口；配置也可在有权的 Web 页面维护，不要求用户编辑 YAML。

官网的主要路径是“把安装/接入说明交给 Agent”。工程命令参考继续保留，避免把用户的常规使用过程写成终端教程。产品 Skill 只指导操作，不能凭 prompt 判断用户权限或充当权限实现。

## 对象与归属

| 对象 | 含义 | 与其他对象的关系 |
| --- | --- | --- |
| Hub | 用户连接的服务实例 | 持有身份、空间、配置及任务的权威数据；与其他 Hub 的身份、资源不自动互通 |
| User | token 对应的稳定用户身份 | 无需注册或验证邮箱；可加入多个空间；资源归属和任务记录使用稳定 ID |
| Space | 协作与资源授权边界 | 成员、角色、仓库目录、Agent 和任务按空间组织；不是磁盘工作区 |
| Machine | 接入的执行机器身份 | 有所有者，跨项目使用；真实文件、工具登录和执行环境仍在机器上 |
| Runtime | 指定机器上的 Codex 或 Claude Code | 独立于机器登记，有所有者与明确的空间授权；不改造成任意启动命令 profile |
| Repository | 空间中关联的 Git 仓库 | 有稳定 ID、规范身份及别名；不为每个会话创建新配置仓库 |
| Checkout | 某用户/机器上的实际仓库目录 | 映射到 Repository，区分 clone/worktree 与基线；目录路径不是跨机仓库 ID |
| Agent definition | 职责、说明及执行参数 | 保存在 Hub；独立描述所有者、共享范围、适用仓库和 runtime 引用 |
| Personal selection | 用户自己的选择 | 用户 × 空间 × 可选仓库下的 Agent/runtime 偏好；不改共享定义 |
| Task / Round | 一次协作与其后续轮次 | 固定发起用户、空间、仓库、主工作区、Agent 版本、runtime 和授权事实 |

原“全局机器/runtime”仍指不受项目目录约束，不应变成对所有 Hub 身份公开。建议机器登记保留 Hub 内稳定物理身份，再明确接入的空间；某空间中的共享不自动延伸到另一空间。同一机器如何对应 HAPI 的多个 namespace/连接身份，需要技术验证，不能仅复制一个相同 machineId 当作解决方案。

建议每个新身份获得一个个人空间，可再创建或受邀加入团队空间；再次使用同一 token 不重复创建空间。两者使用同一权限模型，团队空间中的用户也可有私有 Agent，不需要为每个私有配置额外创建空间。

## 配置范围与可见性相互独立

Agent 有两个独立维度：

- **适用范围：** 当前空间内跨仓库可用，或绑定指定 Repository。
- **访问范围：** 仅自己、指定成员、空间成员；“公开”限空间成员已确认，细分规则见授权设计。

不继续使用文件路径和同名覆盖来决定归属。定义以稳定 ID 引用，名称用于展示；两位用户都创建 `reviewer` 时互不冲突。主 Agent 发现时取得自己可访问的候选、所有者、适用范围和选择原因，不按同名项偷偷切换执行目标。

个人设置支持保存“在这个仓库优先使用我的 reviewer”等选择。仓库共享设置由其管理者维护，个人选择不改写它。初始建议只覆盖明确的选择字段，不引入任意层级 JSON/YAML 合并。若要更改共享 Agent 的职责，创建自己拥有的新定义并在 Hub 中关联；不能通过个人偏好改写他人的 instructions 或绕过 runtime 授权。

用户显式选择优先；否则使用本人的仓库选择，再使用本人的空间默认选择。共享推荐作为可发现候选；没有确定选择或同优先级冲突时由主 Agent 澄清，不随意选一个同名 Agent 执行。

## Git 仓库关联

1. 主 Agent 从真实 cwd 识别 Git 根、worktree/common directory 和 remote；只把识别信息用于寻找已获授权的 Hub 仓库记录。
2. Hub 保存稳定 Repository ID。托管服务可用的稳定仓库 ID 优先；否则使用规范 URL 和明确登记的 SSH/HTTPS 别名。去除 URL 中的凭据，不把本地绝对路径当全局键。
3. 同一仓库的多个 clone 和分支/worktree 关联同一项目设置。fork、不同 host、不同 owner/path 不自动归为同一仓库；不一律小写仓库路径。
4. 多个 remote、仓库搬迁或别名冲突时，Agent 发起显式关联，Hub 检查相应用户是否有权修改/选择该关联。不得因自报一个熟悉的 URL 而取得团队仓库权限。
5. 没有 remote 的 Git 仓库仍可在 Hub 创建记录，由 Agent 显式绑定 checkout；不自动跨机器合并同名目录。非 Git 本地任务继续只使用空间级配置，远端和独立 worktree 保留 Git 前提。

Repository 关联只解决“采用哪个配置”。实际远端任务仍从主工作区的明确基线程序化准备环境，启动前完成 Git、目录、附件和上下文；它不授权 Hub 自行读取任意代码，也不替代 Git 凭据或成果回收。

## 典型流程

### 首次接入

用户向主 Agent 提供 Hub 地址并要求接入。Skill 检查平台、安装配套 CLI，优先使用本机已保存的该 Hub 身份；没有凭据时返回 Web 入口。用户可领取新身份 token 或导入已有 token，无需注册、邮箱验证码或外部登录；领取时自行保存副本。CLI 程序化接收并保存接入凭据，再选择该身份有权访问的空间，具体浏览器衔接机制由技术方案验证。

创建身份不需要邀请，加入别人的空间仍需邀请或接纳。相同 token 对应相同身份；刷新、401 或网络故障不自动创建新身份，凭据不经过模型对话或诊断日志。清除本机凭据后可用保存的 token 恢复使用；无副本时不承诺找回原身份。

Agent 安装 MCP、连接本机 Runner、分别登记机器与 runtime，最后返回 Web 页面和检查结果。机器在线、工具可发现和模型可执行分别报告；检查失败不伪造“就绪”。授权后的重复执行要能辨别已有安装、同一设备和相同配置，不重复注册。

### 配置个人 Agent

用户说“给这个仓库配置一个 Claude 评审 Agent”。主 Agent 识别仓库，读取自己有权使用的 runtime，在 Hub 创建或更新本人拥有的仓库级定义，并显示职责、适用仓库、执行目标及私有/共享状态。用户在 Web 的仓库或 Agent 页面查看最终配置。

### 使用共享资源

runtime 所有者明确决定是否向某空间开放执行。Agent 所有者决定谁可以调用定义；调用者同时满足资源使用规则才可派生。两个开关的差别在 Web 中直接解释，不能显示“共享成功”但不说明 runtime 导致的不可用。

### 发起与回收

MCP 传递可信宿主身份、当前用户、空间和仓库上下文。Hub 解析中心配置并固定当轮快照，复用 HAPI 完成执行和观察。结果、附件和代码引用关联该任务的访问范围；Agent 公开不代表历史任务、prompt、代码和附件随之公开。

### 连接失效

Hub 不可达或身份凭据失效时拒绝新委派，保留可读的历史缓存及其时间说明，不用本地 YAML 静默替代。已经被 Hub 接受的任务按既有持久协调继续收尾；宿主退出后仍不承诺恢复原父会话。

## Web 信息结构

| 页面 | 用户看到什么 |
| --- | --- |
| 当前空间总览 | 当前身份、资源状态、任务、待处理事项；不要求显示所有人的私有任务 |
| 机器 | 所属人、在线/离线、接入的空间、本空间可见 runtime；无权者不展示机器路径与终端 |
| Runtime | 所属机器与所有者、Codex/Claude 类型、工具探测事实、共享范围、不可使用原因 |
| Agent | 本人/共享/仓库筛选，职责、配置版本、适用范围、runtime 绑定、有效操作 |
| 仓库 | 仓库身份、共享项目设置、我的选择、本人可见的关联工作区与任务 |
| 任务 | 当轮配置和发起人、执行/代码/附件状态、经同一授权的 HAPI 会话入口 |
| 空间与身份设置 | 当前身份 ID、token 保存/失效说明、成员、邀请、角色、凭据管理与可读审计记录 |

HAPI 现有 UI 继续用于原生会话与审批，沿用当前 Runweft 身份和授权。用户只管理 Runweft 身份 token，HAPI 内部认证由系统衔接。

## 旧行为迁移

| 旧内容 | 候选迁移方式 |
| --- | --- |
| `~/.runweft/agents` | 当前用户确认目标空间后，导入为本人私有定义；显示预览、冲突与来源 |
| `<repo>/.runweft/agents` | Agent 将定义与仓库身份提交 Hub；不改 Git 历史，不自动删除源文件 |
| 本机 `agent_runtime_bindings` | 按明确用户、空间、仓库匹配目标资源后导入个人选择；未找到 runtime 时显示待绑定 |
| 旧机器/runtime | Hub 管理员核对旧数据的实际所有者后认领；不能因先领取身份而自动获得全部资源 |
| 旧 namespace、任务和成果 | 显式映射旧空间，保留历史数据和“旧版未知用户”来源，不倒填虚假的发起人 |
| local 配置 | 由 Skill 转为显式连接的自托管 Hub 或选定中心，不能在身份失败时偷偷生成另一套本地资源 |

提供迁移预览、备份、执行回执和重复导入去重，未迁移项可诊断；不通过自动清理旧工作区或历史来实现升级。主机路径、数据根、连接凭据和受控缓存仍留在本机，集中的是业务配置及其权威归属，不是所有磁盘文件。

## 后续实现拆分建议

当前设计 Change 统一产品契约，未来建议按以下独立结果拆分并声明依赖；这不是已批准的实现 Plan：

| 模块 | 独立交付结果 | 依赖 |
| --- | --- | --- |
| 身份 token、空间与 HAPI 访问边界 | 用户领取/导入 token、加入空间；底层所有访问路径受同一权限控制 | 无；先验证 HAPI 集成约束 |
| 机器/runtime 所有权与共享 | 对已有全局资源建立可验证的注册、归属和调用权限 | 身份、空间 |
| 仓库及中心 Agent 配置 | 同仓库多用户配置互不覆盖，中心解析具有版本与个人选择 | 身份、空间、资源权限 |
| 委派身份和配置迁移 | MCP 全程使用中心配置，任务、成果和旧数据有明确归属 | 以上模块 |
| Web 资源与配置视图 | 用户在 Web 完成所有查看，不靠 CLI 获取资源信息 | 相应稳定领域接口 |
| 产品 Skill 与新上手流程 | Agent 完成安装到首个任务，官网交付该路径 | 稳定 CLI/授权流程、Web 入口 |

原生执行、工作区与成果传输不重写。任何需要 HAPI 补齐的通用身份能力在其独立仓库评审；本 Change 不预设修改 Codex/Claude launcher。
