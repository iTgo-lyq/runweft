# 账户与授权草案

> 更新：2026-09-30
> 下述“建议”尚未全部确认；公开范围和管理员对私有配置的权限已在会话提问。与 Multica 的差异明确列出，不视为现有 HAPI 能力。

## 账户不是 namespace

建议 Hub 保存实际用户，浏览器登录建立用户会话，CLI/MCP 使用绑定该用户、可撤销的客户端授权。空间成员关系独立保存，每次读取或变更以当前权限判断；客户端提交的 owner、space、repository、parent session 字段不自动可信。

参考 Multica：邮箱验证码登录、可选外部身份登录、浏览器会话与个人访问令牌分开。Runweft 的具体邮件服务、外部提供方及无邮件的自托管正式路径待定；不照搬把验证码写日志的开发模式。建议默认受邀请或管理员允许才能创建新账户，已有账户加入其他空间仍需被接纳。初始 Hub 管理员通过部署侧一次性引导产生，避免公开入口“先到先得”。

用户可在 Web 查看并撤销自己的设备/CLI 授权。Agent 负责发起和完成程序化衔接；用户仅在浏览器完成实际身份验证，不把根凭据或验证码放入模型 prompt。过期、撤销、用户禁用和成员移除应作用于仍连接的客户端及流式订阅，不能只等待下一次重新登录。

## 四类授权分别判断

| 权限 | 含义 | 不自动包含 |
| --- | --- | --- |
| 查看 | 发现资源及获准展示的配置 | 使用机器、执行任务、修改定义 |
| 使用 | 调用指定 Agent，或将自己的 Agent 绑定到获准 runtime | 编辑别人的配置、读取其历史任务、控制机器 |
| 修改 | 修改本人拥有或被明确授权管理的配置 | 转移所有权、扩大共享、读取模型凭据 |
| 治理 | 空间管理员管理成员、禁用资源、处置违规任务 | 自动取得他人私有 Agent/runtime 的调用或改写权 |

资源所有者与空间 owner 是不同概念。Hub 运维管理员是系统管理角色，不在产品 UI 中伪装成资源所有者；自托管运维者具有服务器/数据库控制能力，不承诺对其实现密码学隐私。产品层的账户隔离与同一 OS 用户上的进程/文件隔离也不同，不改变“权限沿原生默认、不新增执行沙箱”的既定边界。

## 建议权限矩阵

下表按“共享限所在空间、私有配置仅所有者编辑”的建议填写，待用户选择后调整。

| 动作 | 资源所有者 | 获授权空间成员 | 未获授权成员 | 空间管理员（不是资源所有者） |
| --- | --- | --- | --- | --- |
| 查看私有 Agent 完整配置 | 可以 | 仅被明确授予查看时 | 不可以 | 默认不可以；可见治理所需概要 |
| 调用 Agent | 可以，仍需 runtime 允许 | 可以，仍需 runtime 允许 | 不可以 | 不自动获得 |
| 修改职责、参数、绑定 | 可以 | 不因共享而允许 | 不可以 | 私有配置不可以；可禁用 |
| 扩大 Agent 调用范围 | 可以 | 不可以 | 不可以 | 不可以 |
| 使用私有 runtime | 可以 | 不可以 | 不可以 | 不可以 |
| 使用空间共享 runtime | 可以 | 该空间成员可以 | 空间外用户不可以 | 作为成员按同一规则 |
| 修改 runtime 的共享范围 | 可以 | 不可以 | 不可以 | 不可以 |
| 给别人的机器新增 runtime | 由机器所有者授权 | 不能因已有 runtime 可用而新增 | 不可以 | 不自动获得 |
| 修改个人仓库选择 | 修改自己的 | 修改自己的 | 修改自己的 | 不可冒充其他用户修改 |
| 修改仓库共享设置 | 被授予仓库管理权时 | 仅明确的管理者 | 不可以 | 可以治理本空间共享设置 |
| 删除/禁用空间资源 | 按资源规则处置自己的 | 不因共享而允许 | 不可以 | 可禁用；删除/归属转移需单独定义与审计 |

建议保留 owner/admin/member 三种空间角色，不扩展自定义角色系统。owner 可以管理 owner 身份，空间必须至少保留一个 owner；管理员管理普通成员及共享设置。分享和运行不由管理员角色隐式豁免。

## runtime 与 Agent 的共享组合

runtime 共享表示同意别人消耗该机器上的执行资源和原生账户额度。Agent 共享表示允许使用该职责定义。建议初版使用二者交集：

| Agent 对用户可调用 | runtime 对用户可使用 | 结果 |
| --- | --- | --- |
| 否 | 任意 | 拒绝 |
| 是 | 否 | 拒绝，并向有权看 Agent 的用户说明目标未开放 |
| 是 | 是 | 再检查成员、仓库范围、机器在线与执行条件 |

这比 Multica 将私有 runtime 绑定主要与 Agent owner 对齐的行为更明确：把私有 runtime 上的 Agent 设为共享，不会自动将该机器借给他人。暂不增加“仅指定 Agent 可代理调用私有 runtime”的第三种授权，避免用户无法判断一个共享开关的结果。

运行中任务不会因配置编辑被改写；每次续接重新检查调用者、成员、Agent、runtime 与版本。撤销授权立即阻止新轮次和未启动执行。建议成员移除、机器授权撤销同时请求停止受影响的在途任务，保留可审计的停止/结果状态；是否已实际停止必须以 HAPI 事实为准，离线不能冒充成功取消。

## 任务和结果的归属

私有 Agent 不意味着其 runtime 所有者永远无法接触任务数据：任务必须送到执行机器，机器操作者可能通过 OS 查看执行现场。Web/API 权限只承诺不通过产品接口越权披露。

任务记录实际发起用户、当前空间与仓库；Agent owner、runtime owner、仓库管理者不能仅凭资源身份自动读取所有调用者的 prompt、报告或附件。默认任务内容仅发起用户和被明确授予访问的成员可读；共享任务是独立动作。执行端取得完成该任务所需的信息及限定操作，不因此获得 Hub 配置管理员身份。

禁止通过公开 Agent 将其历史会话、所有任务、代码 bundle 或附件一起公开。历史记录可保留被撤销资源的 ID/版本用于审计，不允许据此开启新的访问。治理页面的概要与任务正文权限分开。

## HAPI 复用所需满足的边界

目前网关把非 Runweft 路由以及 WebSocket 升级直接转交 HAPI。HAPI Web JWT 和 Runner 使用的认证不能直接充当新的最终用户授权；否则 Web 加了账户，旧入口仍可能访问整个 namespace。

技术方案须覆盖以下实际入口，而不是只给 `/api/runweft/resources` 加检查：

- 会话列表、消息、续接、审批和归档；包括尚未关联 Runweft task 的原生会话如何归属。
- 机器发现、文件读取、命令/终端、派生及其他 RPC；共享 runtime 不等于授权任意机器操作。
- 附件预约、上传、读取、下载、引用和清理，以及仓库/成果 bundle。
- SSE、Socket.IO、终端 WebSocket 的身份、订阅范围和成员撤销。
- Runner 注册、心跳、执行认领及回报；机器身份不能在客户端声明后自动变为可信。
- HAPI `/auth` 的共用根 token 路径；旧路径不得成为新账户模型的旁路。

推荐先验证 Runweft 统一认证及对象授权能否在 HAPI 现有入口完成可靠衔接。若 Socket/Runner 信任契约或原生 UI 存在网关无法补足的缺口，列为独立 HAPI 通用认证扩展并先复现验证；不自建通用 runtime 框架，不修改原生 Codex/Claude 协议。

## 需要保留的验证场景

至少覆盖两个空间、三个不同用户（所有者、管理员、普通成员），加上两个 runtime 所有者，检查页面可见性与直接 API 权限一致。变更对象 ID、伪造 owner/space、复用旧 token、绕过 Web 访问 HAPI、撤销已打开的长连接都应有明确结果。

共享测试同时检查“允许的任务能执行”和“不能借此修改配置或读取不属于自己的结果”。仓库测试必须包含同仓库两位用户、跨 clone/worktree、同名不同仓库和 fork。测试通过前，不能把 namespace 映射方案写成已经验证的多租户隔离能力。
