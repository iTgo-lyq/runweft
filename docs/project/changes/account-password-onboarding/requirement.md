# 账号密码登录与 Agent 主导的首次接入

用户首次使用 Runweft 时，应只需表达一次接入意图，在浏览器注册或登录并确认本机连接，然后由 Agent 完成准备并读回第一次委派结果。普通用户退出后使用账号密码重新登录，无需理解、复制、下载或长期保管身份 token。

本次先交付改造方案与首次体验审查。用户要求保留现有身份、空间和权限体系，并明确服务尚未部署、无需兼容旧数据；密码遗忘由部署者通过服务器管理命令协助重置。本 Change 的实现尚未获准开始，本文和 [技术方案](technical.md) 是供审阅的设计材料，当前产品能力仍以 Specs 为准。

## 目标与规模

保留身份 UUID 作为人员归属主键；空间成员关系、owner/admin/member 角色、机器与 Runtime 所有权、Agent 分享和本人任务访问规则继续使用现有模型。将登录凭据从身份本身拆开，提供账号密码、可撤销浏览器会话、独立 CLI 授权和密码重置。

暂定 large：账户及会话、授权网关、连接协议与客户端、首次体验页面和 Skill/CLI 接入流程需要联动；还须覆盖短 JWT、流连接撤权、后台任务持续执行和当前数据格式检查。不是只增加两个输入框。

## 用户行为

### 注册、登录与恢复

- 注册仅要求用户名和密码；显示名称默认取用户名，初始空间自动创建，不要求填写空间名、配置角色或确认默认设置。
- 用户名在单个 Hub 内唯一，登录与空间授权仍由该 Hub 处理。用户名用于登录，显示名称可另行修改。
- 注册成功即进入账号；日后使用用户名和密码登录。提供密码显示切换、密码管理器自动填充和明确的输入校验，不要求重复输入确认密码。
- 浏览器在当前标签会话内维持登录；刷新保留，退出后该会话在服务端失效。关标签或会话到期后用账号密码重登。首版不承诺跨浏览器重启的长期记住登录。
- 账户页支持修改密码、查看登录环境、撤销某个浏览器或 CLI 环境，以及退出全部用户登录环境。密码修改与重置使既有用户会话、CLI 授权和未完成连接失效。
- 忘记密码时页面引导联系 Hub 部署者；部署者在服务器上签发短期、单次重置码，用户在浏览器设置新密码。重置码仅用于当次恢复，不要求用户预先保存。空间管理员角色不自动获得密码重置权限。

### 首次连接

- Agent 先检查已有程序、当前 Hub、已保存授权、机器与执行工具。已有有效状态直接复用。
- 接入指令明确给出 Hub 时连接该地址；有既有连接时继续使用它；两者都没有且用户采用默认首次体验指令时，在本机启动 Hub，不再额外询问相同决定。
- 唯一正常的身份交互是一张浏览器连接页：展示 Hub、设备名、核对码和授权范围，注册／登录表单与“注册并连接”／“登录并连接”合并呈现。已登录时只需确认连接。
- 新用户自动使用刚创建的初始空间；已有用户优先展示有效的已选空间，仅存在多个候选且无法确定目标时要求选择。
- 浏览器确认后 CLI 自动完成领取和验证；用户不需要把 token、密码或“已完成”文本发回聊天。当前 Agent 持续在场时通过有界等待接续；Agent 已退出时由用户之后发起续接，不后台唤醒父会话。

### 首份结果优先

- 在已有安装授权和首次任务授权内，Agent 用 CLI 完成机器接入、空间关联、Runner 启动、执行工具探测与登记、首个私有 Agent 的创建或复用，以及 MCP 安装检查。
- 当前客户端类型明确且对应原生工具已登录时直接使用它；多种工具存在也不要求用户重复选择当前宿主。原生工具未登录时才交给用户完成该工具的登录。
- 首次任务默认是本机共享目录内的只读代码评审，不要求用户提交现有未提交改动、创建独立 worktree、手工配置仓库、分享资源或选择模型。Git 目录仍须满足现有仓库匹配规则，由 Agent 自动 inspect/match，必要时 create/bind；只有匹配歧义、基线不可用或当前目录无合适源码时才询问。
- Agent 直接使用现有 task CLI 发起、等待并读回首份报告，不把“重开客户端再发第二段提示”作为看到结果的前置条件。
- MCP 已可用时直接核对；新安装的 MCP 只有宿主需要重载时才提示用户重开。首次 CLI 任务成功、MCP 配置完成、MCP 实际调用分别报告。
- CLI 的首次任务保持 CLI 父上下文；重开后的 MCP 会话不冒领该任务，也不伪造旧父身份。

用户仍需主动完成密码输入、连接授权，以及必要的原生模型登录／权限审批。安装冲突、切换已有 Hub、对外共享、无法推断的任务范围等会改变已有状态或授权的选择须说明后处理；不为重复的实现细节反复确认。

## 已明确取舍

- **Q1，技术**：用户回答“完全不需要兼容，目前服务没有在任何地方部署”。直接采用新的唯一当前格式，移除旧身份 token 登录、备份、导入、轮换及旧 CLI 身份输入契约；不增加迁移器、双版本读取或自动清理。旧测试数据被明确拒绝且原文件保留。保留身份体系指保留模型和权限语义，不承诺导入旧数据库。
- **Q2，需求**：用户选择“部署者通过服务器管理命令协助重置”。首版不接入邮箱、短信或外部身份提供商；不把长期恢复码作为普通用户必备物品。
- 用户追加要求：重新 review 首次体验，尽量减少用户交互，可由 Agent 使用 CLI 执行的步骤交给 CLI。对应 [首次体验审查](onboarding-review.md) 的责任划分及目标流程。

## 范围与协作

覆盖 Hub 账户入口、账户设置、连接确认和成功态，CLI 授权与恢复诊断、产品 Skill、官网和使用说明。执行仍复用 HAPI；账号密码属于 Runweft 现有身份与网关，不改造 launcher 或通用 runtime 协议。

当前 `hub-glass-prototype` 是独立视觉原型探索，不作为本 Change 的功能依赖。实施登录和首次体验 UI 前，在项目唯一原型包补充这些完整流程并提供固定预览，协调其共享页面，避免两个分支并发覆盖。该原型工作属于后续方案落实，本轮只审查现状、确定交互与契约。

## 验收依据

| 场景 | 可观察结果 |
| --- | --- |
| 新用户注册 | 一次提交生成账号、身份及初始空间；不显示身份 token，不弹备份框；默认显示名无需额外输入 |
| 退出后重登 | 原会话失效；正确账号密码进入同一身份和空间；错误信息不区分账号不存在与密码错误 |
| 重复用户名、响应丢失 | 不创建第二个身份；先核对登录结果，失败提示可恢复，不换随机用户名重试注册 |
| 浏览器 A 退出、浏览器 B 和 CLI 存在 | 只撤销 A 及其派生访问；B、CLI 和 Runner 保持各自授权 |
| 修改／重置密码 | 旧浏览器、CLI、派生 JWT 和待完成授权失效；机器凭据独立；新密码进入原身份 |
| 部署者恢复 | 无有效本机 Hub 数据或无相应 OS 权限时拒绝；一次性重置码到期、重放、被新码替换均拒绝；秘密不进入普通 CLI/Agent 输出 |
| 首次完整接入 | 前置条件满足、采用默认指令时，用户只发送一次请求并完成一张注册／连接表单；其余 CLI 步骤和首份报告读取由 Agent 完成 |
| 已登录／已有接入 | 跳过不需要的注册、安装、机器登记与 Agent 创建；不产生重复资源 |
| 身份敏感操作 | Agent 从未索要或代填用户密码；浏览器连接确认显示真实 Hub、设备与授权范围 |
| CLI 未获确认、取消、过期或断网 | 未确认/取消/过期的未消费请求不授予可用凭据；断网沿原请求核实是否已激活并续存，未知结果不重新注册用户、不重发首个任务 |
| 新 Hub 中的现有 Git 项目 | Agent 自动登记或匹配并绑定本人 checkout 后开始 shared 评审，不要求用户手工配置，不伪造 non_git 绕过匹配 |
| Runtime 探测通过 | 只报告探测事实；只有真实首个任务完成且报告可读才声明执行体验成功 |
| MCP 需要重载 | 首份 CLI 报告可以先交付；重载后的真实 MCP 调用另外验证，不把 CLI 成功冒充 MCP 验收 |
| 既有权限 | 跨身份、跨空间、私有资源与任务内容隔离成立；成员移除和资源撤权继续按现有业务规则生效 |
| 登录凭据撤销期间有任务 | 用户访问失效，已接受任务按稳定 owner/space 继续推进；不重放模型输入；新登录可以找回本人任务 |
| 受限 HAPI 页 | 仅持指定空间短凭据，不能取得浏览器会话、授权新 CLI 或延长原生页面登录期限 |
| 数据格式 | 仅创建/读取新格式；旧、未知、损坏数据库及连接文件明确拒绝，拒绝过程保留原文件及 WAL/SHM |
| 产品 Skill | 独立 Agent 场景验收证明它复用状态、少提问、凭据不入聊天、通过 CLI 完成首份结果 |

本轮方案文档与现状截图不构成以上新行为的实现或验收证据。实现后按测试手册定向执行接口、CLI、Playwright 和已授权的真实模型验收。
