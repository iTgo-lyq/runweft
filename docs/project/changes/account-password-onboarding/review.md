# 方案独立评审

本轮独立 Agent 只读评审了需求、技术方案、调查依据和首次体验审查，覆盖范围控制、CLI 连接协议、原生页凭据边界及当前代码能否支撑首个任务。以下均为方案评审和文档修正，不构成实现验收。

## R1 首次 Git 目录仍需关联中心仓库

证据：[委派服务](../../../../src/hub/delegation/service.ts) 在所有模式先执行 repository.match，仅接受 matched/non_git。最初方案把 shared 模式误写为无需 Repository，会使全新 Hub 的首个 Git 项目任务失败。

修正：用户无需手工配置，但 Agent 必须 inspect/match，并按明确当前目录/远端 create/bind；歧义时询问。需求、CLI流程、体验表格和验证路径已同步。未改变仓库授权、不伪造 non_git、不擅自提交代码。

## R2 CLI 批准与实际凭据激活必须区分

初稿在 Web 确认时激活客户端已持有的最终秘密，又要求未消费请求在过期/撤权后不可使用；单纯禁止轮询不能约束已经激活的凭据。

修正：confirmed 仅保存批准事实，ACK 事务重查期限、成员和撤销状态后才激活唯一凭据。CLI 随后验证远端并保存本地，最后报告 connected；丢 ACK 或本地保存失败沿原请求恢复，已撤销的凭据不重新激活。网页只显示“已授权”，不把服务端 consumed 冒充客户端已完成保存。

## R3 原始浏览器会话与派生 JWT 不能混同

原生短 JWT 的 ref 可能指向 browser 凭据；若只检查凭据来源类型，就会允许原生页操作账号或授权新 CLI。

修正：账号管理、凭据列表/撤销和 CLI 确认必须直接提交有效原始 browser 会话秘密；派生 JWT 不接受，CLI仅能注销自身。普通身份/空间业务接口继续现有主体与权限规则。

## 范围与保留取舍

独立评审认为账号密码、独立环境撤销、部署者恢复及 CLI 主导首次体验直接服务用户目标，没有必要扩展通用身份平台或工作流引擎。浏览器 sessionStorage 的 XSS 风险及其与同源 HAPI 页隔离的取舍已明确写入技术方案，未声称优于 HttpOnly Cookie；实现前须在方案审阅中明确该取舍。

### R4：凭据结构与后台任务内部身份同步交付

此前 GLM 输出的一项非阻塞联动提醒仍有独立代码依据：删除用户表的长期凭据字段时，须同步替换 `serviceUser`。复核 [AccessStore](../../../../src/hub/access/store.ts) 的 `serviceUser` 仍直接读取 `tokenDigest`，而 [DelegationScopes](../../../../src/hub/delegation/context.ts) 的后台 lease 每次检查都会调用它。

### R5 / iclaude 第 1 项：确认即激活可简化连接协议

**意见**：客户端在 begin 时已持有最终秘密，浏览器确认时即可激活凭据，complete 只负责校验与保存；可省略 ACK 激活阶段。

**处理：保留为可选优化，本轮暂不采纳。** 这个替代设计可行，但评审同样确认当前方案可工作。当前 [连接客户端](../../../../src/hub/connect/client.ts) 已包含本机身份冲突检查、保存和 ACK 流程；改成确认即激活还会连带改变取消、请求过期与恢复的既定语义。本轮没有核心功能缺口需要通过这次协议改写解决，因此保持已描述的协议，不为非阻塞建议重新扩展设计。另外，begin 持久化随机秘密的 pending 记录在两种设计中都需要，“少一个本地文件”不能直接作为净收益结论。

### R6 / iclaude 第 2 项：按标签登录的实际可跳过条件

**意见**：从 Agent 打开的新标签通常没有 Hub 会话，不能把“浏览器另一个标签已登录”当作“连接页只需确认”的前置。

**处理：采纳事实澄清。** 需求、技术方案和体验说明已统一为：Agent 链接新开标签通常使用“登录并连接”，可配合密码管理器；只有连接页所在标签已保存有效会话才跳过密码输入。保留可用的同标签分支；已有有效 CLI 连接仍跳过浏览器。不新增跨标签会话机制。

其他建议涉及闲置期限、退出全部、具体参数和原型排期，本轮保持现有方案，不据此增删功能或启动实现；这些非阻塞建议不增加阶段门槛。此次结论是方案评审，不替代用户确认或新功能运行验收。
