# 方案独立评审

本轮独立 Agent 只读评审了需求、技术方案、调查依据和首次体验审查，覆盖范围控制、CLI 连接协议、原生页凭据边界及当前代码能否支撑首个任务。以下均为方案评审和文档修正，不构成实现验收。

## R1 首次 Git 目录仍需关联中心仓库

证据：[委派服务](../../../../src/hub/delegation/service.ts) 在所有模式先执行 repository.match，仅接受 matched/non_git。最初方案把 shared 模式误写为无需 Repository，会使全新 Hub 的首个 Git 项目任务失败。

修正：用户无需手工配置，但 Agent 必须 inspect/match，并按明确当前目录/远端 create/bind；歧义时询问。需求、CLI流程、体验表格和验证路径已同步。未改变仓库授权、不伪造 non_git、不擅自提交代码。

## R2 确认期限与凭据生命周期须一致

初稿在 Web 确认时激活客户端已持有的最终秘密，又要求未消费请求在确认期限届满后不可使用，两种语义冲突；单纯禁止轮询不能约束已经激活的凭据。此前通过 ACK 延迟激活解决这一冲突。

当前按用户采纳的 R5 更新：浏览器确认即激活，确认期限仅约束尚未确认的请求，确认后按凭据自身期限及撤销状态处理。确认前取消请求；确认后取消则撤销该请求创建的凭据。移除 ACK 激活与 consumed 状态，本地保存失败使用原待连接记录续接，已撤销凭据不重新激活。网页显示“已授权”，CLI 校验和保存后才报告 connected。

## R3 原始浏览器会话与派生 JWT 不能混同

原生短 JWT 的 ref 可能指向 browser 凭据；若只检查凭据来源类型，就会允许原生页操作账号或授权新 CLI。

修正：必须区分原始用户凭据与派生 JWT，不能只看 ref 指向的凭据类型。按用户后续明确的 CLI 核心要求，账号管理与凭据列表/撤销接受本人原始 browser 或 CLI 凭据；改密码/全端退出另验当前密码。浏览器确认新 CLI 仍须原始 browser 凭据与明确操作，人工 CLI 用密码验证授权本机请求。派生 JWT 均不能调用这些账户/授权入口；普通身份/空间业务接口继续现有主体与权限规则。此调整不沿用此前“CLI 只能注销自身”的限制，原因见 R7。

## 范围与保留取舍

独立评审认为账号密码、独立环境撤销、部署者恢复及 CLI 主导首次体验直接服务用户目标，没有必要扩展通用身份平台或工作流引擎。浏览器 sessionStorage 的 XSS 风险及其与同源 HAPI 页隔离的取舍已明确写入技术方案，未声称优于 HttpOnly Cookie；实现前须在方案审阅中明确该取舍。

### R5 / iclaude 第 1 项：确认即激活可简化连接协议

**意见**：客户端在 begin 时已持有最终秘密，浏览器确认时即可激活凭据，complete 只负责校验与保存；可省略 ACK 激活阶段。

**处理：采纳核心简化，保留本地待连接记录。** 2026-10-19，用户明确要求：“那就采纳‘确认即激活’的简化方案，保留必要的本地待连接记录，把需求、技术方案和评审记录同步更新。”此前暂不采纳主要出于复用旧流程；重新权衡后，CLI 在 begin 时已持有最终秘密，浏览器确认就是完整授权，取消和恢复可直接使用凭据语义，无须额外激活阶段。

落实到当前方案：确认事务创建并激活唯一凭据；complete 只查询、校验和保存；删除 ACK 激活与 consumed 状态。`connect.json` 继续保存秘密、原请求和连接上下文，用于断网、进程退出和保存失败后的重试，成功保存或确认取消后才清理；不另建待 ACK 回执文件。确认前取消或过期不授权，确认后取消撤销本次凭据，已确认凭据按自身期限恢复，重复确认不重建或复活凭据。

本机归属冲突保留原连接并取消本次授权，结果未知时保留待连接记录核实。改密码或全端退出撤销所有已有凭据，包含本地尚未保存的已确认凭据；未确认请求尚未绑定用户，旧会话失效后只有重新登录并明确确认才能授权。需求验收、技术验证路径和首次体验表述已同步；[iclaude 原文](iclaude-review.md) 保留评审时的输出，不改写其建议。该同步只更新设计文档，未进入产品实现。

### R6 / iclaude 第 2 项：按标签登录的实际可跳过条件

**意见**：从 Agent 打开的新标签通常没有 Hub 会话，不能把“浏览器另一个标签已登录”当作“连接页只需确认”的前置。

**处理：采纳事实澄清。** 需求、技术方案和体验说明已统一为：Agent 链接新开标签通常使用“登录并连接”，可配合密码管理器；只有连接页所在标签已保存有效会话才跳过密码输入。保留可用的同标签分支；已有有效 CLI 连接仍跳过浏览器。不新增跨标签会话机制。

其他建议涉及闲置期限、退出全部、具体参数和原型排期，本轮保持现有方案，不据此增删功能或启动实现；这些非阻塞建议不增加阶段门槛。此次结论是方案评审，不替代用户确认或新功能运行验收。

主体技术修正：取消方案中不必要的“账号环境管理仅限 browser”限制；CLI/Web 使用同一账户与空间领域规则，派生原生 JWT 仍受限制。人工密码登录复用原待连接请求与确认即激活，不另造一套恢复协议。任务只读接口按当前 owner/space 授权，不构造虚假 Parent；MCP 和执行控制范围保持原规则。分页前保留原本的本机当前目录限制，跨目录/机器查看由显式 --all 表达。

范围控制：不把所有网页按钮做成 CLI，不把完整原生会话编辑、终端、通用工作流或新权限模型纳入范围。用户不必为新增管理命令多做首次设置；Agent 仍先取得首份报告，Web 保留适合人工阅读和交互的可视化。
