# 统一 CLI、身份与部署

> 状态：进行中
> 规模：大型
> 更新：2026-09-29
> 确认依据：Runweft 是统一入口，支持本地模式与 Hub 模式；配置清晰易用，持久数据统一管理。用户无需操作两个 CLI，权限沿默认；HAPI 已有能力优先复用。本地验收由 agent 自动完成。
> 实施授权：2026-09-29 用户授权逐 Change 自主落实细节，经一次 iclaude Plan 评审后实现、提交、验收与归档；远端实测缺口可保留。

## Review 导读

交付用户能够安装、配置并诊断的一套 Runweft 基础入口。HAPI 保持独立源码和执行职责；本 Change 负责安装布局、命令承载、兼容版本选择、服务配置及主体授权，不实现任务调度或 Git 交付。

方案讨论见 [Design](design.md)，项目边界见[架构](../../architecture.md)。当前实现进度和验证证据见 [Execution](execution.md)，完整安装交付仍以本 Change 验收为准。

## 独立验收与交付边界

无需委派、MCP 或远端 Git 功能即可验收基础包安装、现有 HAPI 管理、配置、诊断、退出码和信号透传。阶段 1 必须明确协作代码的承载进程、公共数据位置与现有认证接入；业务数据结构归后续领域 Change，不创建通用执行框架或另一套账号系统。

各领域 Change 自行注册其命令、配置与诊断项，不反向要求本 Change 等全部功能完成；未安装或未就绪的能力不能显示为可用。完整功能包和全量 macOS 协作验收归集成与发布，本 Change 先验收 macOS 基础安装与已有 HAPI 操作。

## 行为变化

### ADDED

#### `installation/cli`：一个安装与操作入口

用户通过 Runweft CLI 操作 HAPI 与协作功能；保留底层退出码、信号和终端交互。提供 npm 安装到 macOS 的路径与诊断，不要求用户另外安装、记忆和日常维护 HAPI CLI。平台资产与具体打包方式待调查后确定。

#### `deployment/identity`：统一配置与授权

提供初始化示例、配置校验、生效配置与来源查询、路径诊断，使首次使用无需猜测必填项。全局 MCP 安装命令由宿主适配 Change 提供，使用这里确定的可执行入口与配置位置。

主机、中心服务和执行机器沿 HAPI 已有主体、执行目标与认证配置。用户不需在日常委派中完成两套独立登录；不另建 Runweft 账号系统、任务隔离凭据或权限策略层，不自动复制用户 home 或修改已有模型凭据。

主机入口校验真实工作目录并建立 `workspaceId` 绑定，供委派和附件引用；父会话身份由宿主适配提供，不用模型自行报告的目录替代绑定。

执行权限使用 HAPI/原生客户端已配置的默认；不为子任务额外隔离，也不自动设置 yolo、跳过审批或全权限参数。禁止递归属于协作工具角色规则，不扩展成 OS 安全隔离。

#### `deployment/operations`：可诊断的服务与兼容版本

封装 HAPI Hub/Runner、存储与版本兼容的已有诊断。任务活跃时不能用不兼容更新替换执行组件；新增协作记录纳入备份。协作层是逻辑职责，不预设另起旧工程 daemon 或独立中心服务；部署先复用 HAPI 已有形态。

MCP 与 CLI 调用同一能力；本 Change 提供服务入口和配置说明，宿主具体工具契约、结果通知与原生身份映射另行讨论。

#### `deployment/modes`：本地与 Hub 模式

本地模式开箱使用本机执行能力，不要求用户另部署或手工维护共享 Hub；内部允许封装本机 HAPI Hub/Runner，继续复用同一执行基础。Hub 模式连接明确的 Hub，使用已注册执行机器。两种模式使用同一 CLI/MCP 业务语义，不各建一套任务实现。

模式和当前连接在配置及诊断中明确显示；本地模式不意外连接外部中心或派到远端。切换模式不静默迁移任务、注册、凭据或用户工作区。

#### `deployment/storage`：明确且持久的数据布局

Runweft 管理的配置、数据库/状态、附件、托管 worktree、日志、缓存和临时文件有固定归属，持久数据不依赖系统临时目录或源码 checkout。默认数据根清晰且可配置；CLI 可输出实际路径、配置来源和保留/清理规则，备份能定位所需持久数据。

原生 Codex/Claude 配置和历史沿原生位置读取；共享主工作区留在原处。已有 HAPI 数据只在明确接入时使用，不自动搬迁。全局机器/runtime 注册、全局 agent 与项目 agent 的作用域分别由所属 Change 定义，不能混在同一个含糊 agent 列表里。

## 验收标准草案

- [ ] 用户从基础安装、配置到 HAPI 运行诊断均使用 `runweft`，无需直接操作第二个 CLI。
- [ ] macOS 通过正式 npm 包安装路径验证基础安装与已有执行管理；完整协作组合由集成 Change 验收，构建成功不替代实机验证。
- [ ] 命令承载、公共配置/数据位置、服务运行位置与认证接入已明确，下游增加领域能力不需要重写启动框架。
- [ ] 本地模式无需用户另部署 Hub 即可使用；Hub 模式可配置并诊断目标，切换不混用身份或静默搬迁数据。
- [ ] 初始化、校验和有效配置查询可自动测试；持久状态、附件及 worktree 不落在随机临时目录。
- [ ] 本地安装、配置、服务启停与数据保留由 agent 自动验收，不要求用户手工操作；真实远端验收单独记录。
- [ ] 版本不兼容、机器离线或缺少能力时明确反馈，不静默更换执行目标。
- [ ] 沿 HAPI/原生默认权限运行，没有新增账号、任务隔离、审批绕过或空白配置 home。
- [ ] 日志不泄露完整 prompt、源码或凭据；MCP stdout 只输出协议。
