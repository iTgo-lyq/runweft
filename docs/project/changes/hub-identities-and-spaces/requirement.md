# 身份 token 与空间

> 状态：待验收
> 规模：大型
> 更新：2026-09-30
> 前置：无；产品契约见 [总体需求](../hub-spaces-and-agent-configuration/requirement.md)。工程决策、Plan 评审和自动验收沿用用户授权。

## 目标与边界

用户无需注册即可通过 Web 领取并保存独立身份 token，凭已有 token 使用原身份，管理自己的空间、邀请和成员。身份与成员判断在服务端完成；姓名不是身份凭据，新身份不自动获得已有空间或历史数据。

本 Change 只拥有身份、空间和接入入口。HAPI 通道授权、机器/runtime、Agent、任务归属及 CLI/MCP 接入由后续 Change 实现；新 token 在接通前不能访问这些旧接口，不宣称多用户执行已经完成。

## ADDED

- `identity/tokens`：主动创建稳定身份，token 随机生成并仅存摘要；可导入、修改本人显示名称、轮换 token。没有留存副本时不提供找回路径。轮换不改变资源所有者 ID，旧凭据立即失效。
- `spaces/membership`：每个新身份创建个人空间；另可创建协作空间。owner/admin/member 角色；成员读本空间，管理员管理普通成员，owner 管理管理员及其他 owner；不得删除最后一个 owner。
- `spaces/invitations`：管理者生成单次、限时成员邀请；凭据持有者主动接受。管理员只能邀请普通成员，owner 可邀请 member/admin；owner 角色通过成员修改授予。撤销、过期、被其他身份消费的邀请不能再加入，同一消费人重试只返回仍有效的原成员关系；成员列表和邀请管理对空间外身份不可见。
- `dashboard/identity`：Web 领取/导入、备份 token、退出当前浏览器、空间切换、成员及邀请管理。不使用邮箱/OAuth，不要求人操作 CLI；刷新和失败不创建身份。

## 验收

- 两次主动创建得到不同 ID/token/个人空间；同 token 重新接入保留身份、空间与成员关系。
- token 明文不落服务端数据库/日志，网页有明确备份入口，退出不删除服务器身份；轮换后旧 token 401，新 token 沿用 ID。
- 两空间三角色的直接 API 权限正确；最后 owner、管理员提权、猜测 ID、邀请重放和过期均拒绝。
- Web 全流程经 Playwright，包括错误、刷新、备份、导入与跨用户邀请；不连接用户浏览器。
- schema 增量迁移保留旧表；原有测试、类型检查、构建通过。新接口不能充当 HAPI 共用凭据兑换入口。
