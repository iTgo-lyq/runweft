# 委派、轮次与子会话续接设计

> 状态：草稿
> 来源：[本 Change 需求](requirement.md)、[跨 Change 架构](../../architecture.md)
> 按用户要求保留需求阶段的方案讨论；本文件不是已确认 Technical，也不代表已实现。

本 Change 负责共用委派语义、实际 CLI/MCP 协作工具，以及本地共享 cwd 的完整流程。宿主适配只提供身份和传递机制；共享目录并发由主 agent 安排，不自动提交或清理。下文的 Git 基线、准备回执和封存要求适用于远端组合；公共 Git 准备和封存归属[本地工作区](../local-workspace-execution/requirement.md)，跨机传输分别归属[远端准备](../remote-workspace-preparation/requirement.md)与[代码回收](../remote-result-delivery/requirement.md)。

先复用当前 HAPI 的状态、消息、历史和控制入口，再补必要父子关联。Agent 定义解析到全局 runtime，runtime 再关联机器；启动前核对当前模式允许的目标，不能由业务 agent 名称替代资源身份。下文的记录与对账是逻辑要求，不预设照搬旧 daemon、独立执行状态库或 durable inbox。

## 1. 启动绑定

Runweft 持久化 delegation 与 HAPI 执行身份的关联；远端场景另关联 preparationId/environmentId。HAPI 保存对应真实执行。关联在调用之前建立或预留，不能等 HTTP 成功返回才开始记录。

HAPI 已有预分配会话身份和 Runner 启动去重基础，但现有公开 spawn 不等于满足 Runweft 的稳定请求重试。执行基础 Change 先核对已有入口和调用方式，仅在确认阻断缺口后评估最小管理入口增补，不预设 runtime 改造。Runweft 关联已有执行请求身份，不要求 HAPI 存储 delegation 业务模型。Git 准备回执由公共工作区能力提供，不能因此让共享目录委派依赖远端。

同一启动请求重试必须查询原关联。若已启动则返回同一执行；明确未启动才允许继续原准备操作。超时后无法判断是否存在进程时，保留未知状态并对账，不再次创建 agent。

会话进程启动、原生 runtime 可接收输入、首轮输入被接受是三个不同事实。首轮只在会话绑定核对完成后投递，并保留 HAPI 对输入的接受证据。

## 2. 每轮输入

每轮保存 `roundId`、任务输入、输入附件版本、HAPI 消息身份和原生轮次关联；启用 Git 工作区时另记开始 HEAD。优先利用 HAPI 已有 `localId`、消息去重和投递对账能力；具体字段映射在两种 runtime 上核对后确定。

模板分为稳定部分和本轮输入：

| 部分 | 内容 |
| --- | --- |
| 稳定协作说明 | agent 职责、主仓库绑定、输出规则、可调用 Runweft 命令、已有审批规则 |
| 环境事实 | 已准备目录、基线、输入位置、继承/排除范围；由程序填写 |
| 本轮任务 | 用户目标、验收要求、当前轮次、新输入和后续指令 |

必须明确告诉 agent：仓库已经初始化，使用提供的工作目录，不另选任务根仓库；需要依赖时按仓库说明安装。任务可按需访问其他研究材料，但不能通过修改 prompt 改变绑定仓库或发布权限。

prompt 可以要求 agent 测试、整理报告、登记附件及说明阻塞；它不能替代初始化完成凭据、执行终态或上传回执。缺少结构化报告时保留原生最终文本及缺失标记，不让一次文本格式问题抹掉真实执行记录。

## 3. 并发和后续消息

- 远端不同 delegation 运行在各自 worktree，可并行；本地共享目录的并发写入由主 agent 调度，Runweft 不自动加目录锁或改成独立工作树。CPU、内存与模型并发额度沿 HAPI/部署策略控制。
- 一个 delegation 默认串行执行轮次。后续任务先记录入队，上一轮原生终态已确认后才可继续；启用远端代码回收时，还须等待所属 Change 确认 Git 成果封存。
- 代码成果已形成不可变快照后，其网络上传可以与下一轮并行；封存失败而工作树仍未固定时不放行下一轮，避免混入两轮改动。纯报告委派不要求 Git 快照。
- 活跃轮次的 steer 只在 HAPI 与该 runtime 确认支持时开放，并单独标注为本轮追加输入；不把新任务排队和即时 steer 混成一个含糊动作。
- 单次 MCP 连接断开或 wait 取消不等于执行被取消。主宿主关闭后不恢复其对话或自动注入结果，已接受任务和结果沿 HAPI 生命周期保留用于收尾与看板。
- 只允许主会话派生任务；CLI 与 MCP 入口共用宿主适配的可信调用上下文，在服务端检查子角色，子 shell 直接调用 CLI 也不能派生。工具分流由[宿主 MCP](../host-mcp-adapter/design.md)负责；模型自报角色或任意 session ID 不能代替身份解析。此规则不增加同一用户进程间的权限隔离。业务方 skill 决定启动什么 agent，Runweft 不增加自动业务路由。

Runweft 只补 HAPI 尚无的父子关联。主会话在线时的通知/注入按宿主可用入口实现；基础路径是当前工具响应和显式查看/等待，不承诺结束主 turn 后的自动唤醒，更不恢复已关闭主宿主。

## 4. 状态与证据

展示至少区分三个维度，不把它们压成“任务完成”一个布尔值：

| 维度 | 来源 | 含义 |
| --- | --- | --- |
| 执行 | HAPI 的原生轮次事实 | 输入已接受、正在处理、等待审批、成功/失败/中断，或当前无法确认 |
| 交付 | Runweft 清单和存储回执 | 尚未回收、部分可用、完整可取回，或回收失败 |
| 验收 | 主 agent / 用户决定 | 尚未评审、接受、要求修改 |

HAPI 的 session 在线、界面不再输出、REST 请求返回成功都不能单独作为某一轮完成依据。应在 HAPI 内部复用或暴露 runtime 原生结束原因、输入关联和最终结果；Runweft 只消费这一事实，不对对话文本猜测终态。

如果某 runtime 无法提供可靠轮次证据，应明确标注当前组合不满足正式远端协作要求；不能用定时空闲猜测替代。

## 5. 中断与失败

中断请求同时绑定 delegation、round 和当前 HAPI 执行身份。HAPI 确认中断前，Runweft 只报告“已请求中断”。如果请求发出时上一轮已结束，不得转而中断下一轮。

准备阶段中断取消对应准备操作；执行阶段中断由 HAPI 完成；交付阶段中断只能停止传输，不改变已经结束的原生轮次。网络断开只触发对账，不证明执行已停止。

失败或中断后，只有 HAPI 确认执行停止、受控工具不再写入该工作树，才能制作恢复快照。快照标为部分成果，不把被中断任务标成成功。仍有写入或状态未知时保留现场，阻止目录回收。

安装依赖失败属于 agent 执行中的阻塞/失败，和启动前环境准备失败分别记录。模型认证无效也可能在真实启动后才暴露，预检查不能宣称认证已验证。

## 6. 单次操作不确定性的处理

| 中断位置 | 恢复动作 |
| --- | --- |
| 主机提交后没收到响应 | 使用同一请求身份查询 delegation，不重新委派 |
| 远端准备完成但回执丢失 | 按 preparationId 读取已保存回执，核对环境版本 |
| spawn 返回前连接丢失 | 按预留身份查询 HAPI 的进程/会话关联；未知时停止自动推进 |
| 用户输入提交后不确定是否接受 | 使用 HAPI 的消息接受记录对账，不重新发送同一 prompt |
| 原生执行结束但报告未到中心 | 重传同一终态记录和成果，不重新运行 agent |
| 上传中断 | 恢复同一文件上传或重新上传相同内容，发布按结果身份去重 |
| 原生会话恢复后 ID 变化 | 保存 HAPI 返回的新旧身份关联，再把后续输入路由到新 ID |

HAPI 负责进程、原生会话与轮次恢复；Runweft 负责委派和成果对账。后台重试仅针对有稳定身份、可查询结果的操作；进程启动和任务输入的未知结果不通过盲目重试处理。

## 7. 一轮结束与下一轮续接

1. 从 HAPI 获取原生终态与结果，保留已有 session/历史引用；不要把完整原生历史复制成另一个会话数据库。
2. 经 HAPI 关闭本 subagent 执行进程并确认停止，保留 Hub/Runner、原生会话记录及工作区。等待审批不是终态。若原生进程共享多个会话，先核对 HAPI 的独立执行生命周期支持，不能直接杀共享 runtime。
3. 需要代码交付时再固定工作树成果；收尾失败也不为等待人工处理而保持 agent 空跑。
4. 下一轮确认同一工作区可用，通过 HAPI 优先 resume 原生 session；保留依赖和代码状态，不要求旧进程持续存活。
5. 只有明确无法找到或恢复原 session 时，使用已有目标、已确认消息、上轮结果、改动依据和待办构造上下文并创建新 session。保留新旧关联，并向主 agent 表明这是历史重建。

历史重建只作上下文输入，不重新执行旧工具、不伪造成功记录、不复制不可获得的隐藏推理。上下文过长时摘要并提供结果引用；不足以完成当前任务时报告缺失。该能力是子任务续接，不是主宿主关闭后的恢复。
