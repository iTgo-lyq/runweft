# 清理计划

范围和验收见 [Requirement](requirement.md)。先由 iclaude 独立审计，再核对方案和实际差异；不按删除数量牺牲有效覆盖。

## T1 收敛工程验证与历史发行工具

删除无生产调用的旧发布判断、退出历史离线组装和被真实平台安装替代的 QEMU 检查，同步其测试、命令与操作说明。将临时文档链接校验转为正式 Node 入口。核对剩余 smoke 调用图及临时脚本的替代覆盖，保留当前集成、原生与发行门禁。

验证：针对性 Node/网站/根测试、文档检查、类型及构建；涉及删除路径的历史链接固定后逐字核对。

## T2 按能力合并规格并减少重复引用

将当前 50 份 Specs 收敛为约 18 份：Agent、资源、身份、空间、仓库、委派、执行及授权、工作区及远端基线、文件、代码成果、安装、宿主 MCP、看板、发行、官网、部署。保留跨能力契约，能力内集中定义；验收执行方法并入发行操作说明，历史结果留归档。按旧能力逐项核对独有规则并修正当前/历史链接。

验证：新旧内容对照、全部当前文档链接/锚点、无失效旧路径、工作流及 diff 检查；iclaude 审核完整差异与验证证据。

## T3 清空临时现场并完成验收

归纳临时脚本保留/删除理由；验证运行结束、自建进程退出，将必要摘要写入执行记录后清空 `.dev-smoke`。按已完成变更执行整体验证，最后复核目录为空和工作区只含本次授权修改。

验证：类型、根测试、Node 测试、构建、文档和工作流结果；清理前活跃进程检查、清理后目录检查。真实模型和外部发布不在本轮范围。
