# npm 首次公开发布计划

> 来源：./requirement.md
> 技术方案：./technical.md
> 状态：执行中
> 执行模式：逐任务提交

## 交付目标

将已验收的 Runweft 1.1.0 发布为公共 npm 五包，并验证用户安装路径。

## 关键决策

- 补齐随包 npm 安装说明后从干净提交重建、验证候选；只读 iclaude Plan 评审一次，主 agent 独立采纳。
- 平台包先发布，主包最后；同名同版本不可覆盖，失败先查询真实结果。
- 官方网页登录为外部认证依赖；已有用户指令授权发布，不另设确认门禁。
- 真正上传确认 E413 后追加 T4，源码归档保留全部代码/许可与当前平台构建工具；原程序不改。

## 任务

### T1 核对发行输入并补齐 npm 安装说明

- 状态：已完成
- 交付：既有候选的校验/预演、正确的随包 npm 安装命令和可执行发布方案。
- 依赖：无。
- 验收：既有冻结输入、归档内容和五个 dry-run 均符合发行；说明更正并提交，Plan 经一次 iclaude 评审并独立判断。
- 验证：候选检查、tarball manifest/Skill/hash、npm dry-run 与说明 diff。

### T4 缩减平台源码归档并验证构建材料

- 状态：已完成
- 交付：按平台携带预编译工具的完整匹配源码归档、来源说明和仓库元数据。
- 依赖：T1；T2 的 E413 失败证据。
- 验收：全部非工具压缩包文件与 Git pin 一致，当前平台工具完整，归档可以交叉编译相应 CLI，构建/测试通过。
- 验证：源码归档逐文件 Git blob 校验、实际四平台 CLI 编译、typecheck/test/build；提交后 T2 重建正式冻结候选并重跑包/安装检查。

### T2 发布与公共安装验证

- 状态：进行中
- 交付：重建候选、公共 npm 五包与专用安装证据。
- 依赖：T1、T4、用户完成 npm 登录。
- 验收：新候选保持已验收程序和 Skill hash，包内说明正确；五包版本、tag、hash、依赖正确；公共下载与隔离安装验证通过。
- 验证：package --all --reuse-hapi、test:packages、test:install、dry-run；真实 npm publish、公共 registry 读取/下载、专用 prefix 安装、版本/程序/Skill/MCP 帮助检查。
- 进展：T4 已修正源码归档体积，重建候选并重新发布；额外认证按新请求处理。

### T3 同步发行事实并归档

- 状态：待开始
- 交付：当前安装/发行文档与完成的发布记录。
- 依赖：T2。
- 验收：只写已验证的发布事实；任务均有独立 Commit，Change 校验通过并归档。
- 验证：文档 diff、链接检查、validate-change；按持续授权自动验收。

## 整体验证

五个公开版本完整性匹配冻结索引；公共 npm 的 Linux x64 隔离安装通过。其他架构只报告本次公共下载校验和既有验收范围，不将 CI 安装等同于完整模型协作实测。
