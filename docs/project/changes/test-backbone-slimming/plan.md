## 交付目标

首先解决验收自身频繁出错、模型流程过长及失败后整组重跑，留下能稳定发现关键故障的骨干测试；再收敛六条原生主链和少量专项，降低整体成本。快测 40 秒不是本轮主验收指标。用户已在方案后授权“优化吧”，按 T1–T6 直接实施和本地验收。

## 任务

### T1 修复验收可靠性并前置已知失败

- 状态：已完成
- 交付：先按 Research 失败表处理浏览器路径、Agent 快照/跨轮 inputs、launcher/core hash、超时退出误判；沿现有 fixture/证据补阶段定位、前置闭环及有界脱敏诊断。按 K1–K12 完成精确删除/合并→替代映射。
- 依赖：实施前核对基线和活动 Change；只读 Plan 评审完成。
- 验收：拟删断言均有真实故障解释或替代定位；fixture 使用真实两端函数，四类已知环境/造数/证据错误均在零模型阶段暴露；模拟 host 超时但 exit=0 仍失败。未知根因不伪判外部故障；部分构造失败仍清理且退出失败，不新增旧格式处理。
- 验证：定向 fixture/lifecycle/候选身份与超时故障注入；正常两轮 fixture→consumer→cleanup 闭环使用新现场可重复。禁止先重跑真实模型来试探静态接线是否正确。

### T2 删除浅层测试并收敛 CLI 重复覆盖

- 状态：已完成
- 交付：先处理源码拼写/纯标签/重复默认映射及 CLI 重复启动；将复杂权限与 CAS 保留在领域用例，编译 CLI 保留真实接线与错误出口。更新删除映射，删除无消费者 fixture。
- 依赖：T1。
- 验收：默认 `./test` 不启动模型，K1–K12 仍有明确骨干；不合并成难以定位的巨大流程；安全/并发/未知恢复断言不因看似重复被误删。
- 验证：改动文件定向测试、typecheck；完成批次后一次根测试。对选择的真实高风险断言做少量临时故障注入，证明保留用例会失败；不安装全仓 mutation 框架。

### T3 合并无模型集成与浏览器验收

- 状态：已完成
- 交付：access/storage/web/service-package 四组显式入口；console 主体与历史读取一次执行；文件/Git 集成仅保留独立故障，完整大文件/heartbeat 验证归单一明确位置。
- 依赖：T1；与 T2 保持同工作区串行。
- 验收：删除重复 smoke/转发入口前完成保障接替，Playwright 实际 token/401/迟到响应可失败，权限/Runner outgoing 重查仍真实执行。只复用不可变程序，不跨 case 共享可变环境。
- 验证：受影响组一次实际无模型集成和清理检查；API/MIME/CSP/权限保障与重启/流式故障保留。

### T4 实现原生骨干、前置检查并冻结候选

- 状态：已完成
- 交付：N1–N6 主链及双 runtime 原生控制/缺失重建专项；专项自建自有会话和现场，不破坏主链证据。旧 producer 断言接替，历史/留存/安装消费者接链一次；每宿主一次 65 秒真实等待；按完整 case 失败重跑。全部六链/专项代码、共享 helper 和 package.json 命令增删在首次模型执行前完成并冻结干净候选。
- 依赖：T1、T3；不得在 preflight 未通过时调用模型。
- 验收：明确实际执行组合和剩余扩展条件，单 case 成功包含 consumer/cleanup；影响共享 helper 时相关证据失效。保留 MCP 文件/成果真实调用、子执行工具禁用、默认权限、原生进程退出和 source 配置不变。
- 可靠性：缩短原生 host 的多步编排，真实 MCP 契约仍实测；单例首跑失败立即记录阶段和归因依据，未知原因停止诊断，明确外部失败最多一次受控重跑，不覆盖首次结果。
- 验证：类型检查、真实 fixture 写入→公共读取→消费者记录检查，以及专用编译 local/hub 空原生配置 preflight；全部脚本与 packageInputs 先提交，随后构建干净候选。真实模型验收单列 T4V，避免把尚未执行的模型验证写进冻结提交。

### T4V 验收冻结原生骨干

- 状态：待开始
- 依赖：T4。
- 交付：先一条代表链验证生产/消费/清理，再执行其余五条及按 runtime 隔离的控制、重建专项；复用有效成功 case，记录首次失败、归因、MCP 调用数和清理。单独失败仅重跑该 case；未知根因先诊断，不靠整组重试。
- 验证：先完成安装及 service-package 无模型 gate；N1/N2 各一次65秒等待；两 runtime真实历史由 shared消费者各检查一次。共享 helper 修改使依赖结果失效；未完成真实验证不声称通过。

### T5 优化 CI 触发和开发入口

- 状态：待开始
- 交付：普通提交快测、本机相关集成、单一发布候选四平台构建入口；更新工作流及开发说明的旧命令引用，不保留兼容转发。package.json 及其他 packageInputs 的调整已经在 T4 验收前完成，本任务不再改动。
- 依赖：T2–T4V；核对 npm-patch-release/npm-beta-publishing 实际结果，避免覆盖另一工作区改动。
- 验收：事件→job 选择表说明代码、测试、文档、网站、发布脚本、stable/Beta tag 和手动运行；同一推送不重复四平台候选。tag/手动候选完整执行无模型 gate，不依据 diff 跳过，正式发布在同一 run 中等待全平台验证。
- 验证：actionlint、既有 Node 发布/网站测试与事件选择检查；真实远端工作流需要实施时的推送范围授权，本方案阶段不执行。没有远端结果则明确保留缺口。

### T6 验收可靠性与总成本并同步事实

- 状态：待开始
- 交付：删/留映射、首次通过/失败分类/重跑范围、含失败尝试的总耗时与模型调用数、前后测试规模，更新相关开发规则和已验证 Specs 后归档。
- 依赖：T2–T5。
- 验收：核心快测和修改的轻量 fixture 闭环使用新现场连续三次无意外失败；原生逐例首次结果和重跑均可追溯。必须验证已知脚本错误前置拦截、首次失败可定位、有效负例仍会失败；快测三次中位数仅辅助评价，不能靠少跑或最终一次成功宣称可靠。
- 验证：复用 T3/T4 同候选有效结果；源码/包输入未变不重建、不重跑全套。根 typecheck/test/build 按实际变更选择必要检查，核对清理、文档链接和最终 diff。

## 实施顺序与主要风险

T1 → T2 → T3 → T4 → T4V → T5 → T6。先修验收自身与失败定位，确定性层稳定后才执行真实模型；减少用例不能替代这一步。六主链覆盖与耗时待实测，发现独立耦合就保留专项。CI 必须以 Beta/正式发布最终文件为输入。所有影响包输入/共享 fixture 的工作在模型验收前完成，避免为了前置改动重跑已完成链。
