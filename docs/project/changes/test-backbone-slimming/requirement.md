# 第二轮瘦身：核心测试与快速验收

> 状态：已确认
> 规模：大型
> 更新：2026-10-03

## 目标与授权

减少浅层、重复测试和真实模型验收的重复成本，保留能发现关键产品故障的骨干用例。用户本轮明确要求“先准备方案”；既有授权允许主 agent 制定工程方案和 Plan，本次只完成方案与一次 iclaude 评审，不开始实施，不派生 subagent。

以第一轮已验收提交 `6cb4332` 为基线；工作分支 `codex/test-backbone-slimming`。主目录仍在第一轮之前且有未提交资料，不在那里实施或覆盖。已有 npm 发布/Beta Change 与本轮 CI 文件有交叉，实施 CI 任务前核对其最终状态，保留通道、发布回执和 OIDC 契约。

## 范围

- Runweft 的 `test/`、验收脚本及 fixture、测试命令、构建验收选择和 CI 触发；调查结论见 [Research](research.md)。
- 保留全部产品能力、CLI/MCP 对外契约和权限边界；自有数据仅支持当前格式，不增加迁移、兼容读取或旧数据清理。
- HAPI 固定版本作为真实集成依赖；复用其保障，不瘦身整个上游测试库，不改 HAPI fork 或 runtime。普通 Runweft 改动不触发 HAPI 全套测试。
- 不以测试数、断言数或删除比例作为完成指标；不把多个独立故障塞进一个巨大用例来降低数量，不新建通用测试框架。

## 行为变化

### MODIFIED

- `release/acceptance` — 验证选择：从散落入口和重复完整矩阵，调整为默认核心测试、按影响选择的无模型集成、代表性原生链及明确触发的扩展矩阵。少跑的组合必须标明未执行，不继承历史完整矩阵的通过结论。
- `release/distribution` — CI 验证成本：普通提交以核心测试及本机必要构建为主；正式候选仍执行四平台构建、安装和发布门禁，避免同一推送启动两套相同候选构建。

### REMOVED

- 测试内部的纯实现复述、重复表示层断言、没有独立故障的组合、重复模型生产者和过时验收入口。删除前标出具体替代用例或说明该断言没有产品保障；内部测试命令可移除，不保留空转包装或旧证据兼容代码。

## 验收标准

- [ ] [核心保障表](research.md#核心保障与测试归属)中的权限、并发、持久恢复、数据不改写、协议和交付保障有明确用例；删除清单包含原测试、故障、接替测试、必要执行层。
- [ ] 默认核心测试不启动真实模型；新增/修改测试能说明会发现什么真实错误，错误码/副作用/持久事实优先于内部调用顺序和源码字符串。
- [ ] 原生主链按 Technical 的六组合执行，两个宿主的长等待、两个 runtime 的真实控制及原生缺失重建保留；只在触发条件满足时扩展组合。
- [ ] 模型调用前完成候选身份和生产者→消费者契约检查；失败按 case 保留证据，只重跑受影响的完整链，失败和清理不确定均不得计为成功。
- [ ] 默认核心测试在同机同版本下，以三次串行运行的中位数对比当前约 60 秒；目标不超过 40 秒。无模型本地集成目标不超过 5 分钟；六条原生主链目标不超过 30 分钟。这些是优化目标，不是已测结论，不用降低有效验证来硬凑。
- [ ] 汇总模型调用数、case 数、墙钟时间、fixture/脚本行数及失败重跑范围；清理确认本次所属进程退出，保留精简证据，不扫描用户或历史数据。
- [ ] 按改变的层级验证一次并复用同候选有效结果；无产品输入变化不为提交、评审、文档或归档重复构建/全矩阵。

## 当前限制

只实测了根测试基线，未启动本轮真实模型、浏览器、HAPI 集成或远端 CI。六组合的耗时和删减后的覆盖需实施时验证；本机多 Runner 不等于物理跨机，其他平台仍按实际执行范围报告。
