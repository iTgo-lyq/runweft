# npm 可信发布实施计划

> 来源：./requirement.md
> 技术方案：./technical.md
> 状态：执行中
> 执行模式：逐任务提交

## 交付目标

五个 npm 包绑定实际发布工作流，后续版本通过 OIDC 发布，当前版本保持不变。

## 关键决策与风险

- iclaude 只读评审一次完成，主 agent 采纳四平台复用、恢复/保留期、事件判断、已有版本预演及权限范围说明；官方 API 确认 OIDC 路径已公开。
- 普通分支只预演，严格 push 稳定版本标签才上传。信任范围为仓库工作流，不添加 environment 或账户策略。
- 本次没有新版本上传；T1 CI 的授权 job 在 T2 完成绑定前可以失败，绑定后只重跑失败 job。

## 任务

### T1 发布工作流与聚焦验证

- 状态：已完成
- 交付：标签发布、普通分支预演、冻结候选/冲突/部分发布检查和 OIDC 交换检查。
- 依赖：无；Plan 完成后只读 iclaude 评审一次。
- 验收：普通分支不上传，已有 1.1.0 预演报告已发布并继续候选检查；同版本冲突在正式上传前停止。平台先于主包公开，回执/候选三十天保留，秘密不进日志。
- 验证：聚焦模拟 registry 与 npm 子进程验证、现有真实 1.1.0 包预演、工作流结构检查；提交推送后真实 CI 构建。

### T2 配置五包信任并验证真实授权

- 状态：已完成
- 交付：五包可信发布绑定、脱敏回执、真实托管 runner 的 OIDC 交换结果。
- 依赖：T1 已推送、用户完成必要 npm 本人认证。
- 验收：逐包核对实际创建响应中的 owner/repository/workflow 和直接发布权限；五个真实 OIDC 交换再次确认，不公开新版本。
- 验证：官方 Registry API 新增响应、真实 CI 检查；认证使用 npm 官方组件，成功操作不重发，专用 logout 和认证清理。

### T3 同步规格并归档

- 状态：进行中
- 交付：开发操作说明、发行规格及可信发布验收归档。
- 依赖：T1、T2。
- 验收：只记录实际完成的绑定和检查，不把授权检查当作新版本上传。
- 验证：validate-change、文档链接和 diff；按持续授权自动本地验收，逐任务提交并推送。

## 整体验证

五包官方绑定、真实 OIDC 交换及同一 CI 候选四平台检查通过；正式上传路径通过失败/恢复的模拟验证，最终验收明确没有发布新版本。
