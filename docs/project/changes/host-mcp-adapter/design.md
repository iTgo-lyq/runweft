# 宿主身份与工具分流草案

> 状态：草稿
> 更新：2026-09-29
> 来源：[Requirement](requirement.md)、[Research](research.md)。这是需求讨论中的候选映射，不是已确认 Technical。

## 适配顺序

优先复用 HAPI 会话、原生 ID、消息与恢复入口，本适配只输出可信调用上下文；父任务与 MCP 业务调用的关联由委派 Change 消费。仅 HAPI 尚未覆盖的主宿主接入信息，才由薄适配读取公开的 Codex 元数据或 Claude stdio 环境/hook。

本 Change 不依赖委派服务；受控 subagent 角色通过 HAPI 启动上下文预先绑定，后续业务调用方可附加 delegation 关联。启动时把已确定的角色与调用上下文绑定到 Runweft MCP 实例，或通过 HAPI 已有 session 元数据查询。字段与注入入口须沿现有实现确定，不新增通用执行框架或独立认证锁。

## 工具分流

| 调用角色 | 工具列表 | 调用检查 |
| --- | --- | --- |
| 已识别主会话 | agent 发现、派生、状态/等待、消息、续接、中断、成果读取 | 使用当前父身份关联任务 |
| Runweft 或原生 subagent | 必要的自身状态汇报、协作消息和成果登记 | 所有创建新子任务的动作拒绝，包括绕过列表直接调用 |
| 无法识别 | 诊断和不产生委派的必要能力 | 不默认为主会话，不要求模型猜测身份 |

列表绑定连接/调用上下文，不能用一个服务全局的 role 开关。多个父任务和子任务同时使用 MCP 时互不覆盖。角色变化后更新列表，同时始终校验调用，避免缓存的旧列表允许递归。

原生子 agent 可能复用父 MCP 连接，而 tools/list 未必包含逐调用身份。这里必须验证宿主支持的子工具过滤或连接绑定；如果只做到调用拒绝，明确报告工具可见性尚未达标。不会为了隐藏工具启动第二套 agent runtime。

角色限制用于落实一层委派，不做额外 OS 隔离、权限系统或防御同一用户主动修改进程环境的安全边界。

## 身份变化与结果进入上下文

Claude stdio 环境只作启动身份，结合 HAPI/原生事件处理 `/clear` 等变化；同目录同时开多个会话不能按 cwd 猜对应关系。Codex 的调用元数据与原生来源共同判定，Runweft 创建的独立原生 root 仍按子角色处理。

基础路径以当前工具响应或 wait 结果提供结构化任务身份、状态、报告及成果引用。继续评估宿主公开的消息注入入口，能复用 HAPI/宿主能力则复用；MCP notifications/tools/list_changed 只刷新工具，不当作任务通知。

主宿主退出后不恢复其会话或自动注入。临时 wait 取消与宿主退出不是同一个事件，不能因一个工具超时杀死执行；HAPI 中的任务和结果按原生命周期记录。

## 全局安装入口

通过显式 CLI 命令一键辅助全局安装、更新、检查及卸载 Runweft MCP，命令示意为 `runweft mcp install --global`。分别适配 Codex/Claude 的原生配置方式；仅维护 Runweft 条目，重复执行幂等，失败保留原配置及恢复依据。

CLI 基础提供稳定可执行路径、模式配置和数据位置，本 Change 负责客户端配置写入及真实连接诊断，不由最终发行 Change 临时补实现。全局注册不绑定安装时的项目 cwd。开发自动验收使用专用用户配置；不因该产品能力擅自修改当前用户的实际客户端设置。
