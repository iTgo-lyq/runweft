# npm Beta tag 发布计划

> 来源：./requirement.md
> 技术方案：./technical.md
> 状态：执行中
> 执行模式：逐任务提交

## 交付目标

同一可信工作流支持 stable latest 与显式 Beta tag/beta 通道，稳定官网继续服务已发布稳定版本。

## 依赖与风险

1.1.1 正式发布 Change 关闭后才实施。Beta 序号必须数值比较，恢复回执必须保留通道，实际 npm 参数不得回落到 latest。只配置/验证流程，不公开首个 Beta 包。

## 任务

### T1 实现 Beta 通道并保护稳定路径

- 状态：已完成
- 交付：严格版本/标签识别、beta/latest 参数、跨通道前进/回执校验、公开 dist-tags 与 latest 不变确认、CLI 共用门禁，以及仅开发分支 Beta 官网跳过逻辑。
- 依赖：1.1.1 Change 已关闭；本 Plan 完成一次 iclaude 只读评审并独立判断。
- 验收：稳定规则保持，Beta 明确使用 beta 参数且上传前后实际核对 latest，原上传/恢复与精确依赖规则保留。
- 验证：聚焦标签/通道/参数/数值比较/恢复、dist-tags 及发布顺序测试，actionlint，根 typecheck/test；不修改程序版本、使用说明或 Skill。

### T2 文档与真实工作流预演

- 状态：已完成
- 交付：Beta 分支/版本/tag/安装/恢复操作说明与真实 main 的检查、OIDC 和无上传预演证据。
- 依赖：T1
- 验收：工作流配置已推送且相关 CI 通过，stable latest=1.1.1 保持；Beta 未实际上传的边界清楚。
- 验证：既有四平台与 npm 预演、稳定官网检查/生产；Beta 官网分支控制通过针对工作流的本地检查。

### T3 自动验收、Specs 同步与归档

- 状态：进行中
- 交付：发行/验收/官网当前事实、需求映射、完整归档和已推送的干净 main。
- 依赖：T2
- 验收：配置事实与仅本地验证的 Beta 门禁/参数/官网跳过、未取得的真实 Beta 上传证据区分，旧包/候选与历史归档不修改。
- 验证：Change/文档链接、git diff、最终远端与工作区状态。

## Plan 评审与独立判断

iclaude 只读评审 c7caebea-de42-4016-a0aa-7f3611693602 已完成，无额度耗尽或委派。采纳 Beta 同时高于 beta/latest、上传前后实际 dist-tags 验证、共用可测试参数/版本逻辑、仅开发分支官网跳过与本地/远端证据区分。恢复只读取同一 run 的新格式回执，不增加旧 run 兼容分支；使用说明/Skill 保持不变。评审后的 Technical 与 T1 验收已包含这些要求。
