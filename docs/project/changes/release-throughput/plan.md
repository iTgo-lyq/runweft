# 发布提速实施计划

## T1 公共候选读取可在总预算内恢复

元数据、主包和本平台 tarball 共用十分钟总预算，以最多五个并发请求读取元数据与标签。仅对传播 404、408、429、5xx 和网络中断重试，尊重 Retry-After；鉴权、URL、manifest 与摘要不符立即失败。临时下载通过完整 SHA-512 核验后再落为候选。记录次数与耗时，上传及 dist-tag 写入保持既有顺序。

验收：HTTP 夹具覆盖恢复、限流、流中断、总预算、不可重试错误、摘要不符和临时文件清理；现有发布及恢复测试通过。

## T2 稳定候选并行验收且完整门禁后才晋级

稳定正式发布在 beta job 保留核心、四平台构建和 service-package；access/storage/web 从公共 npm 下载、核验并解包同一候选，与四平台安装并行。晋级在工作流和脚本同时核对完整门禁。预检与 beta.N 仍在上传前验证四组。Linux x64 安装绑定精确版本，补齐页面 DOM 安装和包内内容检查；恢复已有候选仍运行新增门禁。

验收：门禁任一失败、取消或跳过禁止晋级；预检/预发行模式、完整 descriptor、候选程序摘要、已有 beta 恢复与控制提交差异均有定向测试；工作流静态校验及专用现场的候选集成通过。

## T3 官网接续与发布证据自动收尾

晋级稳定版后，以 main dispatch 接续官网并关联实际 run/attempt，限时等待真实完成。官网按当前 main、已晋级版本及并发规则部署，版本尚未晋级的普通 push 保留静态检查并等待；预发行不部署。自动验证唯一 URL、正式域名及三页桌面/手机，汇总阶段、候选、job/attempt、重试及耗时，供 Agent 复核；官网失败只恢复官网。

验收：未晋级、main 推进、独立官网变更、关联失败/超时、官网失败和域名校验失败均有夹具；现有发布与网页测试、actionlint、typecheck、根/Node 检查及必要浏览器验收通过。无新版本发布和生产部署，四平台真实 CI 与耗时收益留待下一次授权发行，报告中明确区分本地验证和远端实测。

## 执行顺序

按 T1 → T2 → T3 串行交付，每项独立验证后提交推送。三个任务共同覆盖 Requirement，均不改变产品源码、HAPI pin 或候选构建输入。
