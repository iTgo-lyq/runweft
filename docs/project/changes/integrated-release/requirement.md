产出包含可安装的版本化包、兼容 HAPI 版本、安装部署与诊断说明、逐项验收证据及真实限制。包可安装不等于已公开发布；npm/GitHub 等外部发布按既有授权执行，不把上传到公开注册表作为本地验收的隐含动作。

## 行为变化

### ADDED

#### `release/distribution`：一致的可安装版本

用户通过一个 Runweft 安装包与命令入口使用已承诺能力。候选版本固定兼容 HAPI 构建和所需平台资产，包含看板及全部领域命令，不依赖开发 checkout 中未打包的文件。沿统一 CLI 的部署方式提供本机/远端配置、升级、诊断与恢复说明。

#### `release/acceptance`：完整协作的实测证据

对同一候选版本验证 Codex/Claude Code 两种宿主与两种执行 runtime 的组合，覆盖本地共享、本地独立及远端独立 worktree。验证派生、结果读取、中断、进程关闭、session 续接或明确缺失后的历史重建、输入/输出附件、代码取回及看板状态。

用户已授权本次真实跨物理机器验证延期；远端功能本身仍完整交付，并以同机独立 Hub/多 Runner 自动验证协议与成果链路。真实跨机证据继续明确标记未执行，不以模拟替代或虚报完成。

异常验收覆盖未知执行不重复启动/投递、交付失败只重试交付、准备失败不启动、未封存成果保留。主宿主关闭后的恢复仍不在范围内。模拟、单机多进程与真实跨机器证据分开记录；缺少正式验收环境时保留未验证状态。

## 验收标准

- [ ] macOS 通过正式包安装路径完成安装、诊断与真实协作，不依赖开发源码路径。
- [ ] CLI 一键辅助全局安装两种客户端的 MCP，自动验证重复安装、其他配置保留和卸载恢复。
- [ ] 本地模式无需另部署共享 Hub；Hub 模式连接明确；配置示例、校验、有效值和路径查询可用。
- [ ] 持久数据集中于声明的位置，数据库、附件、托管工作区、日志和缓存的保留规则明确；重启不依赖临时目录。
- [ ] 机器/runtime 均为全局资源，agent 可全局或项目级；UI/CLI 和配置文件没有混淆三者。
- [ ] 本地与远端只需 Runweft 操作入口，不要求用户日常操作第二个 CLI。
- [ ] 两宿主 × 两 runtime × 三工作区模式的组合有可追溯验证；同机多 Runner 与真实跨机分别标注，真实跨机按用户授权延期。
- [ ] 保留 worktree 的后续轮次能继续使用现场；进程结束、成果交付和用户接纳分别表达。
- [ ] 附件、代码成果、HAPI 详情和全局看板在同一候选版本下联通。
- [ ] 关键失败场景通过，文档区分实际验证、源码证据和已知限制。
- [ ] 已承诺能力没有被降成占位、固定假数据或“后续版本再补”；配置与凭据沿用户既有约束处理。
- [ ] 安装、升级与回退验证沿原 Change 的数据兼容规则，不覆盖用户已有工作区、配置或 HAPI 数据。
