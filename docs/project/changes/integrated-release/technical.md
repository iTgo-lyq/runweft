# 完整发行技术方案

> 来源：[Requirement](requirement.md)、[Research](research.md)
> 状态：草稿
> 更新：2026-09-30

## 就绪性

以既有单 CLI、固定 HAPI、统一数据根和已实现协作接口做发行整合，不新增执行层或领域功能。产品范围继续沿用户授权；实施前必须完成 C11 看板验收。macOS 原生运行入口尚未确认，影响验收可执行性，因此本方案保持草稿、不提前创建或评审 Plan。

## 发行产物

首个完整发行使用 1.0.0，与阶段候选 0.1.0 区分；沿主 npm 包与 macOS/Linux arm64/x64 四平台包。源码开发工程继续 private，生成包移除 private:true；包描述与用户入口文档改为已验收的完整能力，未公开发布的事实保持明确。`package` 只构建并打包，不调用 npm publish、push 或创建 PR。

每个平台继续提供相邻 Runweft/HAPI 程序、HAPI 许可/NOTICE/工具许可及匹配源码归档；固定 HAPI revision 与二进制 hash 的现有核对继续生效。安装不需要开发源码或全局 Bun，MCP 只配置 Runweft 命令。未发布时可从平台 tarball 解包并直接运行 bin/runweft；常规 npm 安装仍需同时提供主包与平台依赖的 registry，不要求用户另装 HAPI。

在既有包 index 中记录 root 源码 revision、配套 HAPI pin、平台程序 SHA-256 和 tarball SHA-512，形成一个版本证据入口。集成验证使用这些已构建程序，证据保存同一 hash；验收期间若改产品代码，重新构建并重跑受影响组合，不用同为 0.1.0 的旧候选替代。

## 源码、部署与升级

干净源码顺序为 submodule 初始化、root/HAPI frozen install、类型/根测试、配套构建和发行包。CI 显式在 types/tests 前安装 HAPI 工作区依赖，沿已有四平台安装 jobs；不新增有权访问模型凭据的公共 CI 流程。

README 与使用说明统一入口：获取程序、init/start、MCP 全局安装、机器登记、runtime 登记与 Agent 定义各自独立，再进入共享/本地 worktree/远端工作区协作和看板。保留可复制配置、有效值与路径说明；删除已交付能力仍列为“后续”的过时描述。

发行整合不改变 schema v6。升级试验保留已验证的 0.1.0 程序与专用数据副本，先确认 1.0.0 能报告仍运行的旧版本并要求重启，再停服务、备份业务库/HAPI 数据/文件与必要源仓库，保留身份、任务、refs 和原生配置后升级并恢复查询。更高 schema 的现有拒绝不能改成静默降级；回退仅承诺经过验证且数据兼容的这组版本，不覆盖用户正式数据。

## 完整验收组合

| 维度 | 最终证据 |
| --- | --- |
| 安装与全局 MCP | 同一包的真实安装、重复安装、其他 MCP/原生配置保留、备份及卸载；专用 home，普通输出无秘密 |
| local 与 Hub | 独立配置/数据所有者、带/不带 Runner 的服务、诊断、重启和凭据/任务持久性 |
| 两宿主 × 两 runtime | 已安装候选通过原生 Codex/Claude MCP 发起任务；输入、派生、等待、报告、续接、停止事实与子 MCP 禁用 |
| shared / 本地 worktree / 远端 worktree | 每组合固定候选，附输入/输出；独立模式准备先于启动、实际保留现场与 Git 成果；远端以同机独立 Runner 自动验证并明确物理跨机未执行 |
| 控制与失败 | 真实审批/中断和停止；未知不重发、准备失败不启动、封存失败保留、交付重试不重跑模型沿领域已验收注入方式，不新建状态机 |
| 原生历史缺失 | 两 runtime 在专用历史为空的原生 home 下，先获得 HAPI 的精确 missing，再由业务重建历史；核对随机记忆、来源 round ID、新原生 ID、原生输入仅一次和停止，不删除原历史；现有编译产品已完成 Research 实测，最终候选沿同一路径验证 |
| 看板与成果 | 当前候选读取上述任务，代码/文件与执行分开、同源登录及真实 HAPI 会话详情；浏览器证据与 HTTP 检查分别归档 |
| macOS | 同一发行包的实际安装、诊断、MCP 与真实本地协作；只在取得可执行的 Mac 环境后运行，不以 Linux 或交叉编译结果代替 |

最终矩阵沿现有 smoke 脚本，补足缺失的组合和真实重建，记录候选 hash、原生版本、宿主/runtime/模式及证据路径。公共 CI 保持无模型；真实原生验收沿专用复制配置和当前机器已有认证，不转存凭据到 GitHub 或其他新服务。

## 依赖与收尾

- 看板：C11 尚待浏览器入口或用户允许的替代浏览器，完成信号为实际页面断言、候选安装及 Requirement 映射通过并归档；此 Change 不接手未完成页面。
- Mac：需要当前主机可达的专用 SSH 入口，或把任务执行环境切到已具备原生登录的 Mac。当前仅能发现本地项目，没有命令连接；已询问用户。完成信号为在该主机执行程序并取得平台/原生版本，再运行已安装候选的自动验收。
- 发布：目标为可发布产物，不自动发布。最终交付包、hash、兼容 HAPI、安装/配置入口与证据；实际 push/npm publish 另依明确授权执行。

通过完整矩阵后同步 release/distribution 与 release/acceptance Specs，引用各领域事实，归档本 Change。环境或失败项仍未解决时不能把“编译成功”写成完整交付。
