# 技术方案

取消 Promise.race 中落败的截止计时器，使用 finally 清理，保持原错误与 SIGTERM/SIGKILL 语义。用独立进程退出时延的回归验证证明不会残留保活计时器，并覆盖失败与超时路径。

service-package 保留 standalone tarball/symlink 和 npm launcher 两套完整服务验收，只去掉直接平台目录那一次；两套现场本来独立，先顺序测量，再根据耗时判断最多两个并行。所有已启动验收必须等待结束、记录失败和独立证据。

先固定候选摘要测量 access/storage 原始及修复后时长。若剩余串行开销显著，storage 配置三份、access 两份固定用例集合；完整组入口保留。分片在不同 GitHub runner 独立安装依赖、下载并校验同一公开候选，不重新编译。用单一用例清单校验无遗漏重复，并以全部矩阵成功作为晋级条件。Mac Intel 的安装和完整卸载仅在变成关键路径且测得净收益时拆开。

磁盘准备记录可用量，在构建前确保足够空间，仅不足时清理托管镜像中的预装 SDK；不依赖未验证的绝对节省值。记录关键阶段磁盘快照以校准余量。npm 包上传顺序、公开可见性和散列校验不变。

验证分层：生命周期/调度失败边界测试 → 同候选前后测量 → 分支 CI 完整核心检查和受影响集成 → iclaude 独立复核 → 归档合入 main → 新版本正式发布。估计仅是目标：同传播约 25–27 分钟，最终以实际记录替代。
