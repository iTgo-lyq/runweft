# 任务附件与持久交付

> 状态：草稿
> 规模：大型
> 更新：2026-09-29
> 确认依据：输入和输出附件集中管理，启动前可准备输入，成果不能只给远端路径。存储实现与保留策略为草案。

## Review 导读

提供独立于活跃 agent 会话的文件上传、授权引用和取回能力，供本地及远端任务复用。任务归属由调用方提供并校验，本 Change 不负责创建任务、执行终态或 Git 提交语义。

方案讨论见 [Design](design.md)。HAPI 已有上传和 scratchlist 存储，可评估复用底层能力；需要新增的是任务附件生命周期。

先复用 HAPI 存储、下载与默认访问规则，仅补启动前输入和任务成果所缺的关联/保留能力。不以“附件中心”为由再建一套通用文件服务或独立权限系统。

## 独立验收与交付边界

文件对象可在没有活跃 agent 的情况下上传、校验、读取和保留；使用阶段 2 已有共享协作验收启动前输入及输出登记，不依赖独立 worktree 或远端。只有对象 CRUD 测试通过，不足以替代任务附件组合验收。

本 Change 拥有附件 CLI/必要 MCP 操作、任务输入/输出接入和保留引用；不拥有 Git 对象语义或委派状态。公共工作区能力只接收已经落地的输入，附件代码不反向调用 worktree 来决定是否允许上传。

## 行为变化

### ADDED

#### `artifacts/inputs`：启动前输入

通过统一 Runweft 入口提交和引用附件，保留主体、主工作区、委派或轮次的归属。子会话启动前可下载并验证输入；重试不能产生含糊的重复对象。

#### `artifacts/delivery`：离线可取回的输出

输出完成校验并持久化后，才声明可取回。远端会话离线不影响已交付对象；上传失败不能用本地绝对路径充当下载地址。清单可表示部分交付，补交产生新版本。

#### `artifacts/retention`：权限与引用保留

ID 或 hash 不是读取权限。文件名不直接成为存储路径，拒绝路径逃逸；执行配额检查并保护仍被任务、结果或恢复基线引用的对象。具体大小与期限由部署策略确定，不在此虚构默认值。

## 验收标准草案

- [ ] 无活跃 HAPI 会话时仍能上传、引用和读取已授权输入。
- [ ] 本地共享委派在启动前取得必需输入，输出可取回；必需输入失败阻止启动，输出失败不重新执行任务。
- [ ] 错误 hash、未完成上传和配额不足不能形成“可取回”状态。
- [ ] 断线或发布回执丢失后能查询或重试同一操作，已发布内容不可被悄悄改写。
- [ ] 远端离线后已交付成果仍可下载；无权限或路径逃逸请求被拒绝。
- [ ] 引用中的对象不被普通清理删除，删除后返回明确失效状态。
