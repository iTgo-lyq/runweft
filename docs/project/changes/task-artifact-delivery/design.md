# 任务附件与交付记录设计

> 状态：草稿
> 来源：[本 Change 需求](requirement.md)、[跨 Change 架构](../../architecture.md)
> 本文件保留需求阶段方案讨论，不表示 Technical 已确认。

## 1. 附件存储与运行模式

附件在创建子会话前已经可以存在，归属于协作主体/工作区和委派，而非只能挂在活跃 HAPI 会话下。本地模式使用受控本机持久存储，Hub 模式使用所选 Hub 的文件能力；沿统一配置定位，不在临时目录放唯一副本。

优先复用 HAPI 已有文件存储与传输机制，按用途区分输入、报告、代码传输包及输出。先核对其流式上传、校验和发布行为，只为缺失部分增补；不预设独立对象服务、重复存储或新的权限体系。

- 上传返回确认的 artifactId 和 hash；只成功写入临时字节不能在报告中标为已交付。
- Agent 可用 `runweft artifact …` 上传指定输出，并用 `runweft result …` 登记成果候选。登记不会改变 HAPI 执行终态，也不提前封存仍在写的 Git 工作树。
- 收集器只处理显式登记的文件及约定输出目录，不递归上传整个工作区、home 或依赖目录。输入附件已在准备阶段就位，不需要等会话建立再走 HAPI upload。
- 文件显示名称与存储键分开；规范化目标路径，不允许通过 `..`、绝对路径或逃逸 symlink 读取/覆盖别的任务文件。
- 访问沿 HAPI 已有主体/namespace 默认规则，任务归属用于成果关联；不新增任务隔离权限。知道 ID 或 hash 不替代现有认证，持久引用不依赖临时下载 URL。
- 对象完整性校验、权限校验和大小/配额检查由程序完成。配额不足时保留本地候选并明确交付失败，不把本地路径当作可下载链接。

HAPI 已有会话上传和 Hub scratchlist 附件存储；应复用合适的底层文件校验/存储实现，但不直接把任务成果伪装成某个会话的 scratchlist。两者的所有权、启动前使用和保留期限不同。

## 2. 上传与发布

文件上传与结果清单发布分开。上传中的对象不可下载；完成长度、hash、权限和配额校验后才产生持久可用引用。相同请求身份的重试应返回同一对象，不确定是否发布时先查询，不重新运行任务。

结果清单引用不可变对象；补交通过新版本体现，不能悄悄改变已经引用的内容。清单中逐项说明哪些必需附件未交付，不能用一个成功上传掩盖其他失败。普通报告不要求包含代码或绑定活跃 HAPI 会话。

委派与轮次的业务关联由[委派生命周期](../delegation-lifecycle/requirement.md)维护；本 Change 只校验已授权的归属信息，不创建委派或推断任务终态。Git bundle 可复用对象传输，但它的前置对象、引用与祖先关系由[远端代码回收](../remote-result-delivery/requirement.md)验证。

## 3. 保留与删除

附件保留期限独立于 HAPI 会话在线状态。可删除条件需要检查活跃输入、结果清单与恢复引用；普通缓存清理不得删除仍被引用的对象。删除后读取返回明确的失效状态。

配额、保留期限、备份和访问凭据沿[统一部署设计](../unified-cli-and-deployment/design.md)配置。调用方取回确认不等于业务验收，不能单凭一次下载删除唯一副本。

## 4. 验证边界

可在没有 agent 会话的情况下验证：上传后校验、启动前下载、重复请求、断线重传、跨主体拒绝、路径逃逸拒绝、配额不足与删除保护。HAPI 已有上传与 scratchlist 存储的证据见[共同调查](../hapi-subagent-foundation/research.md#远端设计补充证据)；本 Change 尚未实现上述行为。

## 5. 领域接入边界

本 Change 自行实现文件命令与既有委派的输入/输出接入，复用阶段 2 的准备条件、结果关联和查询，不修改委派原生执行状态。无需独立 worktree 即可用共享任务完成组合验收；本地独立和远端只消费已经落地的输入及持久输出引用。
