# Hub 前端交互与样式重构

## 目标与规模

将现有 Runweft Hub 后台重构为现代、易读、易操作且冗余信息少的真实产品界面。保持蓝色主题，允许克制的明暗和渐变；液态玻璃仅用于导航、切换器和浮层，正文与表格保持清晰实底。

用户在 2026-10-19 明确要求将本 Change 升级为前端交互与样式重构的 large Change。本次范围从独立原型扩展至真实 Hub 的完整交互与样式。涉及约千行现有浏览器代码、共享应用壳和七组端到端交付，按 large 组织；保留 ID `hub-glass-prototype`、既有分支和 T1 原型成果。

已发布的[蓝色轻玻璃原型](https://pub-cc623a99ce8e4606a3491cc2d4b4436c.r2.dev/runweft/b149b044b09411002b131c5b1f80eca821e0d8980ae4d6366f28c8b5bc137dc3/tasks/index.html)及八入口固定引用作为设计参考。原型的内存流程、示例数字与演示成功不能代替真实产品行为；本轮升级不补记用户已验收原型或新需求。原型后的业务补齐应先更新相应原型场景并提供预览。

## 范围与行为

| 能力 | 重构目标与必须保留的真实行为 |
| --- | --- |
| 应用壳与基础交互 | 统一蓝色主题、字阶、间距、导航、空间切换、按钮、表单、弹窗、抽屉与状态提示。桌面固定导航，手机收起侧栏后直接呈现内容；当前身份、空间和页面始终清晰。低频 ID/配置/治理动作渐进展开，关键风险、权限与恢复提示不能因精简而隐藏。 |
| 身份与空间 | 覆盖领取/导入身份、备份与轮换 token、显示名称、显式选择/创建空间和 CLI 连接确认。保留未知结果恢复、token 备份顺序及 origin/机器/核对码确认；刷新、401、断网均不自动创建替代身份。 |
| 任务与交付 | 重构列表、现有服务端筛选/分页、轮次详情、报告阅读和分页、文件/代码状态与维护说明。区分运行、需要处理、失败、未知、停止和留存，不把未知简化为可重发；实际原生详情/审批/文件入口可达。 |
| 机器与 Runtime | 以清晰列表或卡片呈现所属人、在线、登记、凭据、空间关联/停用与可用原因。保留现有管理、检查、分享与治理权限；本机初始接入和凭据轮换继续由 Agent/CLI 处理。 |
| Agent | 完整支持定义、模型/推理等已有字段、版本条件编辑、历史、分享和治理。私有内容遵循服务端权限；发生版本冲突明确提示并刷新，不覆盖他人更新。 |
| 仓库与个人选择 | 保留仓库名称/别名/登记及本人只读 checkout；全局和仓库级 Agent/Runtime 选择、失效选项、清除、真实解析预览可用。失效选择保留 ID 与原因，不自动回退。 |
| 成员与邀请 | 重构成员角色、邀请生成/撤销/接受、移除与退出空间。操作取决于服务端权限和角色约束；不引入邮箱账号体系或从原型示例推导新权限。 |

范围聚焦 `/hub` 及其同源前端资源、原型和必要构建/浏览器验证。官网、HAPI 内置会话 UI、launcher/runtime 协议、业务编排、后端持久化格式及模型接入不在本次重构范围。停止、续接、取回、清理仍由 Agent/CLI 执行；前端提供真实入口和说明，不新增自动业务编排器。

## 验收

1. 八个入口都由真实 Hub 接口驱动，完整现有能力可达；用真实 API 的专用测试数据验证各角色及成功/失败路径，产品包不带原型 mock、演示审批或固定统计数。
2. 视觉与信息层级以固定原型及包内 DESIGN 为参考，保持蓝色和克制的玻璃效果。阅读区文字、状态、主要动作清晰，低频信息按需展开；提供同场景前后截图和功能对应说明。
3. 检索、计数和分页只声明实际范围。保留 workspace、parent、status、page/limit 的现有契约；如提供文本筛选，明确仅筛已加载页面。不将当前页统计伪装成全量状态汇总，也不宣称已有跨资源全文搜索。
4. 空态、首次失败、刷新失败、离线、结果未知、无权限、凭据过期和并发冲突都有准确提示与可执行的恢复方向。刷新失败保留已有成功内容；身份/空间切换清空旧视图，迟到响应不能恢复前一上下文。
5. 保留创建请求 ID/内容摘要及回执核对、轮换恢复、详情轮次/报告位置/展开状态、文本报告安全呈现，以及短 JWT 原生会话授权边界。凭据不进入 URL、普通日志、DOM 属性或其他站点请求。
6. Playwright 覆盖桌面 1440×1000、平板 834×1112、手机 390×844，覆盖全部入口和关键操作；无页面横向溢出、不可达控件或浏览器错误。键盘导航、可见焦点、弹层焦点恢复、Escape、触摸操作及减少动态效果/透明度偏好可用；不单凭截图宣称完整无障碍合规。
7. 类型、核心回归、构建及所需工具/文档/工作流检查按 ci-scope 执行，聚焦 Web 集成验证真实授权与恢复。large 关闭前必须进行上下文隔离的独立评审并记录证据，由用户验收产品效果后同步 Specs、归档和合入协作分支；main 发布另按明确指令。
