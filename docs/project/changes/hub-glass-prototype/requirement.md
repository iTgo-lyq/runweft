# Hub 前端交互与样式重构

## 目标

Hub 是用户在浏览器中登录账号、确认 CLI 连接，并管理空间、任务、机器、Runtime、Agent、仓库、个人选择和成员的后台。现有页面把表单、事实列表和折叠区顺序堆叠，主要信息与 ID、配置、治理动作同等权重，手机上更难找到下一步。本 Change 在保留全部现有能力的前提下，重做 Hub 的信息层级、布局与交互，形成安静、内容优先、易读易操作的蓝色主题界面。

分两段推进：

1. **原型设计（当前交付）**：在项目原型包完成 Hub 主体页面的交互原型，经用户明确验收后作为产品重构的设计依据。
2. **产品重构**：原型验收后再编写技术方案与计划，然后实施真实 Hub。原型验收前不修改 `src/hub`。

2026-10-19 用户要求回滚此前预定的产品实施计划（原 T2–T8），先完成原型。基线为当前 develop 的 Hub：账号密码注册/登录、CLI 连接确认和账号设置已经上线，原型包已有 `account-onboarding` 入口。T1 交付的[蓝色轻玻璃原型](https://pub-cc623a99ce8e4606a3491cc2d4b4436c.r2.dev/runweft/b149b044b09411002b131c5b1f80eca821e0d8980ae4d6366f28c8b5bc137dc3/tasks/index.html)和本分支此前的修改只作参考：它们早于账号改造，身份页仍是领取、导入、备份 token 的旧流程。

## 设计方向

风格参考两份材料：用户提供的 Craft 视觉与交互总结（由另一 Agent 整理，未逐项对照 Craft 产品核实），以及 Apple 对 Liquid Glass 的定位——控件和导航是浮在应用之上的独立功能层，并向内容让位（[Apple Newsroom：Apple introduces a delightful and elegant new software design](https://www.apple.com/newsroom/2025/06/apple-introduces-a-delightful-and-elegant-new-software-design/)，2025-06-09 发布，2026-10-19 读取）。结合 Hub 的后台属性，落地为：

| 方面 | 要求 |
| --- | --- |
| 气质与层级 | 内容是视觉中心。侧栏融入窗口背景，主内容区是一块完整、清晰的实底表面；用低对比背景、细边界和留白分区，少用分割线。导航、内容和辅助面板层次明确，辅助面板随当前操作出现。 |
| 色彩 | 冷调中性色做框架，蓝色只用于选中、主要操作、焦点和链接。成功、警示、失败等状态用低饱和色，并配文字和图标。 |
| 液态玻璃 | 只用于浮在内容之上的功能层：顶部工具栏、平板与手机的浮动导航、空间切换器、菜单、弹出层和抽屉。表格、报告、表单等阅读与输入区保持实底；不玻璃叠玻璃，不在每张卡片上重复光效。浏览器不支持背景模糊或用户开启减少透明度时退回不透明表面；任何情况下文字对比优先。 |
| 字体与组件 | 使用系统无衬线字体，不请求外部字体；用字号、字重和间距建立层级，照顾中文、中英混排和长报告的阅读。圆角随组件尺寸递增、嵌套时同心；按钮、列表、标签、输入框和菜单节奏一致，少边框、少装饰；图标笔画统一。 |
| 交互与反馈 | 常用操作直接可达；ID、配置、治理和危险操作等低频内容收进上下文菜单、弹出层或辅助面板，但风险、权限与恢复提示不能因此隐藏。悬停、焦点、选中、按下、禁用和完成状态清晰可辨，“选中”与“打开”明确区分。状态同时用文字、图标和颜色表达。动效短促、连续，只用来解释展开、切换和布局变化。空态和错误提示简洁，并说明下一步。 |
| 深色模式 | 浅色与深色一起设计（需求 Q2），默认跟随系统，也可在演示工具条切换。深色重新处理表面层级与文字对比，不是简单反色；手机可用纯黑底。 |

Craft 中依赖文档产品的部分按 Hub 实际取舍：Hub 没有用户文档，主要阅读面是任务报告，因此不做封面、自选字体或个性化背景；就地编辑只用于已有接口支持的改名；快捷键限于导航、聚焦筛选和开关浮层；没有批量接口，不做多选与批量操作。

[shadcnuikit](https://shadcnuikit.com) 提供布局思路。它的条目是 React/Next.js/Tailwind 源码，原型只借鉴布局、信息分组和状态处理，沿用原型包的原生实现，不安装或复制其组件源码。下表列出各页的候选条目，绘制时逐个查看后选定，最终取用记录在原型包 DESIGN.md。

## 原型覆盖

所有入口共用一个工作台壳：顶部栏、当前身份与账号菜单、空间切换/创建/接受邀请、资源导航、手机导航，以及“让 Agent 帮我接入此 Hub”说明。产品中的身份与空间位于工作台侧栏，不是独立页面，因此原 `identity` 入口并入工作台壳（需求 Q5 已据此撤回）。

| 入口 | 主体内容与主要交互 | shadcnuikit 候选参考 |
| --- | --- | --- |
| 账号与首次连接 | 注册与登录切换、忘记密码（重置码）、请求过期；CLI 连接确认（核对码、设备、默认空间）与“已授权”结果；账号设置（显示名称、登录环境与撤销、改密码、全端退出） | `auth/login`、`auth/register`、`auth/forgot-password`、`onboarding-screens`、`pages/settings` |
| 任务（默认页） | 列表与状态、工作区、父任务筛选和分页；打开详情查看轮次、分页阅读报告、文件与代码状态、原生会话入口及维护说明 | `apps/tasks`、`apps/mail`（列表与阅读区）、`project-detail`、`dashboard-ui/tables` |
| 机器 | 所属人、在线/登记/凭据状态、空间关联、分享与治理；接入和凭据轮换只给 CLI 指引 | `dashboard-ui/tables` |
| Runtime | 同机器，另含工具类型、空间分享与停用、检查结果 | `dashboard-ui/tables` |
| Agent | 定义列表与详情、完整字段编辑、版本历史、分享范围与治理 | `apps/notes`（列表与内容区）、`pages/settings`、`dashboard-ui/form-layouts` |
| 仓库 | 名称、别名、登记状态，本人 checkout 只读 | `dashboard-ui/tables` |
| 我的选择 | 空间默认与仓库级的 Agent/Runtime 选择、失效项、解析预览 | `dashboard-ui/form-layouts` |
| 成员与邀请 | 成员与角色、生成邀请（一次性 token 展示）与撤销、移除成员、空间改名、退出空间 | `pages/users`、`apps/api-keys`、`dashboard-ui/modal-dialogs` |

8 个入口全做（需求 Q4）。每个入口做默认视图和主要操作，不逐一复演全部增删改弹窗。通用状态用演示工具条切换：正常、空数据、首次加载失败、刷新失败（保留已有内容）、离线或结果未知、凭据过期；另可切换 owner、admin、member 三种角色，展示随权限出现的操作。空态与错误参考 `pages/empty-states`、`dashboard-ui/empty-state` 和 `pages/error`。

## 原型须遵守的产品事实

原型只表达产品已有或纯前端可实现的能力，不新增后端能力，也不用示例数据暗示不存在的接口：

- **账号**：使用用户名加密码，界面不出现 token 输入、备份、下载或轮换；“已授权”表示连接已确认，不代表本机执行已就绪。依据：[身份](../../specs/identity/spec.md)、[Hub 页面与任务总览](../../specs/dashboard/spec.md)。
- **任务**：状态分为进行中、需要处理、执行未确认、已完成、失败和已停止，另有文件交付与代码封存状态；“执行未确认”不能表达为可以重发。服务端筛选只有 workspace、parent、status 和 page/limit，文本筛选只能作用于已加载页面并写明。没有聚合接口，不显示全量状态统计。停止、续接、取回和清理由 Agent/CLI 完成，页面只提供任务 ID 与说明；原生会话、审批和文件在 HAPI 页面的新标签中打开，原型只做入口。
- **资源、Agent、仓库与选择**：可见内容和可用操作由服务端权限决定，原型用角色切换演示差异，不推导新权限；失效选择保留原 ID 与原因，不自动回退；机器登记与凭据轮换只在目标机器上由 Agent/CLI 完成。依据：[资源](../../specs/resources/spec.md)、[Agent](../../specs/agents/spec.md)、[仓库](../../specs/repositories/spec.md)。
- **成员**：遵守 owner、admin、member 的权限差异与最后一位 owner 的限制；邀请 24 小时内只能使用一次，token 只在生成时显示。依据：[空间](../../specs/spaces/spec.md)。
- 不出现全局全文搜索、通知中心、批量操作等当前没有接口支撑的功能。

## 不在本次范围

- 官网、HAPI 内置会话 UI，以及原型验收前对 `src/hub` 的任何修改（需求 Q1）。
- 产品前端技术选型：沿用原生栈还是迁移框架，留到原型验收后的技术方案决定（技术 Q3）。原型沿用原型包现有技术，自包含、只用内存数据，不发外部请求、不用持久存储。
- 新的后端接口或数据格式。

## 验收

### 原型阶段（当前）

1. 覆盖范围内的入口都能从共享工作台壳打开，默认视图与主要操作可用内存数据演示，刷新或重置后恢复初始状态。
2. 视觉符合设计方向：蓝色只做强调，玻璃只在功能层，阅读与输入区为实底。原型包 DESIGN.md 更新为唯一视觉规范，写清浅色与深色的 token、玻璃使用规则、字阶、圆角和动效。
3. 演示工具条能切换上述通用状态和三种角色，各入口显示对应提示与下一步。
4. 界面和文案不与“原型须遵守的产品事实”矛盾。
5. 桌面 1440×1000、平板 834×1112、手机 390×844 的浅色与深色截图和交互检查都通过：无横向溢出、不可达控件、浏览器错误、外部请求或存储访问；键盘导航、可见焦点、Escape 关闭浮层并恢复焦点、手机触摸、减少动态效果和减少透明度均可用。不单凭截图宣称完整无障碍合规。
6. 每个入口附与当前 develop 原型的同场景对照截图，并说明主要变化。
7. 从干净、已推送的提交构建并发布固定预览，登记到本 Change 和原型清单。用户明确验收通过后，才开始编写产品重构的技术方案。

### 产品重构阶段

原型验收中确定的布局与交互调整，在编写技术方案前补入本节。

1. 真实 Hub 实现已验收原型的布局与交互，全部现有能力可达并由真实接口驱动；产品包不含原型 mock、演示状态或固定统计数。
2. 保留现有恢复与安全行为：创建请求 ID/摘要与回执核对、身份或空间切换后旧响应失效、刷新失败保留已有内容、连接确认的 `#connect=` 入口、原生会话短 JWT 边界；凭据不进入 URL、DOM 属性或日志，不放宽 CSP。
3. Playwright 在三种尺寸覆盖全部入口与关键操作，按 ci-scope 完成类型、测试、构建与集成检查。关闭前进行上下文隔离的独立评审，用户验收产品效果后再同步 Specs、归档并合入协作分支。
