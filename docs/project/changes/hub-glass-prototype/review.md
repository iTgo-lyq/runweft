# 重构规划核对

本记录来源于现有 Specs、产品源码与原型实现的对照，覆盖本轮范围升级的具体风险；不作为尚未实施的产品改动的独立评审或验收结论。

## R1 原型交互不能替代产品恢复与授权

原型仅有内存状态；产品的创建请求 ID/摘要/回执核对、身份轮换恢复、服务端权限与上下文代次均影响真实操作正确性。依据为 dashboard/identity Specs 与 `src/hub/console.ts`、`src/hub/app.ts`。新版 Requirement、Technical 和 T3–T8 已明确保留这些行为，实施评审需逐段核对，不能仅按截图覆盖旧逻辑。

## R2 检索和统计必须对应真实数据范围

原型的八条示例和本地搜索不证明已有全量状态聚合或跨资源检索。dashboard Spec 的 overview 参数严格限定；`src/hub/tasks-page.ts` 使用分页接口。新版方案要求明确本页过滤和服务端筛选，缺少聚合端点时不提供假精确汇总；T4 验证统计、分页与异常状态。

## R3 液态玻璃与快速导航需要适配产品安全边界

产品 CSP 只允许同源脚本/样式，身份接入使用 `#connect=<UUID>`，原生会话通过独立标签页短 JWT。原型的内联资源、模拟审批和导航不能直接作为产品实现。T2/T3/T4 分别覆盖静态打包、连接确认与原生入口，读取区保持实底及清晰对比度。

## R4 原型交付记录与大型产品重构分开核对

保留 T1 和固定预览作为可追溯成果。需求范围扩展应回到 requirement，清除旧需求/技术/计划确认、关闭结论与等待项；新产品任务独立登记，不能沿用原型通过结论关闭重构。新版 rework 的规模参数应同时验证清理旧确认和保留已完成任务/预览的行为。产品实施结束后仍需独立审阅整个产品差异、需求对应与测试证据。

## 本轮升级差异的独立评审

2026-10-19，由未参与本轮写入、且未继承实现对话上下文的独立 Agent 只读核对工作树相对 HEAD 的升级差异。覆盖 rework 规模参数、7 项命令测试、JSON 状态保留、Requirement/Technical/Plan 与现有 Specs 的对应，以及 Review 对评审边界的说明；未发现需要修复的问题。

独立执行的命令测试、文档/工作流/diff 检查与旧状态对比断言通过。文档检查延后了 54 条未初始化 HAPI 源码链接。本轮仅评审流程和规划升级，未评审未来产品实现、真实接口与视觉效果；large 产品重构完成后的独立评审要求继续适用。
