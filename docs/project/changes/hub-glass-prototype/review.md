# 重构规划核对

本记录来源于现有 Specs、产品源码与原型实现的对照，覆盖本轮范围升级的具体风险；不作为尚未实施的产品改动的独立评审或验收结论。

## R1 原型交互不能替代产品恢复与授权

原型仅有内存状态；产品的创建请求 ID/摘要/回执核对、身份轮换恢复、服务端权限与上下文代次均影响真实操作正确性。依据为 dashboard/identity Specs 与 `src/hub/console.ts`、`src/hub/app.ts`。新版 Requirement、Technical 和 T3–T8 已明确保留这些行为，实施评审需逐段核对，不能仅按截图覆盖旧逻辑。

## R2 检索和统计必须对应真实数据范围

原型的八条示例和本地搜索不证明已有全量状态聚合或跨资源检索。dashboard Spec 的 overview 参数严格限定；`src/hub/tasks-page.ts` 使用分页接口。新版方案要求明确本页过滤和服务端筛选，缺少聚合端点时不提供假精确汇总；T4 验证统计、分页与异常状态。

## R3 液态玻璃与快速导航需要适配产品安全边界

产品 CSP 只允许同源脚本/样式，身份接入使用 `#connect=<UUID>`，原生会话通过独立标签页短 JWT。原型的内联资源、模拟审批和导航不能直接作为产品实现。T2/T3/T4 分别覆盖静态打包、连接确认与原生入口，读取区保持实底及清晰对比度。

## R4 原型交付记录与大型产品重构分开核对

保留 T1 和固定预览作为可追溯成果。需求范围扩展应回到 requirement，清除旧需求/技术/计划确认、关闭结论与等待项；新产品任务独立登记，不能沿用原型通过结论关闭重构。新版 rework 的规模参数应同时验证清理旧确认和保留已完成任务/预览的行为。产品实施结束后仍需独立审阅整个产品差异、需求对应与测试证据。

## 2026-10-20 产品实现独立评审

Claude Code 的产品独立评审因会话额度中断，未形成结论。接手后另由未参与实现、不继承实现对话的独立 Agent 只读评审 `origin/develop...7279b70` 的完整差异，并继续复核 T17 的修改。范围包括需求、方案、执行与验证证据，自有 UI 库、Hub 八入口及账号/连接、原型隔离、构建/CSP、CI 选择，以及本 Change 涉及的 SpecTrail 流程修改。

| 问题 | 影响与修复 | 回归证据 |
| --- | --- | --- |
| P2 根会话读取未隔离迟到结果 | 旧刷新或深链接读取可恢复旧空间；增加根读取代次、上下文代次与同步会话引用，只有最新有效结果可更新页面和 sessionStorage | Chromium 挂起 A 的读取，切 B 后放行 A，页面与保存空间保持 B；深链接同样覆盖 |
| P2 JWT 等待期间仍可发送旧空间写入 | 仅在等待 JWT 前核对上下文不够；取得 JWT 后、发送资源请求前再次核对，错误解释同样拒绝旧上下文 | 单元测试证明切换后不发送 DELETE；旧 401 不使新账号过期 |
| P2 隐藏本人全部角色控制 | 存在另一所有者时，服务端允许本人降权，但页面以 self 隐藏；改为消费 permissions，成功后刷新根身份与权限 | 真实 Hub 两位所有者，第一位降为管理员，页面与角色控制同步；本人移出仍不显示 |
| P2 CI 未选择前端纯逻辑单测 | 单改 `src/hub/web/api/*` 或 `route.ts` 未选择 core；补上选择规则 | CI 范围测试覆盖 API、HTTP 与路由路径 |
| P3 手机导航关闭后焦点丢失 | Escape 或关闭按钮使焦点落在 body；关闭时归还导航按钮，已导航到标题的焦点保留 | UI Playwright 覆盖 Escape 与按钮关闭后的焦点 |

另去掉两处文件末尾多余空行。

上下文修改的独立复验进一步发现连续选择第二个空间会被旧代次拒绝，以及空间切换期间退出时旧回调失效。显式空间选择可以覆盖尚未完成的前一次选择，立即重建当前页面回调；账号退出、改密码、退出全部环境统一按账号处理，发起时使之前根读取失效，结果不受空间切换影响。浏览器回归覆盖连续选择、退出先返回及空间读取先返回两种顺序，避免仅验证一种时序。

卸载 CI 修复另行核对：仅接受已确认不存在或僵尸状态的进程；无法确认启动标记的存活进程仍拒绝，不扩大可终止进程范围。独立执行核心与卸载竞态测试 12 项、UI 检查 18 项、CI 范围测试 4 项全部通过，diff 检查通过。

账号操作的独立复验还发现，过期请求落到成功文案会错误宣称密码已更新或全部环境已退出。已将 expired 作为独立失败出口，清除失效登录并显示“登录已失效”，仅成功响应显示操作成功。真实服务回归在后台先撤销当前凭据，再提交两种操作，验证提示与旧密码仍有效。

最终独立结论：未发现剩余有效产品问题。独立 Chromium 的 10 个定向场景通过，包含退出的两种响应顺序、改密码/全端退出跨空间成功与失败、旧响应不影响新账号，以及过期请求不误报成功。评审全程只读，浏览器复现使用从源码另建的临时 bundle；最终真实 Hub 回归和 CI 由接手实现 Agent 核验。视觉证据沿用 T15 已记录的 48 对对照，本轮没有宣称重新进行跨浏览器或真实模型验收。
