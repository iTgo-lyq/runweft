# Hub 前端重构技术方案

依据[需求](requirement.md)的产品重构阶段：按已验收原型重做 Hub，并建立长期维护的自有 UI 库。视觉规范以原型包 [DESIGN.md](../../../../packages/prototype/DESIGN.md) 为准。

本稿按 Q6、Q7 的推荐方案编写，两题待用户回答；回答若与推荐不同，受影响的是组件实现方式和原型包结构，目录划分、构建交付、数据边界和测试路径不变。

## 现状

| 事实 | 依据 |
| --- | --- |
| Hub 浏览器端由静态骨架 `page.html`、46 行 `style.css` 和 7 个 TS 模块（约 1500 行）组成，命令式 DOM 操作；页面以 type-only import 复用服务端类型，如 `TaskOverview`、`AgentView` | 已验证：`src/hub/*.ts` |
| `page.ts` 在请求时用 `Bun.Transpiler` 逐个转译模块，不打包；CSP 为 `default-src 'none'; script-src 'self'; style-src 'self'; connect-src 'self'` | 已验证：[page.ts](../../../../src/hub/page.ts) |
| 交付物是 Bun 编译的单二进制，页面资源以文本导入嵌入；集成测试使用 `dist/runweft` | 已验证：`scripts/build.ts` |
| 原型包约 2700 行原生 JS：`h()` 组件、CSS token、内存接口和演示控制，构建为自包含 HTML | 已验证：`packages/prototype/src` |
| 6 个 Playwright 脚本约 100 处按元素 id 选择（`console.ts` 42 处、`console-tasks.ts` 22 处、`web-identity.test.ts` 20 处等） | 已验证：`test/integration` |
| 与 CLI 的入口契约：`/hub#connect=<id>`，`task show` 生成 `/hub#space=…&task=…&round=…`，原生页失效跳回 `/hub#native-expired` | 已验证：`src/tasks/commands.ts:67`、`src/hub/native-page.ts` |
| HAPI 网页使用 React 19.2、Radix 和 Tailwind 4；本次不改 HAPI | 已验证：`hapi/web/package.json` |

## 关键取舍

### 技术基础（技术 Q6，待回答）

| 方案 | 得到什么 | 代价 |
| --- | --- | --- |
| **React + 自有组件（推荐）**：组件全部自己写，弹窗用原生 `<dialog>`，菜单与弹出层用原生 Popover API，样式用 CSS 变量 token | 声明式更新：刷新数据时自然保留输入、滚动位置和展开状态，正好对应需求里的“刷新失败保留已有内容”；与 HAPI 同一框架；组件代码完全归我们 | 运行时约 58KB（gzip）；跟随 React 升级 |
| **原生 TypeScript 组件库**：把原型的 `h()` 组件提炼成库 | 零运行时依赖，体积最小 | 状态更新、列表复用、焦点保持都要自己维护，页面越复杂成本越高；原型整页重绘的方式不能直接用于产品 |
| **React + Radix/shadcn + Tailwind** | 生态最大，可直接搬 shadcnuikit 的代码 | 依赖链长（Radix 十余个包加 Tailwind 构建链）；部分组件锁滚动时会往页面插入 `<style>`，被当前 CSP 拦截，需要改成每次请求生成 nonce；我们的 token 要改写成 Tailwind 主题 |

推荐方案的可行性已用实验验证（Bun 1.4.3、React 19.2.3、Chromium，在临时目录完成，仓库固定的 Bun 1.4.2 在实施时复验）：

- `Bun.build` 打包 TSX 与导入的 CSS，生产模式下 React 部分约 183KB、gzip 后 58KB。
- 以 Hub 现有 CSP 响应头加载，浏览器没有报告违规；React 的 `style` 属性通过 CSSOM 设置，不受 `style-src 'self'` 限制。
- 原生 `<dialog>` 打开后焦点进入，Escape 关闭；Popover 点外部自动关闭。

第三种方案的 CSP 问题依据：Base UI 文档说明其组件为锁定滚动注入 `<style>`，严格 CSP 下需要 nonce（[CSP Provider](https://base-ui.com/react/utils/csp-provider)，2026-10-19 读取）；Radix Dialog 依赖的 react-remove-scroll 使用同类机制，属合理推断，未找到 Radix 官方说明。

不随 Q6 变化的决定：

- 不引入 CDN、外部字体或运行时网络依赖；依赖版本精确固定在 `bun.lock`。
- 浏览器基线为近两个大版本的 Chrome/Edge、Safari 17 及以上、Firefox 125 及以上，以支持 Popover API、`<dialog>`、`color-mix()` 和 `backdrop-filter`（合理推断，实施时以 MDN 兼容表复核）。浮层定位用少量脚本，不依赖 CSS anchor positioning。
- 不引入 Tailwind、Radix、数据缓存库或 Storybook，理由见[冗余审查](#冗余审查)。

### 原型与产品的关系（技术 Q7，待回答）

推荐原型包直接构建 Hub 前端页面，换上内存版接口和演示控制：

- 界面只有一份实现，原型和产品不会走样；原型数据按真实接口类型编写，自然遵守“原型须遵守的产品事实”。
- 新功能先在产品页面代码里做，数据走内存接口；后端就绪后接真实接口。
- 纯探索性的草图仍可在原型包里单独写页面，同样使用 UI 库。

代价是原型要遵守产品代码的结构和类型，演示控制需要从页面外部注入数据场景。另一种做法是原型独立实现页面、只共用 UI 库，原型更自由，但页面逻辑写两遍，长期会和产品出现差异。

## 代码组织

| 位置 | 职责 |
| --- | --- |
| `packages/ui` | 自有 UI 库：token、组件、交互行为、图标、组件目录页与说明。仓库内维护，不发布 npm |
| `src/hub/web` | Hub 前端应用：入口、工作台壳、路由、会话与空间上下文、接口层、8 个入口的页面 |
| `src/hub/page.ts` | 继续负责 `/hub` 路由与 CSP，改为提供打包后的单个 JS 与 CSS |
| `packages/prototype` | 原型：构建 Hub 页面，加内存接口与演示控制；探索页面 |

`src/hub/web` 放在服务端代码旁边，页面继续通过 type-only import 使用服务端类型，接口字段变化在类型检查阶段暴露。

### UI 库

- **token**：从原型 `style.css` 提取颜色、表面层级、玻璃两种厚度（工具栏的薄玻璃，菜单、弹出层与抽屉的常规玻璃）、圆角、字阶、阴影与动效，覆盖浅色、深色、手机纯黑，以及减少透明度和减少动态效果的退回。
- **组件**：以原型 `ui/kit.js` 的清单为起点，约 25 个：按钮、标签与状态徽标、横幅、空态、事实列表、输入框/多行/密码/下拉、开关、分段、标签页、筛选条、本页查找、菜单、弹出层、对话框与确认框、轻提示、工作台壳（侧栏、工具栏、手机抽屉）、列表加检查器、检查器标题、方向键列表、就地编辑、纬线与关系链、头像、加载与分页。每个组件一份 TSX 加同名 CSS。
- **交互行为**：焦点归还、列表方向键移动、浮层定位、Escape 依次关闭，从原型移植。
- **组件目录**：一个静态页面，展示全部组件及其状态，可切换浅色与深色；同时是组件自动检查的测试对象。
- **文档**：DESIGN.md 从原型包移入 UI 库，成为唯一视觉规范，原型配置改为引用它；README 写使用方式，以及新增和修改组件的约定。

### 数据与状态

- **接口层**：定义 `HubApi` 接口，浏览器实现负责 fetch、15 秒超时、错误映射、空间 JWT 的换取与 14 分钟缓存；页面只依赖接口，原型换成内存实现。
- **会话**：沿用 sessionStorage 键 `runweft.hub.session`，升级后已登录的标签页继续可用。
- **上下文隔离**：身份 token 与当前空间组成上下文。切换时中止进行中的请求，迟到的响应丢弃，与现有 `generation` 检查语义相同。
- **读取**：页面用一个小的资源 hook 读取数据，记住上次成功的结果；刷新失败时保留已有内容并显示错误。
- **写操作**：只禁用当前操作的控件，不再像现在这样禁用页面上的全部控件。网络失败时提示“结果未确认，先刷新核对”，不自动重试。401 且会话失效时回到登录。
- **创建回执**：`createResource` 的请求 ID、内容摘要和 sessionStorage 待确认记录原样移植。
- **原生会话**：`openNative` 的新标签页流程原样移植，包括先开空白页、空间 JWT 校验和会话可读检查。
- **路由**：继续使用 hash，保持 `connect`、`space`、`task`、`round`、`native-expired` 的含义；新增 `view` 参数记住当前入口，刷新后不丢失。

### 构建与交付

- 新增前端构建脚本，用 `Bun.build` 把 `src/hub/web` 打包成一个 JS 和一个 CSS，生产模式压缩；输出目录被现有 `.gitignore` 的 `dist/` 规则忽略。
- `scripts/build.ts` 先构建前端再编译二进制，`page.ts` 以文本导入嵌入产物；`bun run dev` 和集成测试脚本同样先构建前端。
- `/hub` 只返回最小骨架（挂载点和无脚本提示），CSP 响应头不变；`/hub/native.js` 继续按现有方式转译，本次不改。
- 运行时依赖 `react`、`react-dom` 加到根目录并精确固定；UI 库和原型包从根目录解析同一份 React。

## 与现有功能的差异

现有前端是 MVP，布局与交互不作为约束（需求）。功能层面的差异：

| 现有 | 新界面 | 处理 |
| --- | --- | --- |
| 生成邀请后可“复制”和“下载备份” | 保留复制和可选中的文本，去掉下载备份 | 需确认：邀请 24 小时内一次性使用，应立即交给对方；下载会把 token 留在磁盘上 |
| 任何操作进行中，页面全部控件禁用 | 只禁用当前操作的控件 | 防重复提交的范围不变 |
| 身份、空间和资源 ID 直接显示在卡片上 | 收进检查器或“更多”菜单，可选中复制 | 仍可获取 |
| 任务详情以五段原始 JSON 展示配置快照、执行观察等 | 按原型分标签展示结构化信息，原始数据保留在可展开的诊断区 | 信息不减少 |
| 所有结果通过页面顶部一条通知显示 | 成功用轻提示，失败、未确认和离线用页内横幅 | 播报方式改为 `aria-live` 区域 |

除上表外，现有能力在原型中都有对应入口（逐页对照了任务、机器、Runtime、Agent、仓库、我的选择、成员、账号与连接）。

## 后端

按已验收原型核对，现有接口已能提供所需数据，目前没有必须的后端改动。实施中如果交互优化需要接口调整，在计划中单列，写明契约、调用方和验证；持久化格式变化遵守项目约定，不兼容升级先由用户取舍。

## 验证

| 对象 | 方式 |
| --- | --- |
| UI 库 | 在组件目录页上用 Playwright 检查角色与名称、键盘操作、可见焦点、Escape 关闭并恢复焦点、减少动态效果与减少透明度；浅色与深色截图使用 GPU 合成，否则圆角玻璃的模糊不会渲染 |

| 纯逻辑 | `bun test` 覆盖回执状态、上下文隔离和 hash 路由解析 |
| 原型 | 原型包现有 `verify.mjs` 继续运行；改用 UI 库后，与已验收版本逐入口截图对比，差异逐项核对 |
| 仓库检查 | 更新 `ci-scope.mjs`，让 `src/hub/web` 和 `packages/ui` 的改动触发类型检查与对应测试；按 AGENTS 执行 typecheck、test、build、test:tools、文档与工作流检查 |

## 切换与回退

在 Change 分支上完整替换，新界面全部完成后删除旧前端模块，不保留新旧并存或开关。不涉及数据格式，回退为撤销合入提交；会话键不变，回退前后已登录的标签页都不受影响。

交付顺序：先做 UI 库、构建链和工作台壳，再按入口实现页面，最后迁移原型包、替换测试并删除旧前端；具体任务在计划中定义。

## 冗余审查

| 机制 | 结论 | 理由 |
| --- | --- | --- |
| 创建请求 ID、摘要与回执核对 | 保留 | 防止结果未知时重复创建，需求明确要求 |
| 身份或空间切换后丢弃迟到响应 | 保留 | 防止旧空间数据显示在新空间，Spec 已有要求 |
| 操作期间禁用全部控件 | 删除，改为只禁用当前操作 | 防重复提交只需作用于当前操作；全局禁用会挡住无关操作 |
| 原型独立实现页面 | 合并到产品页面（Q7） | 两份实现必然走样 |
| Radix、Tailwind | 不引入（Q6） | 对话框和浮层用原生能力已够；引入会带来 CSP nonce 改造与较长的依赖链 |
| 数据缓存库 | 不引入 | 需求只要求保留上次结果和上下文隔离，一个小 hook 足够 |
| Storybook 或文档站框架 | 不引入 | 一个组件目录页同时满足浏览和测试 |
| 提交到仓库的截图基线 | 不做 | 验收时现场生成对比即可，长期维护基线成本高于收益 |
| 带内容哈希的资源名与长期缓存 | 延后 | 现在 `/hub` 统一 `no-store`，预计资源 gzip 后约百 KB，暂无性能问题 |
| UI 库独立版本号或 npm 发布 | 不做 | 只在仓库内使用 |
