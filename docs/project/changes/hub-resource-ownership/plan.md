# 机器与 Runtime 归属实施计划

> 状态：执行中
> 来源：[Requirement](requirement.md)
> 技术方案：[Technical](technical.md)
> 执行模式：逐任务提交。方案/Plan 由主 agent 按授权确认，已完成 iclaude 评审并由主 agent 落实修正，见 execution.md。

## 交付目标

新身份可在同一 Hub 独立登记机器、注册 runtime、明确向空间开放执行，并受到与管理入口一致的权限检查。独立组合网关和 CLI 可自动验收；默认 serve 迁移不混入本领域。

## 任务

### T1 可信机器接入与全局登记

- 状态：已完成
- 交付：增量存储、带 requestId 的 enrollment、凭据替换/撤销、机器名称/登记/空间关联及 HTTP 接线；可复用组合函数，传递 RequestLease，成员移除级联撤回关联。
- 依赖：已归档身份/空间和 HAPI 通道授权。
- 验收：不能自报旧机器 ID 认领；被替换/撤销的 enrollment 重放明确冲突，不复活旧凭据；重启/丢响应保留原机器；凭据只存摘要；其他所有者/管理员不能改机器；关联不产生 runtime 或机器控制权。
- 验证：SQLite 并发与迁移、HTTP 正反向及凭据轮换重放；typecheck。

### T2 Runtime 所有权、分享、治理与目标解析

- 状态：已完成
- 交付：独立 runtime 登记；两空间分享与本空间治理禁用；复用原生探测的可见概要和受控目标解析；同步 usable 判定及原生 HTTP/RPC 执行钩子，分享/关联/治理使用同一规则。
- 依赖：T1。
- 验收：同机同类型稳定 ID；私有/共享与管理/使用分离；治理不能越出当前空间；分享不泄露路径或其他配置；撤销/成员移除/注销在异步探测后仍生效，重入不自动恢复分享。
- 验证：两所有者、两个空间、三角色矩阵；并发与离线/错误路径；原生入口绕过与旧探测行为回归，已验收授权 smoke。

### T3 Hub 管理 CLI 与持久机器接入记录

- 状态：待开始
- 交付：typed client 与同一 Runweft CLI 下的 Hub 机器/runtime 管理命令；按既有 connections 分区保存的 machine 接入记录；并发初次创建、active/pending 轮换与 Web 备份 Hub 核对。
- 依赖：T1、T2。
- 验收：显式身份/空间，无旧认证或本地服务回退；可完成 enrollment、分享、治理和 check；丢响应用原凭据恢复；stdout/错误不含秘密，所有持久数据在明确的数据根内。
- 验证：编译 CLI + 专用 Hub/home/身份文件，跨 Hub 不串用凭据；保留旧命令回归。

### T4 真实 Runner 验收与接口交付

- 状态：待开始
- 交付：真实 HAPI/Runner 注册与探测、共享目标解析、完整需求矩阵和后续委派接口说明。
- 依赖：T1–T3。
- 验收：真实 Runner 持机器凭据工作，资源共享者只能使用获准 runtime；配置保留离线历史；本阶段不声称真实模型或默认服务已迁移。
- 验证：typecheck、全套 test、build、test:hub-resources 真实协议/CLI smoke、hub-access/hub-realtime 回归、结构校验；自动验收后同步 Specs 并归档。

## 风险和验证重点

机器接入秘密先在客户端落盘再提交；同请求不得创建第二台机器。空间治理只作用于本空间，所有者登记/分享开关不得清除禁用。共享响应与治理概要必须显式裁剪；原生工具探测复用既有函数，不让共享资源用户获得完整机器 API。运行中任务的实际停止由下一阶段委派层依据 HAPI 完成，本领域提供可重新核对的权威状态。
