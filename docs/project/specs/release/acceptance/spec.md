# 发行验收范围

> 现有官网/四平台发行包仍对应旧认证与配置。Hub 集中委派已在当前源码和 Linux 编译 CLI 验收，尚未生成包含这些行为的同版四平台发行包；旧产物证据不证明新接口已发布。

当前 1.0.0 的可安装产物、程序 hash、逐项需求及原始证据定位见[完整验收记录](../../../archive/2026-09-30-integrated-release/acceptance.md)。各领域行为以对应 Specs 为准；本页只限定组合证据的范围。

## 已验证组合

Linux x64 从实际 npm 安装后的同一 Runweft/HAPI 候选，使用专用原生配置与认证副本完成：

| 范围 | 证据覆盖 |
| --- | --- |
| 安装与配置 | npm 安装、平台 tarball 独立运行、local/Hub 服务、配置诊断；两客户端的重复 MCP 安装/卸载、其他设置保留及备份恢复 |
| shared 协作 | local/Hub × Codex/Claude 宿主 × Codex/Claude runtime，8 组真实两轮任务 |
| 本地 worktree | 相同 8 组组合，准备、项目配置继承、封存、显式合入、现场与 session 留存 |
| 远端 worktree | 同机 Hub/两个独立 Runner × 两宿主 × 两 runtime，4 组两轮任务，输入/输出、Git/LFS/子模块成果、执行端离线取回 |
| 附件与控制 | 8 组独立附件组合，2 组 MCP 控制；另有两 runtime 的原生审批、拒绝、中断和进程结束证据 |
| 历史与恢复 | 同 session 续接；仅精确 missing 后业务历史重建，新 ID/来源可追溯，新轮次输入仅一次；服务重启查询成果不重跑模型 |
| 看板 | Playwright Chromium，真实历史与明确标注的故障/分页 fixture，登录、恢复、筛选、375/1200 布局及 HAPI 详情 |
| 升级与回退 | 旧程序产生的数据副本升级至 1.0.0，相同 HAPI/schema v6 下兼容回退，停止后完整备份/原路径恢复，原件指纹不变 |

干净安装、类型检查、173 项根测试及四平台构建通过。未知执行不重发、准备失败不启动、封存失败保留、只重试交付和更高 schema 拒绝采用故障 fixture；这些证据与真实模型执行分开记录。Codex 支持当前验证的追加输入，Claude 明确返回 `steer_unsupported`，不将不同 runtime 描述为能力完全相同。

## 尚未取得的证据

- macOS 两架构完成构建、格式/架构及包内容校验；最终版本实机验证由用户承担，尚未执行。
- Linux arm64 经 QEMU 验证版本、初始化、配置、路径和 Agent 命令；没有最终版本原生 arm64 完整服务/模型证据。
- 物理跨机器及实际网络组合按用户授权延期；同机多 Runner 不替代物理远端验收。
- 本次修改后的 GitHub CI 未触发，Nginx 示例未经运行；固定 HAPI 有已记录的环境性 skills 测试失败，不能宣称上游全套通过。

用户全局配置保持不变；本机原生模型可用性与测试副本的实际选择记在验收记录中，不把某账户可用的模型设为产品默认。上述证据边界不减少已经实现的功能或省略对应平台产物。
